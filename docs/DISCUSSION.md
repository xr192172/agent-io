> 可执行结论不在这里：判据 / 门 → `GUIDE-GATE.md`；工具 / 流程 → `GUIDE-USAGE.md`；三方合并 → `MERGE.md`；未完成 → `INDEX.md` §四；缺陷 → `DESIGN.md`。

## 一、这条链错在哪：不是链，是「分支之后还该一样」

`AST → 实际侧 → 设计侧 → 回写` 的顺序、fork 的语义、merge 的时机都成立。
唯一不成立的是隐含假设：**「分叉那一刻相同，之后只有绕过监管才会不同」**。

| | 实际侧 | 设计侧 |
|---|---|---|
| 谁在改 | 机器（源码变 ⇒ live 变） | 人（写意图） |
| 有什么 | 事实（文件 / 符号 / 边） | 事实 + **意图**（`decision` / `expectations` / `task`） |
| 结果 | 永远等于源码现状 | 有实际侧**从来没有**的东西 |

⇒ 「乱」只有三个来源，不是链设计错了：

1. **意图层**：设计侧多一整个维度。merge 只能裁「同一份数据的两个版本」，裁不了「单边存在」——
   单边只能靠 ⑥ 回写（设计 → 实际）或 observe 回流（实际 → 设计）。
2. **实现边界**：设计 DB 没有函数体（DSL 只有结构 + 意图）⇒ 回写只能改结构（签名 / 增删符号），
   **不能生成实现**。这是纪律的后果，不是工具没做好。
3. **历史包袱**：`observe_*` / `patrol` / `brickify` / `dsh` 等来自另一条产品线，没接进主链，现在是旁路。

## 二、设计 DSL 的真实形态：全量底色 + 少量笔迹

- 设计 DSL 是**工作区**，不是 diff：要改一个签名，得先看见符号、边、布局的全貌。全量拷贝不是违规。
- 但「哪些是人写的」不能靠字段形状分辨——`signature: "..."` 既可能是意图，也可能是 fork 抄来的事实。
  ⇒ 每次拿 `baseline` **现算**（`design vs baseline`），**不落字段**。
- 实测形态：绝大多数节点自 fork 起一字未动，只有几十处有人改过。具体数字用 baseline 现算，别背。
- 一句话：**底色不是违规，违规的是「分不出笔迹」。**

## 三、一个函数可以「形状全对、语义全错」

契约测试能从签名自动做的只有：不崩 / 类型对 / 纯，外加边界值构造；**"值对不对"它判不了**。
`extractFuncName("f(a)") === "x"` 这种错，前三层全过也抓不到——**语义期望只能人写**。

⇒ 分工：**机器穷举边界，人只写「这个输入应该输出什么」**。
这也是 `run` 不可被契约测试替代的原因；该换掉的是它的实现（求值域太窄），不是这个 kind。
