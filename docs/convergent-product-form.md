# 合并形态设想（2026-10-08）：一份「可读的认知卷」+ 一份「可执行的活文档」+ 一层「人审的决策账」

> 起因（用户四问）：*"AOCI 的这些其实已经很完善了，是吗？那我们和它的方向是一致的吗？
> 整个设想里也有我们值得吸收的东西吗？两方面有可以合并、最后这样一个产品形态，你能设想出来吗？
> 设想出来了之后，再做一个计划，然后再往那方面施工。"*

## 0. 先给四问的答案（一句话各一条）

| 问 | 答 |
|---|---|
| 它很完善吗？ | **在它自己那一格里很完善**（"给 LLM 读的仓库认知索引 + 治理"做得极致）。但**"完善"是在它的目标内** —— 它没有可执行、没有几何、没有决策版本栈、没有人审闸门。**它是"某一格做到极致的专用件"，不是"更全的产品"。** |
| 方向一致吗？ | ★ **入口一致，出口不同**。两边都在做同一件事：*让 LLM 动手前先有一份它真读得懂的仓库认知*。而**独立收敛**（不是抄）这件事**本身就是"这个方向对"的最强证据**。不同的是：它是**只读的认知压缩**，我们是**可执行的活文档 + 人审决策层**。 |
| 有值得吸收的吗？ | ★ **3 条**：**显式格式版本**（DSL 文件这一格）· **上限预算** · **认知丢失探针**。（+1 条治理：**面上锁**）★ 见 §1 —— 我原先说 5 条，**查完收敛到 3 条**。 |
| 能合并吗？ | **能，而且不新建任何真相源** —— 合并形态 = 把已有的东西**显式化 + 补治理**（§2）。 |

## 1. ★ 先修正我自己三个判断（这次是"查完才敢说"）

我在 `docs/aoci-dsl-format-comparison.md` 初稿里把「格式版本」「预算」「准入判据」**三条一律写成"我们没有"**。
查完的实情（`src/application/observe/reconcile/reason_validator.ts` 等）：

| 我原先说 | 实情 |
|---|---|
| 我们没有格式版本 | ⚠️ **半有**：**DSL 文件没有**（`_dsl_rev` 是**乐观锁修订号**，不是格式版本）；**索引库有**（`cache.db` 的 `schema_versions` 表 + 迁移） |
| 我们没有预算 | ⚠️ **只有下限**：`MIN_REASON_CHARS = 6`（L1）；**人写文本没有上限** ⇒它管"别写太长"，我们管"别写太空" |
| 我们没有准入判据 | ★★ **错，我们比它细**：**L1–L4 四层校验器** —— **L1 非空** · **L2 套话黑名单**（"更新代码/修复bug/优化"…，且**剥掉套话后仍无实质**才算命中，防误杀） · **L3 实体绑定**（必须含 ≥1 个具体实体：trace/diff 名/数字/节点 id） · **L4 证据回溯**（声称的 evidence 去**真实录制事件**里复算，对不上就打回）。**它是"一行给人读的纪律声明"，我们是"每次写入真的执行的四层闸"。** |

⇒ **该吸收的从 5 条收敛到 3 条**；同时**要记下我们领先三条**：**写入准入（L1–L4）· 可执行 · 几何画布**。

## 2. 合并形态：**MANIFEST + COGNITION + 原有三层**（三个视图，一份真相）

### 2.1 形态

```
<repo>/
├─ MANIFEST.txt              ← ★新增：**卷声明**（10~20 行纯文本；只有声明、没有数据）
├─ COGNITION.txt             ← ★新增：一行一个文件 F/R/A/S（= `query=digest` 的落盘形态）
└─ .agent-io/
   ├─ features/<f>.json          base 设计 DSL       （可再生成）
   ├─ features/<f>.overlay.json  overlay **决策层**  （人写；独立保留；含决策卡 + 验收）
   ├─ live/<f>.dsl.json          live 实际快照       （只读；随扫描重建）
   └─ archive/<f>/               下线库             （只增；含完整 DSL 快照 + 决策卡）
```

### 2.2 `MANIFEST.txt` = **把"三个层"从注释里请出来**（★ 落**仓根**）

★ 直接治上一轮实证的病：**"三个 DSL"这条心智全仓只住在 `storage_overlay.ts` 的注释里**，
README / router / mind **三处都不写** ⇒ 谁都不会想到有三个。

★★ **为什么必须放仓根（用户追问"我们现在的设计达得到简化 LLM 读取的目的吗"的答案）**：
这是「**file 通道**」与「**tool 通道**」之别 ——

| | file 通道（放仓根） | tool 通道（只做 `query=digest`） |
|---|---|---|
| LLM 怎么拿到 | **读文件**（它本来就在读仓） | **调工具** |
| 前置要求 | 无 | **服务在跑 + 知道工具有没有 + 20 个 query 里挑对** |
| 实测结局 | — | ★ `query=digest` **早就实现且能用**，三处引导全不点名 ⇒ **我自己连着四轮没看见**，还提议再造一个 `query=outline` |

⇒ **所以"我们现在的设计"达得到渲染这一半，达不到"被看见"那一半。** 声明文件正是补那一半。

草案（★ **全篇只有声明，没有数据** ⇒ **不新增真相源**）：见仓根 `MANIFEST.txt`（21 行 / ~1.5KB，由 `npm run manifest` 生成）：

- `#Format-Version: agent-io/volumes-v1` ⇒ 治"**DSL 格式漂了没处看**"（吸收 AOCI 第 1 条）；
- `#Quota:` ⇒ 治"**没有上限预算**"（吸收 AOCI 第 2 条；级数思路取自它，数值是我们的口径）；
- `#Admission:` ⇒ 不吸收它的做法，**指向我们已经更强的那道闸**（L1–L4）——**声明已有的，而不是新造一个**。

★★ **进 Git 的判据 = 变更频率**（不是"重要不重要"）：

| 文件 | 变更频率 | 进 Git？ |
|---|---|---|
| `MANIFEST.txt` | **只在"卷的布局变了"时变**（罕见；本仓实测 21 行 ~1.5KB） | ✅ **进**（可 diff、可评审、**走原生通道**） |
| `COGNITION.txt` | **随每次代码改动而变** | ❌ **不进**（churn 高；靠工具现渲染，见 §2.3） |

★ 这就是"**为什么 MANIFEST 进 Git 而 COGNITION 不进**"的完整答案 —— 一句话：**它俩的差异不在价值，在 churn。**

### 2.3 `COGNITION.txt` = `query=digest` 的落盘形态

★ 治"**digest 没人点名**"：**文件天天躺在仓根，不可能看不见**。
★ 但必须防它**变成第二份真相** ⇒ 文件头写**派生指纹**：

```
#Generated-From: feature=<f> dsl_rev=<n> sha256=<hash>
```

`_dsl_rev`（**今天只当乐观锁用**）在此**复用成"派生指纹"**；对不上就印「**已过期，请重生成**」。
⇒ 由此它**可进 Git（可 diff、可评审、LLM 直接读，省一次工具调用）**，同时**不冒充真相**
（这正是 AOCI 用 Git 存索引、而我们的 `digest` 坚持"只读不落盘"——**两边立场各对一半，合起来才是完整解**）。

### 2.4 原有三层**一格不改**

几何 / overlay / 决策卡 / 验收 / archive —— 那是我们的**出口**，不动。
★ 判据：**"只读前两个文件，能不能开始正确地动手？"** —— 能 ⇒ 合并成立；不能 ⇒ 还缺东西。

## 3. 三个视图各自服务谁（"合并"到底合的是什么）

| 视图 | 谁读 | 读多少 | 能做什么 |
|---|---|---|---|
| `MANIFEST.txt` | 人 + LLM | 10~20 行 | 知道**这份认知有哪几卷、什么格式、什么配额、谁是真相、谁能改** |
| `COGNITION.txt` | LLM（**开工前一遍读完**） | 一行 / 文件 | 知道**每个文件干什么、依赖谁、有什么契约、哪里是坑** |
| DSL + overlay + 工具链 | LLM + 人（**动手时**） | 按需 | 改结构 · 生成骨架 · 改名 · 对账 · **写决策 · 审批 · 验收** |

⇒ **AOCI 提供的是第 1、2 行；我们提供的是第 3 行与第 2 行的渲染器。合起来 = 完整的一个产品。**

## 4. 该吸收的 3 条 + 1 条（怎么落 + 判据）

| 吸收 | 落在哪 | 判据（可判定） |
|---|---|---|
| **显式格式版本** | `MANIFEST.txt` 的 `#Format-Version:` | 改一个 DSL 字段名 ⇒ 旧文件被读时**报"格式版本不符"**，**不静默降级** |
| **上限预算** | `MANIFEST.txt` 的 `#Quota:` + **把 L1 扩成双边**（现在只有下限） | 超上限**拒绝写入**；配额值是**一处常量**（不许两处各写一份） |
| **认知丢失探针** | `capability_map` 顶部提示（复用 `snap:*` 观测） | 读一遍 `COGNITION.txt` 的字节数 > 阈值 ⇒ **提示"认知可能丢失，先读 MANIFEST"** |
| **面上锁** | 快照记 `facesOf()` 输出 | 把 `import_project` 从 `direct` 拿掉 ⇒ `snap:diff` **变红** |

## 5. ★ 不吸收的 2 条（抄了伤本体）

1. **把几何层塞进同一条记录** —— 它零坐标，是它省 token 的来源，**也是它画不出图、不能在图上下决策的原因**。
   ⇒ 正解是**两个视图分开**（人读用 `COGNITION.txt` 零坐标，画布仍吃 `geometry`），**不是删掉几何**。
2. **降到"只读"** —— 我们的 DSL 是 `scaffold` / `edit_code` / `consistency_check` / rename 联动的**输入**；
   砍掉 = 砍命脉。

## 6. 计划（步骤 → 判据 → 依赖）

| 步 | 做什么 | 判据 | 依赖 |
|---|---|---|---|
| **S1** | `MANIFEST.txt` 的**生成 + 读取**（只有声明） | 生成后**内容与磁盘实况一致**（列出不存在的卷 ⇒ 报错，不静默）；读它**能答出"谁是真相、谁能改"** | — |
| **S2** | `COGNITION.txt` 落盘（**带派生指纹**） | ① 与 `query=digest` 输出**逐字一致**（同一渲染器，**不许第二份实现**）；② 改 DSL 后不重生成 ⇒ 文件头印「**已过期**」 | S1 |
| **S3** | **上限预算**：L1 扩成双边 + `#Quota` 单点 | 超上限**拒绝写入**；把配额改一处 ⇒ 两处行为同时变（**证明只有一处**） | S1 |
| **S4** | **认知丢失探针** | 阈值内不提示、超阈值**必提示**（**两个状态读数不同** —— 本仓 G5 的教训：读数相同的不是判据） | S2 |
| **S5** | **面上锁**：快照含 `facesOf()` | 把 `import_project` 从 `direct` 拿掉 ⇒ `snap:diff` **变红** | — |

★ **顺序理由**：S1 是地基（S2/S3 都读它）；S2 产出可见物（能立刻验"合并形态是否成立"：**只读两个文件能不能开工**）；
S3/S5 独立可并行；S4 依赖 S2 的产物大小。

## 7. 没做 / 未验（诚实清单）

- **全是设想，未写一行代码**；S1–S5 **未开工、未上清单**。
- ★ **需要你拍板的一条**：**`COGNITION.txt` 是否进 Git**。我倾向「**进，但带派生指纹 + 过期即标**」
  —— 但它**会影响 4 个下游仓**（`dsh-brain` / `dsl-workbench` / `elv` / `ai-config/skills/design-canvas-mind`），
  属于**对外契约变更**，按规矩**不自行决定**。
- **未量**：一个真实仓库的 `COGNITION.txt` 会有多大（我们的 4 个现存 feature 太小，量了也不代表）。
- **未验**：`_dsl_rev` 借来当"派生指纹"够不够 —— 它的语义是**乐观锁（写冲突检测）**，
  **借来当指纹属于复用**，得在类型注释里标清，否则又是"一名两义"。
- ★ **已定（2026-10-08）**：`MANIFEST.txt` 住**仓根**，**判据 = 变更频率低**（只在卷布局变时变，实测 21 行 ~1.5KB）。
  `--in-data-dir` 保留给"不想让仓根多一个文件"的场合。
