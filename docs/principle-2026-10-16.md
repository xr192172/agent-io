# 这个项目的原理（2026-10-16 版）

> 用户的话（逐字）：*"机器只能算出它的那些 DSL，我的意思是让你手写一份和机器算出来的东西同一性质的东西，
> 只不过那个是机器算出来的，而你是对于项目的一个设计。"*
> 本文就是把这句话展开成一套可执行的机制。**每一条都标了"已做到 / 还没做到"，不许混。**

## 一、两份 DSL（不是一份 + 补丁）

| | 谁写 | 文件 | 性质 |
|---|---|---|---|
| **实际那一份** | **机器算**（扫描源码） | `.agent-io/live/<feature>.dsl.json` | 每次重算，是"施工结果" |
| **设计那一份** | **你手写**（或 LLM 代写） | `.agent-io/design/<feature>.dsl.json` | **独立文件，重建不碰它** |

★ **两份"同性质"**：都能过**同一把** `validateDSL`（自洽校验器）—— 实测：手写那份 `valid=true`。
★ **已实测**：改写设计图后 `rebuild_design=true` **前后逐字节相同**（971→971），
  而且**设计图里那个"扫描里根本不存在的节点"重建之后仍在** ⇒ **改设计不会被实际盖掉**。

★ **两条老路（仍在，但降级为"辅助"）**：
- `.agent-io/features/<f>.json` = **扫描 ⊕ overlay** 的合并视图（今天的 `edit_dsl` 写的是这里 ⇒ ★ **这是另一半没走完的路**）；
- `overlay` = "不可再生的意图"（决策卡/验收/参数/标注/`progress`/`lifecycle`）的住处 —— 它的锚点**按扫描 id 对齐**，
  所以它**只能改"现状认得出的对象"、声明不了新结构**。**这就是"为什么一直是同一个文件 + 一个补丁"的根因。**

## 二、一份 DSL 是怎么构成的

```
{ geometry: { nodes[], edges[] }         ← 结构（"已实现的东西"）
  semantic: { files[] }                  ← 文件事实（path / symbols / lines）
  <节点上>.decision { summary, expectations[], progress, … }   ← 人写的意图（挂在该节点上）
  meta: { goals[], storyboard, … }       ← 无类型袋子（放"还没有的东西"）
  user_nodes[]                           ← 构想树（文本节点，不是图结构）
}
```

## 三、id 规则（★ 这条解开了整个架构的硬问题）

> 用户的话（逐字）：*"那就是实现了的，有 ID；没实现的没 ID，不就好了"*

- **已实现的对象 ⇒ 有 id**（由扫描给，路径派生：`file_src_...`）；
- **还没实现的东西 ⇒ 没有 id**，用**名字/路径**指代。

★ **配对问题因此消失**（不需要第二套 id 体系）：对拍时——
| 情况 | 判定 |
|---|---|
| 两边都有（同 id） | 比属性 ⇒ **同名属性差** |
| ★ **只在设计里** | **`要实现`** ← **这就是"拖建筑"得到的任务** |
| 只在实际里 | **`未纳入设计`**（提示，未必是错） |

★ **已实测**：未实现的条目现在放 `meta.goals` 里的一条**无 id 的 goal**（★ 工具层的 `id` 本来就是 optional）
  ⇒ 落盘为 `{"title":"待建模块 X","description":"src/planned/thing.ts","status":"active"}`；
  ★ **不放 `nodes[]`** —— 因为 `validateDSL` 要求 `Node.id`，而 `nodes[]` 本来就是"已实现的结构"。
  （实测对照：塞回 `nodes[]` ⇒ `valid=false`，报 `[required] /geometry/nodes/1: must have required property 'id'`。）

## 四、这条路怎么走（六步，像玩基建游戏）

```
① 在设计 DSL 里画/改（= 拖建筑：只管"我要什么形状"，不管实现、不管依赖）
        ↓
② 对拍：设计 vs 实际（机器算的）⇒ 出差异块
        ↓
③ 按差异块改源码（= 施工：★ 到这里才要管依赖；改前先登记）
        ↓
④ 实际 DSL 重算（扫描）
        ↓
⑤ 两边对拍通过 = **按图施工** ⇒ **验收**
        ↓
⑥ 全程有把尺子（validateDSL）盯着"图本身不能自相矛盾"
```

**六件事各自的现状（不许混）：**

| # | 事 | 现状 |
|---|---|---|
| ① | 改设计图 | ★ **做到一半**：`design/<f>.dsl.json` 独立住处 ✓、重建不抹 ✓；**但 `edit_dsl` 仍写在合并视图上** ⇒ "直接改设计图"还没全部到位 |
| ② | 对拍出差异块 | ✓ 做到：`src/domain/design_sheet.ts`（纯函数）+ 工具层入口，三类差异都实测过 |
| ③ | 按差异块改源码 | ✓ 做到：`rename_files` / `rename_file` / `symbol_move` / `oplIntegrate` **四条经它改绿**（改前先登记，闸会拦未登记） |
| ④ | 实际 DSL 重算 | ✓ 做到（`import_project`） |
| ⑤ | 对拍通过 = 验收 | ✓ 做到：真仓 `6 条 · 通过 6 · 不满足 0` |
| ⑥ | 自洽尺子 | ✓ 做到：`validateDSL` **已接在 `edit_dsl` 的落盘前**（只拦"本次新引入的错"，按**错误键**判、不按文本，以免重命名误判） |

## 四·五、★ 为什么只有"设计那一份"可写（两个消费者）

★ 用户原话（2026-10-16）：
> *"**实际 DSL 是给 LLM 去读，让它去掌握项目的实际情况的。设计 DSL 是给 LLM 用来修改创作新的方案的**，
> 也就是说**实际 DSL 不需要你去修改，它是直接根据项目重算的**，你去修改它有什么用呢，它每次重算都是新的。
> 而且重算以后，它才能掌握最新的结构，才能给 LLM 正确的现状，你去 edit 它干嘛？
> **设计 DSL 由于它需要传达自己的设计目标，它才是唯一需要修改的**。"*

| | **实际 DSL**（`live/`） | **设计 DSL**（`design/`） |
|---|---|---|
| **消费者** | ★ **LLM 读**（掌握**实际情况**） | ★ **LLM 改/创作新方案** |
| **来源** | **每次根据项目重算** | 人 / LLM 写 |
| **可写？** | ★ **不可写** —— 重算后才是最新的、才能给 LLM **正确的现状** | ★★ **唯一需要修改的**（传达设计目标） |

★★ **注意理由的强弱**：`live/` 不该改，**不是因为"改了会被覆盖"**（那是弱理由），
而是因为 **它是给 LLM 看现状的** ⇒ **改它 = 让 LLM 看到一个假的现状**（那比被覆盖严重得多）。

### ★★★ 由此得到一条判据（比"投影是算出来的"更硬）
> **一个数据该不该可写，看它有没有"要修改它"的消费者。**

⇒ `features/<f>.json`（合并视图/投影）**两个消费者都不认它**：
不是"给 LLM 读的现状"（那是 `live/`），也不是"要修改的目标"（那是 `design/`）
⇒ ★ **它没有消费者** ⇒ **该退役**（退化为"读时派生"）。

⇒ ★ **写只写两处**：**设计（`design/`）** 与 **实际（`live/`，由重算写、不由人写）**；**投影是算出来的。**

## 五、为什么这样能行（三条原理）

1. **设计的结构层不依赖扫描**（独立文件 + 重建不碰）⇒ 所以"图纸"能先于"施工"存在；
2. **未实现的用名字指代** ⇒ 不用给"还不存在的东西"编 id ⇒ **配对问题消失**（这是过去多代一直绕不过去的那一关）；
3. ★★ **扫描侧永远自洽**（设计文件的结构是从扫描 fork 的，`expected_apis` 与代码同源）
   ⇒ **唯一能产生差异的，就是"人写的意图"** ⇒ **所以"写意图"才是全部价值所在**。
   （系统自己在对拍报告里逐字写着这件事。）

## 六、由此得到的两条纪律（今天用痛换来的）

- ★★ **"仿照现状写"与"写想要的形状"是相反的两件事**：仿照现状 ⇒ 对拍永远干净 ⇒ **没任务**（却看着很健康）。
  ⇒ **判据**：期望**必须能判 fail**（把实现改坏 ⇒ 它必须红，**且期望文本逐字不变**）。
- ★★ **"总数变绿" ≠ "每一条都真的绿了"**：要核**分母是谁**（`checked` 是哪几条）。
  ⇒ 系统自己也写着：*"没得比 ⇒ 给不出结论 … 报告里若只剩 `0/0/0` + 一句'无待办'，会被读成'查过、没事' —— **而真相是'什么都没查'**。"*
