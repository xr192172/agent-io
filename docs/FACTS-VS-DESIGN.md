# 事实册 ↔ 设计册：两层模型 + 同构要求

> 2026-10-30 定稿（用户提出"设计册要和实际册一模一样"）。
> 本文修正一个容易走偏的表述，并给出可判的同构规则。

---

## 一、先纠一个措辞：不是"舍弃 AST 拥抱 LSP"

正确形态是**两层并存**，各管一段，**不能互相替代**：

| 层 | 实现 | 能力 | 何时可用 |
|---|---|---|---|
| **语法层** | tree-sitter（51 语言） | 结构、节点、文本位置 | **永远可用**（哪怕代码编译不过、依赖缺失、语言冷门） |
| **语义层** | `go/packages` + `go/types`（Go）· `typescript` Program/Checker（TS） | 绑定、**字段选择**、类型、调用图 | 项目能 type-check 时 |

两条硬理由：

1. **翻译前端必须留在语法层**：我们要翻的代码**很可能编译不过**（缺依赖、跨版本、样例片段）。若前端依赖 type-check，翻译直接不可用。
2. **语义层失败必须降级而不是静默**：`go list` 失败 ⇒ 事实标 `syntax-only`，判据转 `unsupported`，**绝不假装精确**。

"不起 LSP 服务也有 LSP 能力"成立——因为能力在库里（`gopls` 就建在 `go/packages` 上），**协议只是包装**；而且 `types.Info.Selections`（字段选择）**LSP 协议里根本没有**。

## 二、同构：设计册 = 事实册投影 + 意图叠加

### 2.1 形态

```
事实册（facts）    由语义层机械生成，全量、可重建、无人工
   │   id 同源、层级同构：file → symbol → field/signature → call edge
   ↓
设计册（design DSL） = 事实册投影  +  意图叠加层（decision / expectations / goals / status / arch_layer）
```

### 2.2 三条同构规则（都要能机器判）

| # | 规则 | 违规后果 |
|---|---|---|
| R1 | **键集合相等**：事实有而设计无 = 未设计（红）；设计有而事实无 = 幻觉（红） | 只能通过**登记**放行（口径同 `t454` 分叉账） |
| R2 | **id 同源**：设计侧 id 由事实册派生（`file_…` / `symbol_…`），不手起名 | 手起名 ⇒ 无法对账 ⇒ 红 |
| R3 | **人只写意图**：`decision.*` / `expectations` / `goals` / `status` 人工；其余由投影生成 | 人工改事实字段 ⇒ 下次投影覆盖并报冲突 |

### 2.3 为什么这样能消灭一类 bug

今天的实例：`src/infrastructure/authoring/translate/go_std.ts` 在设计库里**没有任何节点**
⇒ 没有任何判据要求过它 ⇒ 它是"**没有验收标准的文件**"，我改它时只能靠自觉。

同构之后：**投影即存在** ⇒ "有代码但没有设计节点"在结构上不可能。

## 三、落地（增量，不推倒重来）

| 阶段 | 做什么 | 判据 |
|---|---|---|
| **F1** | 事实册生成器：`go/packages` + tsc → `occurrences` / `fields` / `symbols`（新增表，与 `nodes`/`edges` 并列） | spike 已通：`defs=5704 uses=23532 selections=4427` |
| **F2** | `t458` 对拍：我们的 extractor 推断 vs `go/types` 事实 → 分叉账 | 分叉 → 0 才允许替换手写逻辑 |
| **F3** | 设计册投影：从事实册生成节点骨架（id 同源、层级同构）+ 保留人工叠加 | `t459` 键集合对账：missing/extra 全登记 |
| **F4** | 工具层：只改"自己重实现符号解析"的那些（`find_references` / `rename_symbols` / `impact` / `move_symbol` / `code_health`） | 各自证不倒退 |

★ **不推倒重来的理由**：仓库现在有门、有双棘轮基线、有全部册的判据在真跑（门清单 = `scripts/verify.mjs#GATES`；
判据条数由 `node scripts/judge-all.mjs` 自己打印；双棘轮基线由 `AGENT_IO_TSC_FIX` 那轮自己打印）；
`certs/` 那套第三套验证（原「张证」）已整目录退役，见 `docs/RETIRED.md`。
**重写会把"验证"清零，而验证是这个项目最贵的资产。** 今天 546→336 全程靠它守着不倒退。

## 四、实际册/设计册各自还缺什么（补齐清单）

### 4.1 事实册（`cache.db`）缺
| 缺的 | 价值 | 成本 |
|---|---|---|
| ★ 绑定（occurrence → symbol，role=def/use/selection/type） | 现积压 `unresolved_refs` **32,426 条** | 低（语义库直接给） |
| ★ 字段事实（structure/name/**ordinal**/type/**json tag**/是否嵌入） | 嵌入字段丢、位置式字面量认不出 | 低 |
| ★ 调用点实参映射（call → arg i ↔ param i） | 权威检测只能靠标签猜 | 低 |
| 类型结构化（TypeRef 树而非文本） | 类型推断/渲染靠字符串比 | 中 |
| 导出面与可见性 | 跨语言契约边界 | 低 |
| 错误路径（error 返回 / panic 点） | Go `error` vs TS 的最大语义差 | 中 |
| 并发原语使用点（mutex/channel/goroutine） | 槽位 `conc` 轴无事实支撑 | 中 |
| 值/指针接收者与 copy 语义 | `isValueStructType` 目前是手写猜 | 低（`go/types` 有） |
| 语料覆盖报告（哪些构造未被语料覆盖） | `t454` 只报"比了几体"，报不出"没比什么" | 低 |

### 4.2 设计册（DSL）缺
| 缺的 | 为什么重要 |
|---|---|
| ★ 字段级契约（名/类型/可空/**序列化名**/跨语言映射） | `t457` 只做了对账，没有"契约"层 |
| ★ 行为用例覆盖率 | `behavior-cases` 有了，但不知道**哪些行为没用例** |
| 不变量（如 map key 非空、nil 切片语义） | 跨语言转换最易错处 |
| 槽位决策依据（为什么 `Time→number` 而不是 `Date`） | 现在只有结果，没有理由 |
| 域级依赖规则 + 实测偏差 | `arch_layer` 只有标签，没有"实测是否违反" |

## 五、[未核]

- `go/pointer` 已从 `x/tools` 移除 ⇒ **深度别名/指针分析没有免费版**；
- `go/packages` 要求依赖可解析（离线/私有库场景会失败）⇒ 必须保留 `syntax-only` 降级路径；
- 事实册全量重建耗时未实测（spike 只跑了 48 文件 5 包）；
- 设计册投影会放大人写判据的**位置漂移**（id 变了判据就悬空）⇒ 需要 id 稳定策略（moniker 而非行号）。
