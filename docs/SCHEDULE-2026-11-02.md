> **这份是"什么时候做什么、按什么顺序、派给谁"**；长期欠账（谁欠的、在哪、T 编号）仍住 `docs/todo.md`。
> 两者分工：**todo = 欠账台账（无时间）· schedule = 执行顺序（有时间、有依赖、有派法）**。
> 不合并的理由：合并会让"排期"和"欠账"互相污染 —— 排完的活会从欠账里消失，欠账就再也数不准了。

## 主进程的职责（用户裁定）

```
主进程只做三件：**排班 · 派活 · 验收**
· 派出去之后**不操心实现细节** —— 子代理自己读 AGENTS.md / AGENTS-RULES.md 去完成
· 验收只看两件：**判据是否成立** + **读数是否自洽**（不看它怎么实现的）
· 批次之间严格串行（单写者：共享 dist/ cache.db/ .agent-io/design/）；批次内可 1 写 + 1~2 读
```

## 排序原则

1. **止血优先** —— 会**静默制造错误**的机制先修，它比"少一个功能"危险得多。
2. **仪器先行** —— 测不出来的东西不要动；没有量具的重构等于赌。
3. **收束能力面是主线**（用户裁定优先级），但穿插仪器批次。
4. **大件最后** —— slice 3 要动写单元，得等写口收干净。
