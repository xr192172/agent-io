## 二、外部已有人做得更好（三个直接可借）

### ① ADR + **可执行规则** —— 把决策变成治理层
- **archgate**：把 ADR 变成跑在 CI / pre-commit、并喂给 AI agent 的治理层；**每条 ADR 可带 `companion.rules.ts` 导出自动检查**。[来源](https://pypi.org/project/archgate/0.43.0/)
- **Sentinel**：agent 拿 **ADR-014** 去评 PR，偏离就带引用地拦在合并前。[来源](https://dl.acm.org/doi/full/10.1145/3786335.3813195)
- **GitHub「Design Decision Gate」**：*检查 PR，判断 diff 里是否**藏着**一个显著设计决策，缺就由 ADR-writer agent 起草一条*。[来源](https://github.github.com/gh-aw/blog/2026-10-15-agent-of-the-day/)
- ★ **对照我们**：我们的「决策卡 + `expectations`」**就是 ADR + companion rules，结构完全同构** ——
  但**我们没把它当"每次变更都要跑的治理层"**，它只是"收口时的验收"。**这是最便宜的一处升级。**

### ② Event sourcing —— 册不该是可变单文件
- 事件是不可变事实、**是唯一真相源**；当前状态由事件 apply 出来的**投影**派生；
  **"纠正是新事件，不覆盖历史"**。[langwatch 架构](https://raw.githubusercontent.com/langwatch/langwatch/588f1d4665096bff16d6ce874c609c5e3d3dae15/langwatch/src/server/event-sourcing/ARCHITECTURE.md)
- ★ **这一条一次解掉 P3 + P4 + 决策 history 占 55%**：
  ```
  册（JSON）        ← 改成 **投影**
  事件日志          ← 新的源（append-only，小、不可变、天然并发安全）
  _dsl_rev 乐观锁   ← 删掉（不需要：append 不需要锁）
  整本重写 8.8 MB   ← 删掉（只 append 一条事件）
  决策 history      ← 天然是事件，不再是册里的 55%
  ```
- ★ **它同时修正了我原来的 slice-3 计划**：我写的是"册搬进 DB（可变行）"，
  正解是"**事件为源、册为投影**"。前者只是换存储介质，后者才解决并发与重写。

### ③ Capability（能力令牌）界到**路径集**，token 绑定确切参数
- 形如 `repo.patch:src/auth/**`；agent 起草 **ChangeSet** → 网关按策略放行 → clearance token 绑到确切参数。[GembaOS](https://gembaos.dev/en/scenarios/it-ops/)
- ★ **对照我们**：`authorize` 入参**已经是** `files:`/`nodes:`/`subtree:` 的能力令牌形态 ——
  缺的只是它必须 **⊆ 坍缩集**。**一处比对，不是重新设计。**

### ④（补充）Mylyn task context / working set —— 先验 vs 后验
- Mylyn：任务上下文 = 一组 artifact + degree-of-interest，**从交互中学**。[Kersten & Murphy, FSE 2006](https://acm-stag.literatumonline.com/doi/10.1145/1181775.1181777)
- 2026 同题：**agent 的 working set 与 coherence debt**。[arXiv 2608.16630](https://doi.org/10.48550/arxiv.2608.16630)
- ★ **关键边界**：DOI 是**启发式**，**不能当硬授权**。启发式只许用于"建议还要改哪几个"。

## 四、重写路径（**每一步必须写"删掉什么"**）

> ★ 这是本文件的核心纪律：**"删掉什么"一栏空着，就说明你在加线。**
> 用户 2026-11-02：*「重写应该是在原功能上重写，你是不是经常只是往额外的线上加功能？」* —— 读数 6.3:1，答案是"是"。

| 步 | 重写什么（在原功能上） | **删掉什么** | 依赖 |
|---|---|---|---|
| **R1** 写闸授权 | 授权判定从「scope 里有一张我的卡」改成「`scope ⊆ 坍缩集` ∧ 卡是我的」 | 删 `evaluateRunAuthorize` 里"任意一张卡"那条宽松判定；删 Impact Ledger 的旁路记账（并入同一处） | — |
| **R2** 册变投影 | 册由**事件日志**投影出来；写 = append 一条事件 | 删 `_dsl_rev` 乐观锁；删"读整本+写整本"；删 `decision_history` 独立表（改投影）；`docs/DESIGN-SLICE3-design-db.md` 里"册搬进 DB 可变行"的方案作废 | R1 |
| **R3** 三集合比对 | 读集/声明/实际 三向对账，一个读数出口 | 删散落的 3 处读集消费（`task_ops:145` / `handlers:99` / `apply_writes:39` 各判一套） | R1 |
| **R4** 决策变治理层 | 决策卡 + `expectations` 在**每次 diff** 上跑（不只收口）；diff 里藏着的决策缺 ADR ⇒ 红 | 删 `docs/todo.md` 里"补证/补判据"的逐条债（由 R4 一次覆盖） | R2 |
| **R5** 计数口径 | 每个覆盖率/规模数自带"回答哪个问题" | 删重复的覆盖率报表；删 `coverage`/`规模`上被复用的字面数 | — |

**排序理由**：R1 最便宜且止血（越界现在**根本不被发现**）；R2 最大且解掉一半 P 项；
R4 依赖 R2（事件为源才能"每次变更都跑判据"）；R5 可独立穿插。

## 六、附：「一处权威」为什么一直不成立（**这是最重要的诊断**）

### 6.1 先撤回一个错误归因

```
我最初的结论：加:删 = 6.3:1 ⇒ 我在加补丁，而不重写原功能
★ **这条撤回。** 它把**脉冲**当**趋势**：
   加是**连续的**（每次改动都加一点），删是**脉冲的**（只在归一化运动里批量删）
   ⇒ 比值必然 > 1，**对"是否加补丁"没有诊断力**
```

### 6.2 用户的反驳（正确）

> *「你会自己定位到那处权威，然后去重写它。然而事实是我做了好几次的权威归一化运动，以及好几次的相似定位工具合并的运动。」*

**读数支持这条反驳**：`归一/一处权威/重合/第二处/两套/重复实现` 命中 **105 处**；
`docs/RETIRED.md` 128 行中 **45 行含「被取代 / 并入 / 合并」**（= 至少 45 次归一化事件）；
`2026-10-27.md` 一个文件记了 **61 行**；`docs/CONSOLIDATION.md` 是 2026-10-25 的首次系统性生态位普查。

⇒ **真实情况：`0.9 一处权威` 是一条"规则"，不是"机制"。**
规则只能在被想起时生效；机制在每次写入时生效。**所以它只在运动里被恢复，运动之间持续退化。**

### 6.3 为什么"我会自己定位到那处权威"实际没发生

```
我搜索的时候，搜的是**我要写的东西**（"幂等怎么判断"），
不是**"已经有人判断过幂等吗"**。

而现有量具只能查"**同名 / 同文本**"：
  find_references  按符号名
  explore_code search  关键词 / 语义向量（但只用于"找代码"，没有"入库前查重"这一步）
  gen-db-check  只查**判据归属**重复，不查**实现/工具/能力**重复
⇒ **同名可查，同语义不可查。** 而归一化的本质恰恰是找"同语义不同名"的重复。
```

### 6.4 正确的机制：**新东西入库前必须对语义最近邻表态**

```
触发：新增 public 符号 / 新工具 / 新 domain 模块 / 新判据 / 新脚本
动作：强制取语义最近邻 top-3（同一问题的候选答案）
表态：逐个写「不同（给理由）」或「相同 ⇒ 必须取代它，删掉旧的」
判据：表不出态 ⇒ **不许入库**
```

★ 这与已经成立的 `dsl_write_scope`「**谁写谁声明**」是同一个模式，只是从"写口"搬到"符号"：

| 维度 | 已有机制 | 本机制 |
|---|---|---|
| 写册 | 谁写谁声明（`runDslWriteScope` + `_sync.via`） | — |
| 加符号 | — | **谁加谁声明"它与谁不同"** |

★ 为什么必须是"表态"而不是"自动判定"：**同语义判定是启发式**（向量近邻会误报），
硬授权不能建在启发式上（同 §二④ 对 DOI 的边界）。**启发式出候选，人/agent 出表态。**

### 6.5 因此 `I1 一处权威` 要配的判据（替换掉我原来那条错的）

```
✗ 错的（撤回）：净增行 ≤ 净删行 × 1.5
   —— Goodhart：会惩罚合法的结构性重写，也会奖励"为了比值而删"

✓ 对的（范畴式，二值可判）：
   本次新增了 src/**/*.ts / 新工具 / 新判据 / 新脚本
   ⇒ 必须指名它**取代 / 删掉了哪条旧线**，且给出"与最近邻 top-3 不同"的表态
   ⇒ 指不出 / 表不出态 ⇒ 拒
   ★ 判据是对**每一条新增**逐个适用的，不是对提交整体的比值
```

★ 配套的**趋势读数**（不是判据，只做监控）：7 日滚动「归一化运动次数 / 新增文件数」——
若运动次数不降而新增持续上升，说明这条机制还没生效。

## 七、[未核] 与风险

- `[未核]` R2 的"事件日志 + 投影"对**画布**与**任务卡**是否也适用（它们现在住在 `tasks.db` 可变行）；需先量"每类写操作的频率与体积"再定。
- `[未核]` archgate / Sentinel 的"companion rules"与我们 `expectations` 的**表达力差异**（它们是文件级正则/函数，我们是 6 种 kind 的语义判据）—— 未必需要对齐，可能是我们更强，但没做过对照。
- **风险**：R2 是"换心脏"级改动。**必须先有"册可由事件重建且逐字节等值"的证**（parity），才许切换读端；否则册会静默丢数据。
