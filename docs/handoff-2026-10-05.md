**让一个工具的输出，能直接喂给下一个工具的输入**（Unix 的 `|`）。
它**不是**目录/命名问题，也**不是**简洁化的一部分 —— 是**新能力**。

### 3.1 已经建好的（今天的产出）

| **链的接法表** | `src/domain/chain_wiring.ts` | `上游 → touched 键 → 下游入参位置 + cardinality('single'/'pick')`；挂在 `capability_map` 上给 LLM 看 |

### 3.5 ★★★★★ 下一步（**先做这个**）

用户 2026-10-05 给了**分两类数据的判据**，它是本阶段最重要的一句话：

> **「有可被再利用的价值时，才有被当做『出参』的意义。否则把它当变量、当剪贴板直接剪贴给下一个。」**

⇒ **判据**：**下游若不用它，是不是得从头重算一遍？** 重算贵 ⇒ **出参**（进 `Touched`）；下游自己轻松能得到 ⇒ **剪贴板**。

**按此判据在 `Touched` 六键上的判定**：

| 键 | 判定 |
|---|---|
| `read_files` | ★ **剪贴板**（下游自己读就行；**读工具只吃路径，不关心是源码还是事件**） |
| `nodes` | ★ **出参** ✓ |
| `written_files` | ★ **出参** ✓（"本次调用改了哪些"只有本工具知道） |
| `symbols` | ⚠️ 边界，待定 |
| `feature` / `project_dir` | ★ **第三类：作用域声明**（只有调用方知道） |

**⇒ 执行顺序**：
1. ★★ **把 `read_files` 从 `Touched` 撤出**（它**零代码消费者** ⇒ 撤了不伤任何东西）。
   ★ 它的病根：**它是"剪贴板"却占了"链的接口"的位置** ⇒ 所以没人从它那儿接。
2. ★★★ **补「剪贴板 / 变量」这一格** —— 即"某个值被选中后，能原样填进下游"。
   ★ 这一格**今天不存在**（`chain_wiring` 的 `cardinality:'pick'` **只说了"要挑"，但"挑出来的值"没有实体承载**）。
3. ★ `harvest_decisions` 的 `read_files` **路径基准不是仓库相对**（注释自陈 `process.cwd()`）⇒ **真缺陷，单独修**。

★ **不做**（已判）：
- **不拆 `read_files`**（文件列表是通用数据 + 它零消费者 ⇒ 拆名是"为想象中的消费者服务"）；

## 6. ★★★★ 这个项目最容易踩的坑（**下一会话必读**）

**每一条都是 2026-10-05 一天内真实踩出来的，代价很大：**

1. ★★★★★ **"名字像" ≠ "同义"**（本仓头号病根：判据分叉）
   - 同名的 `files` 在产物侧有 **6 种语义**；`read_files` 装了**源码/事件/文档共 3 类**；
     `find_references` 的入参 `file` 是"**符号定义在哪**"，**不是**"我读的文件"。
   - ⇒ **任何"合并同义字段/常量/改名统一"的动作，先看类型 + 语义**。
   - ⇒ 反过来也成立：**"看起来不一致"可能根本不是同一件事**（`languages/` vs `adapters/` 就是）。

2. ★★★★★ **"实测夹具里恰好是 X" 不是契约**
   - 我把"一次真跑里 `read_files[0]` 恰好是定义文件"当成了**类型级保证**，据此标了一条 `verified` 链边。
   - 真相：那只是**私有 helper 里的语句顺序** + `Set` 插入序，**没有类型/schema/测试/文档**兜底。
   - ⇒ **凡接法：要么有类型/结构保证，要么标 `pending`。**

3. ★★★★ **量具会量到"影子"而不是判据**
   - `measure_b_contract.mjs` **只量产物顶层字段** ⇒ **`touched` 内部六键完全看不到**。
     我据此断言"`symbols`/`read_files` 产物端 0/37"，**整轮结论作废**。
   - ⇒ **读"X 的字段覆盖"前先问：X 是对象还是叶子？嵌套对象里的字段，扁平扫描一律看不见。**

4. ★★★★ **展示层不许 filter 关键字段再下判断**
   - 我写候选清单时把 `touched` `filter` 掉再打印，然后断言"量具只看顶层"——**是我脚本骗了我**。

5. ★★★ **先查历史与设计文档，再说"这东西没做过"**
   - `docs/` 里**好几份是设计文档**（不只学习笔记）。`docs/tool-chain-contract.md` 就是那次统一定义 `Touched` 与目标链的地方。
   - ★ 今天的 T28 参数化，其实是**重做** `2301041`（更早做过同一件事）。

6. ★★★ **不许只信"派活方的假设"**
   - 今天派出去的子代理**三次推翻了我任务单里的东西**（"这条是死路"其实有活的生产者、"这个修法"会引入跨语言误解析、"影响面是闭包"实测 0 变化）。
   - ⇒ 派活时**写清判据**，并要求**先回报再动手**。

7. ★★★ **"半修比不修更坏"** / **"过度放宽"是同一个病的反方向**
   - 让 `exts` 覆盖判定 ⇒ 会引入 `.go` 解析到 `.ts`（跨语言误解析）；正确修法是**只补 `.mts/.cts`**。
   - ⇒ **改动的边界要能说清"只影响什么"**。

8. ★★ **我的稳定失误模式**：**用"看起来对但没量过"的判据下结论**（今天判断类错 ≈10 处，事实类 0 处）。
