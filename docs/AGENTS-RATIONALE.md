## 0.7 的四条小事 —— 论证

### `STALE_BUILD` 的实证
那个 MCP 进程是 **10-30 21:00** 启的、跨几百次 build ⇒ 用它判卡得到"后态 2 条 unsupported"，
而新鲜进程复刻同一判定是 **15/15 全过**。**这个警告整天出现在每一次回执里，被当噪音忽略了一整天**，代价是一张卡收不了口。

### 备份必须做"真恢复演练"
`git bundle create --all` 在 **shallow 仓**（`git rev-parse --is-shallow-repository` = true）上会产出一个
`verify` 报 **"The bundle records a complete history"** 的包，而**真克隆报**
`Failed to traverse parents … / remote did not send all necessary objects`（graft 点无法遍历）。
⇒ 备份的唯一判据是：**从它克隆出来，数提交数与源一致**。
本仓可用的做法：直接复制 `.git`（实测 57.3 MB）→ `git clone <那份 .git>` → 比 `rev-list --count`。

### 两处"全量替换"语义的实证
某代理用 `decision.update` 只想加 1 条，结果把既有 9 条 / 2 条判据**整段覆盖**，
靠"`judge` 总数从 401 掉到 394"才发现 —— **判据总数是这类事故的唯一仪表盘**。

## 0.20 的四次"重造第二处权威"（0 次自省发现）

```
① 拼 SQL 数"12 个写口"                 → 实际不止，后来必须改口
② 用 grep 命中数当"在册登记数"           → 32 命中 vs 真实 file 节点 0 个
③ 自己编 v15 形状当夹具                  → 而 `git show <commit>:schema.ts` 就有原文
④ 自己查 `live_cards`+`task_history` 判卡活不活
   → 唯一权威是 `cardLivesOf`（口径 = 那两处 ∪ **设计册 `geometry.nodes[].task`**）
   → 差 3 张**只在册里**是 candidate 的活卡 ⇒ 按错数会**消解掉 3 张活卡的画布**
   → 而 `rewrite_plan.ts:821` 的注释早写着：「卡的下落**只问 `cardLivesOf`**（不再自己查 —— **那正是"两把尺"的来源**）」
```

### 根因不在主控这边，在工具面
那些权威是**内部函数**（`cardLivesOf` / `detectDeadImports` / `parseScope` / `skipDirSet` / `collectRequiredKeys` …），
**不在工具面上** ⇒ agent **结构性看不见**，只能靠 `grep` 偶然发现 ⇒ 于是每次都在重造第二处权威。
⇒ 根治：① 这类"会话级/仓级事实的权威"应**升到工具面**（一个入口 + 描述里写明"唯一权威，别自己查"）；
        ② `capability_map` 除"工具导航"外，应多一段「**要判 X ⇒ 用 Y**」（含内部函数名），否则它导航不了"事实"。

## 0.10 的"口语判句 → 可判规则"处置四步（可移植，不限于本仓）

新项目里几乎必然存在这类句子：注释里的「这里应该注意别直接读 storage」· 文档里的「最好保持一处权威」·
**判据 / 测试名 / 断言**里的「模块应尽量解耦」。共同问题：**脱离当时语境就无法判对错** ⇒ 不能执行、不能验收、不能被下一个 agent 继承。
★ 而**口语化的判据**正是"量具被发明"的直接原因：判不了 ⇒ 只好造一条 grep 冒充它。

1. **提炼**：把"应该 / 尽量 / 注意"改成 **条件 + 后果** —— `X 时会出现 Y ⇒ 必须 Z`。
2. **给判据**：若它其实是验收条件，写成可执行的（行为用例 / 可跑表达式 / 一条检查）；**写不出来 ⇒ 它还不是需求，先别进册**。
3. **搬故事**：来龙去脉搬去退役 / 决策台账或 commit message；原地只留一句**不变量** + 一行指针。
4. **优先级**：用户可见字符串（报错 / 工具描述 / 判据 `why`）> 内部注释。
