# 内部术语对照表（TERMINOLOGY）

> 目的：把内部工作语言（工单编号、缩写、口胡比喻）映射到专业表述。
> 使用规则：**替换只发生在注释与文档**；判据数据（must/symbol/path 值）、字符串模板中的行为语义、既定机制名不动。

## 一、映射表（有把握的条目）

| 内部术语 | 专业表述 | 说明 |
|---|---|---|
| `[B]` / "B 词条" | **受控操作契约**（tool input contract） | 指纯函数注册为工具时必须遵守的入参契约；`B_TERMS` 为其注册表 |
| `A7` | **写闸授权检查**（write-gate authorization） | 按 run 授权范围与 claimed 卡判定写权限的检查 |
| `假红` | **误报**（false positive） | 校验失败但被证明是校验自身失真 |
| `红即任务` | **失败判定转化为任务工单** | 判据 fail → 建卡修复的流程 |
| `对拍` | **行为差分对拍**（differential replay） | 以旧实现输出为基线比对新实现 |
| `带病提交` | **含失败门通过提交**（commit with failing gate） | 明令禁止 |

## 一·五、feature（活跃核心词，2026-10-24 升格定义）

| 术语 | 专业表述 | 说明 |
|---|---|---|
| feature | **项目分册标识**（project ledger namespace） | MCP 必填参数；一个 feature = 一个项目的独立账本（设计册分册+任务分册+实际基线）。非退役概念——今天起就是『项目 ID』。 |

## 二、保留不替换（既定机制名，改了反而破坏一致性）

| 术语 | 理由 |
|---|---|
| 跑环（继任链工作流） | 任务系统已定型的机制名 |
| 写闸 / 读集 / 收口 / 补红 / 立卡 / 翻卡 | 闸与任务状态机的机制名 |
| 台账 / 入史 | 审计存储的机制名 |
| 金丝雀（canary harness） | 行为对拍的实现术语 |
| `T74` / `T157` 等工单编号 | **保留**——git 历史考古锚点；新文档不再新增编号引用 |
| `composed` / `atomic_call` / `brief` | 对外工具面名称（README 已收录） |
