# AgentIO 自迭代试点：用现有 AgentIO 生成下一代垂直切片

状态：交给独立开发窗口执行的**受控实验设计**。不是重写整个产品的承诺，不是当前实现说明。

## 0. 实验问题

> 现有 AgentIO 能否根据自己的目标设计，生成一个更简单、可验证的下一代垂直切片；并用它完成一次真实小改造，证明哪些部分值得替换旧实现？

回答只能是：有证据支持、证据不足、或证伪。不能用工具数、文件数、字段数、生成代码量或“全部绿灯”替代回答。

## 1. 试点目标

在一个**独立项目目录**生成最小可用产品：

```text
一个本地 TypeScript 项目
→ 建立实际事实
→ 按功能找到一个纯函数及其相关上下文
→ 读取当前设计与目标行为
→ 形成一个最小变更计划
→ 修改函数实现
→ 重建事实并执行独立行为契约
→ 对账并给出完成/未完成/不可判
```

这是一条垂直切片，不是“完整支持任意语言、任意项目、任意重写”。

### 1.1 这次只实现的能力

1. 项目登记与 TypeScript 实际事实索引；
2. 功能查询与相关上下文；
3. 设计目标/行为契约的最小表示；
4. 由目标差异形成一个函数级工作项；
5. 一个受控函数改写；
6. 写后重建、行为验证与对账。

### 1.2 非目标

- 完整任务卡状态机、租约、权限体系；
- 通用前端、多人审批、多代理调度；
- 多语言 AST/IR；
- 自动设计评分；
- 全量翻译；
- 自动发现全部影响面；
- 复制当前所有 DSL 字段与工具名；
- 完整替换旧 AgentIO。

## 2. 新项目落点与数据边界

建议新目录：`D:\agentio\dev\agentio-next`；若已存在则先检查，不能覆盖。

旧仓 `D:\agentio\dev\agent-io` 是**事实与执行核的参考来源**，不得被试验修改。

新项目的数据分账：

```text
src/                    新实现
.agent-io/live/         从目标源码重建的实际视图
.agent-io/design/       少量意图与目标行为
tests/                  独立行为反例
docs/                   新切片自己的现状与边界
```

数据库、临时文件、快照不进 Git；意图与文本可交接记录进 Git。

## 3. 先设计什么

### 3.1 最小模型

```ts
type ProjectRef = { root: string; feature: string };
type SymbolRef = { file: string; name: string; kind: string };

type ActualSymbol = {
  ref: SymbolRef;
  signature: string;
  exported: boolean;
  sourceRevision: string;
};

type BehaviorContract = {
  id: string;
  subject: SymbolRef;
  cases: Array<{ given: unknown[]; expect: unknown }>;
  source: 'design' | 'existing-test' | 'approved-baseline';
};

type ChangePlan = {
  objective: string;
  target: SymbolRef;
  behaviorContractRef: string;
  baseRevision: string;
};
```

这些是逻辑形状；先复用当前解析、索引、行为执行与改写实现，不要为字段外形重造基础设施。

### 3.2 目标差异在哪里

设计侧只保存目标行为和理由；当前签名与结构从实际索引读取。计划保存两者的引用与基线，不把当前实现抄成期望。

### 3.3 完成定义

只有同时成立才可核销：

- 实际改到目标函数；
- 关联的独立行为契约真实执行且通过；
- 计划外源码改动为零或已明确纳入；
- 重建后的实际事实与新实现一致；
- 没有 fail、unsupported 或 pending。

只改注释、没运行、输入无预期、索引陈旧、把当前输出当预期，均不得核销。

## 4. 如何复用旧 AgentIO

允许阅读并适配：

- 解析与索引；
- 功能检索；
- 源码符号定位与改写；
- 行为契约执行核；
- 写后重建与对账；
- 可回滚写入。

每个复用必须写明：来源、公开契约、独立行为反例、它在新切片服务哪一步。

不得直接复制：

- 旧工具注册面；
- 全量设计册 schema；
- 无消费者的 contract 展开器；
- 历史任务状态与流程字段；
- 旧读数型判据；
- 未接线的 OPL/翻译支路。

若复用旧模块导致新切片继承不必要依赖，应记录并选用更薄的适配，而不是为兼容复制整套世界。

## 5. 工作顺序

### 阶段 0：先证明工具可用

- 读旧仓 `VISION-ORIGINAL.md`、`PROJECT-DESIGN.md`、`RETIRED.md`、`INDEX.md`；
- 用现有 `capability_map`、`index_integrity` 核实工具与索引；
- 给新目标建立任务/意图链，不从文件任务起步；
- 先写新切片的通过例与不得核销反例。

**出口**：目标和证据路径明确，当前可用旧能力有来源；缺事实就停止，不凭设计猜现状。

### 阶段 1：先建立完整设计图谱，再生成源码

**不允许先写可运行骨架，再边做边补设计。** 先建立本次垂直切片的：

- 功能图谱：事实建立、功能上下文、行为契约、变更计划、改写、重建、对账；
- 模块职责、边界、依赖方向与禁止关系；
- 上述最小数据形状及它们的真实交接；
- 一个受控 TypeScript 夹具项目的目标行为；
- 独立行为契约、R1–R6 反例与核销条件；
- 工作项、先后依赖与机械/模型执行分工；
- 每一步做不到时的 unsupported 与停止语义。

把这些形成设计 DSL/设计 DB 的可读输入，并让后续工作项逐项引用它。设计允许目标文件与符号尚不存在；它们正是待生成对象。

设计完整性的判据不是字段填满或每个函数体都写进 DSL，而是：**本次范围内的功能、公共契约、模块边界、行为、交接与不变量没有未裁决缺口。**

设计自查通过后，才生成源码。实现过程中的内部等价写法、局部变量和函数体组织属于实现自由度，不预先塞进设计。

**源码骨架存在不等于功能存在；设计图谱存在也不等于能力已验证。**

### 阶段 2：走通一次改造

```text
建立实际事实
→ 查询目标功能
→ 返回主体、签名、相关证据和遗漏
→ 写独立行为预期
→ 生成计划
→ 修改实现
→ 重建事实
→ 真跑行为契约
→ 输出对账结论
```

### 阶段 3：新旧对照

对同一夹具与同一行为变更，比较：

- 是否找到正确函数；
- 是否遗漏相关上下文；
- 是否只需一次明确设计输入；
- 是否能检测错误实现；
- 是否拒绝无证据核销；
- 新切片仍需要哪些手工交接；
- 哪些旧机制确实没有被需要。

这些结果用于决定迁移、保留或停止；不能把“代码更少”直接当“能力更好”。

### 阶段 4：决定下一步

- 证据支持：选择一项真实旧能力迁移，不整仓替换；
- 部分支持：保留独立实验，列出缺口；
- 证伪：保留记录，停止继续堆功能。

```text

只允许在 D:\agentio\dev\agentio-next 新建/修改本实验文件。
不修改 D:\agentio\dev\agent-io 的任何源码、设计册、任务或历史。

先建立本次切片完整的设计图谱、设计 DB 输入、工作项与验收，再生成源码；不允许先写骨架后补设计。

设计没有未裁决缺口后，才按工作项生成源码并真跑一次变更。

```

## 6A. 第一轮侦察后的主控裁决（2026-11-07）

侦察报告已证明工具可用但有环境/覆盖边界；据此修订，不允许把报告里的未决项静默吞掉。

### 1. 数据根与意图链

**只允许在 `agentio-next` 内落设计、任务与试验数据。** 不经当前 MCP 在旧仓数据根建册或建卡，不改旧仓项目注册表。

本切片可用 `docs/` 与 `src/model.ts` 表达最小意图链；不为了试点引入旧任务系统。

### 2. 并发边界

旧仓作为**只读参考**，不是静止的实时对照。禁止复用正在开发的 `change_set.ts`、`change_set_view.ts`、`rewrite_plan.ts` 新改动；本试点不重复实现 ChangeSet 组合视图。

对照以旧仓固定 `HEAD` 版本＋已核实的既有导出行为为准，不读进行中的工作区作为旧侧规范。若旧仓还有活动重锁或版本不一致，暂停需要它的对照，不把这种环境态算成功能结论。

### 3. 行为执行

接受已实测的“复用 `transpileForHarness`、`nodeRunnerSource`、`sameBehaviorRet` 等公开零件，换用文件重定向/允许的 spawn 方式”的适配。

不要求在本机解决沙箱 pipe 限制，不声称复用了完整 `runHarness` 本体。缺相对 import 闭包与依赖链接时，本切片仅限自包含纯函数。

### 4. 报告暴露的其它事实修订

- `ActualSymbol.exported` 从 modifiers 等真实字段派生，不假装 nodes 有 exported 列；
- `sourceRevision` 从 files.content_hash 等真实来源适配；
- 实际事实权威为项目内可重建索引，不要求为了试点生成 live DSL；
- 功能上下文由符号检索、import/call 关系、消费者与 omissions 自组；没有设计册时不能宣称 locate 可用；
- 独立反例落 `tests/`，不复活 certs。

### 5. 放行范围

下一轮先建立本次切片的设计图谱、设计 DB 输入、工作项与 R1–R6 反例；设计完整且交接无未决缺口后，才允许创建源码实现。每个反例必须真实执行并证明该红会红；不能只写测试名。

允许的完成不是“设计文档写完”或“骨架建好”，而是：设计驱动的一次真实函数行为变化从实际事实走到独立契约验证与对账，且所有不得核销反例均被挡住。

## 7. 本次实验的判断纪律

- 设计完整但链没跑通 ⇒ 未闭环；
- 链跑通但无独立预期 ⇒ 未验证；
- 行为正确但靠手工搬所有参数 ⇒ 自动补全目标尚未达成；
- 旧功能缺失但实验并不需要 ⇒ 不算损失；
- 新切片省略机制但同类错误重现 ⇒ 说明省略的是必要约束；
- 新旧结果不一致 ⇒ 先判谁错，不以旧实现为当然正确答案。

**最终交付不是“下一代 AgentIO 已完成”，而是一份有证据的迁移决定。**
