# 第一章 · 怎么写一道不撒谎的判据

判据门 = 自动决定「放行 / 拦截」的脚本。它属于**保险**：保险失效比事故本身更危险——事故会被发现，静默放行不会。

## 1.0 三条纪律

1. **只跑真证据，不读源码。** 正则解析源码 = 猜"它大概什么样"；要 import 编译产物、真调函数、内省运行时对象。
2. **未实施的级显式标 `unenforced`，绝不计作通过。** 跑到 L1 就写 `proofLevel:'L1'`，并打印"L2/L3/L4 没有被验证"。
3. **两个方向都自证。** ① 坏输入被挡在**正确的级与检查项**上；② **好输入必须放行**。只证 ① 可能是"一律 blocked"的废门。

★ 三条只约束**门**，不约束注释与散文（§1.1）。

## 1.1 管门，不管散文（2026-10-01 用户校准）

> 「怎么感觉你这个**断言**这个东西，老是影响你写东西。按理来说，**能通过测试功能对的不就是好的吗**？」

| 断言住在哪 | 要不要较真 | 为什么 |
|---|---|---|
| 门 / 量具 / 测试 | ★★ 必须（撤掉修复 ⇒ 必须变红） | 它撒谎时「绿」等于没绿 |
| 注释 / 文档 / 散文 | 便宜且真，发现即改，**不做出生证** | 文档卫生而已。判对错就两条：测试通过 + 与契约相符 |

★ 反面教训：因注释一句话与上游不符就升格成"纪律"——**把小事变成仪式**，副作用是写字缩手缩脚。
★ 项目没有外部消费者时，"改了对外契约"不是代价，是自家一次同步。
★ **但不能反用**：本节说"散文不必被门审"，**不是**"门可以拿散文当判据"（后者见 §1.6.3、案例 7a）。

## 1.2 标准落地七步

1. **阶梯是数据**：`[{level, name, enforced, scope, why}]`，打印与回执共用。
2. **每级写清"声明还是运行期"**：本进程能观测的可判；要跑起来才知的归**未实施级**。
3. **门是唯一能改状态的路径**：`pending → active` 只有过门才转；`acceptance.kind` 只认门写的回执，**散文引用不算判据**。
4. **回执可审计**：`{kind, ref, status, ranAt, proofLevel, unenforced, checks[], evidence}`；`checks[]` 逐项 `{level, name, ok, detail}`。
5. **输出直白**：`✅ admitted` / `⛔ blocked` + `FAIL [级] 名称 — 详情`；过门时**必须**打印未实施的级。
6. 写自证（§1.3）。7. **退出码**：有 blocked ⇒ 非 0。

★ 第 3 步最易被绕：允许"文档写一句已验证"就放行，门就退化成"若干写端之一"，其余写端没有判据。

## 1.3 自证：三种"证明它会红"

| 问法 | 证明什么 | 只有它会漏什么 |
|---|---|---|
| **两方向** | 门能**区分**好坏 | 门测了个无关的东西，恰好也随好坏变 |
| **消融** | 门测的**就是那个修复** | 撤掉修复仍红 ⇒ 你以为修了，其实没测 |
| **出生证** | **旧逻辑**在这份输入上**真会坏** | 测试从未失败过 ⇒ 什么也证明不了 |

**1.3.1 按真实读者的检查顺序复验**（2026-09-15，整代起不来）：修会话日志的脚本复验全绿（能解压/往返一致/违规归零），
但真实读者 `assertZstdHeaderFrame` **最先查物理帧契约**（第一帧明文必须恰好一行），我却压成**单帧**
⇒ 下次启动 `list()` 抛错 ⇒ **整代启动失败被回滚**。
⇒ 先读**读者自己的校验函数**（本例 2 行），把判据逐条复刻进复验。
**"我能解开" ≠ "读者能接受"**；格式契约（帧/编码/分隔/行尾）永远优先于语义校验。

**1.3.2 两方向**：每种坏法断言**被挡 且 失败点落在正确的级与名**（只断言"被挡"，恰好因别的原因被挡，会让真正的检查名存实亡）；
必须有**正向用例**（好样本 exit 0 + 状态转正）；核对**确切名称**；夹具放 gitignore 目录，并**首尾双向断言真实文件未被触碰**。

**1.3.3 消融**（2026-09-21）：**逐个撤掉修复 ⇒ 对应断言必须变红。**
两方向都过，仍可能"测试与被检对象一起错"——你以为验 A，其实验的是碰巧同时变的 B。
实例：移植 `skill_tree.go` 补 5 处，`ablation-check.mjs` 逐个撤回 ⇒ **5 处全红**；不撤时 **60 pass / 0 fail**。
① 把"撤掉"做成开关（`X_ABLATE=1`），只改 gitignore 产物，**绝不碰 `src/`**；② **逐个撤**；③ **断言名写清意图**。
★ **消融不红 = 假绿**。**修完 bug 先问"撤掉它会红吗"；答不出来就还没修完。**

**1.3.4 出生证**：把旧逻辑跑**新夹具**——`old -> 健康（会放行那次崩溃）`，`new -> unknown -> rollback`；写进测试并注释"旧代码会挂的就是这条"。
★ **自证自己也要被检查**：变异体**必须就是那个要防的形状**。实测（铁律 41④）：旧自证"能报红"却**没在测要防的东西**。
★ **必须真注入并回读确认落盘**：实测 `node -e` 的正则被 CRLF 吃掉 ⇒ 注入没生效却不报错 ⇒ 门照绿，
看起来像"判据失效"，其实**是证据先坏**。⇒ 先分清"判据坏了"还是"证据坏了"。

## 1.4 严重度分档

`ERROR` ⇒ 非 0（装配会崩、产物缺失、判据本身不成立）；`WARN` ⇒ 退出 0，但**大声打印 + 计数**（未启用的新包、残留备份、源比产物新）。
**不能一律判红**：有合法例外，使用者就会（a）绕过门，或（b）盲目加豁免。**门被绕过 = 退回没有门，而你以为有。**
再给 `--strict` 把"严"做成可选旋钮。每条指名"哪个对象、哪一步"，**不出总分**。

## 1.5 边界检查

- **`.gitignore` 吃掉新文件**（本仓 `**/lib/`）⇒ 新增目录后 `git check-ignore -v <path>`。
- **别 import 会自我执行的 CLI**（顶层就跑主流程）；共用逻辑抽独立模块。
- **同文件两个 Edit 并行 ⇒ 后者按旧快照覆盖前者，两边都报成功**（连踩 2 次）⇒ 串行 + `grep` 验证。
- **`node -e` 带反引号/正则/花括号会被 bash 抢插值** ⇒ 写 `.mjs`；含反引号的 markdown 别用 JS 模板串。

**1.5.1 覆盖的是【源】还是【用户碰的对象】？** 源 `scripts/dsh-up.cmd` 修好了（0 非 ASCII / 0 纯 LF），
但**派生物**桌面 `DSH 启动 (双击).cmd` 从没重生成（243 非 ASCII + 66 纯 LF）⇒ 用户双击满屏
`'-click' / 'icon' / '-25'`，甚至把 "every **time**" 的 `time` 当 TIME 命令跑掉 ⇒ **挂住**。
**最坏的形状 = 被检查的都干净、用户碰的那个没人管。**
① 门覆盖**派生物**，用**指纹重算 + 逐字节比对**；② 生成器自己把关（拒装坏源、写完复验、指纹进日志）；
③ 三态 `PASS/FAIL/SKIP`（不存在时 `skip`）。★ 凡"生成/拷贝出来的东西"都问：**它的门在哪？**

**1.5.2 扫描面 = 管辖面。** 症状：读数**恒 0** 或恒为某整数。
实测（2026-10-04）："未登记目录"门只遍历 **1 个**容器却声称管整仓 ⇒ `unlisted: 0`，真实 **17 个目录、约 90 个源码文件**未登记。
★ 连修两版仍假绿：v1 漏容器递归；v2 递归了又漏"登记为 flat 的目录**也是容器**"。
v3 才对：**容器判断优先**；容器**既算自己又递归进去**。★ **改判据本身必须做出生证**。

**1.5.3 门不能把自己数进去。** 残留门必然在自己源码里出现要查的模式 ⇒ 扫自己则基线**永远到不了 0**。
用**单独常量**排除，**不要**塞进"历史/豁免"名单——两种豁免意思完全不同。

★ **收尾别只依赖"删除"**：宿主会对 `rmSync` 批量护栏（`{"count":74,"threshold":50,"scope":"turn"}`）
⇒ 整趟删 74 次会在第 51 次起全拒，`restore()` 集体失败 ⇒ 8 条红与被测代码无关。
**先删，删不动就置空**，断言放宽为"不存在**或**已置空"；能不插就别插。
★★ 元教训：拿到逐字错误前我**猜错三次**，每次都信了自己刚编的因果——**先拿最后一段原始证据，再解释。**

## 1.6 假信号三档（★ 全仓唯一一套）

> ★★ 这节取代原先两套并列：`gate` §3 的"按有没有坐标排序"与 `guard` §1d/§7b/§7d 的"按案例展开"
> **是同一件事的两种切法**。现在：**骨架用 gate 三档（正向定标准），guard 案例逐档挂入（反向作注脚）**。
> ★ 新增失效形态**只能往这三档里挂**。

| 档 | 症状 | 有没有坐标 | 为什么坏 |
|---|---|---|---|
| **① 假绿/空过**（最坏） | 没跑、或退化成空转，显示成**通过** | **没有** | 绿的，你连该去哪看都不知道，而且你以为查过了 |
| **② 无门**（次坏） | 压根没有（或只管一小块，你以为管了全部） | 没有 | 诚实的无知：至少你知道自己没查 |
| **③ 假红**（相对最好） | 判据写错，拦住合法输入 | **有** | 把「未知的未知」变成「已知的未知」——给了坐标 |

**⇒ 假红优于无门。** 为什么按坐标排：能不能继续查，比"错得多离谱"更决定后果。

### 1.6.1 第 ① 档：假绿（十类）

| 类型 | 实例 | 判据 |
|---|---|---|
| **(a) 空过** | 遍历空集也算通过；只断言"没抛错"不查值 | 写完门**必须构造一个"应该红"的输入** |
| **(b) 依赖不存在的 API** | `sessionPersistence.listSessions()` 方法名不存在 ⇒ 取空列表 ⇒ 恒 0 ⇒ **171 条记录全 0** | 先确认方法真存在并写成断言；**常量级读数（恒 0/恒真/恒空）就是红线** |
| **(c) 判据为真的次数 = 0** | 204 次 defer 里 `waitedTurnEnd=true` 为 **0**；171 次 freeze 里非零 `lastSeq` 为 **0** | **门要打印"这条判据曾为真几次"**——0 本身就是警报 |
| **(d) 注册了但永不变红** | `verify.mjs` 默认模式**从不设 exit code** ⇒ 无条件 0；当时真有未定义占位符 `candidates`，仍退出 **0** | **说出"凭什么它会变红"**；说不出就是**装饰**。最强证明是**带违规输入真跑一次**。修法：**先让它能失败，再修它报的东西** |
| **(e) 对所有输入成立** | pair 链检查遇两条**通配边** `ANY_TOOL → ANY_TOOL` ⇒ 每对都命中 ⇒ 每条链都"通过" | 全称成立的边**必要但不充分**，从判决移除。抓到它靠**与已知事实不一致**：机器说没问题，当天真跑已证明会断 |
| **(f) 结构性盲区** | 308 文件分 glue 23 / brick **283** / contract 2，**92% 默认桶** ⇒ `layer_violation: 0` | **那个 0 不是通过，是证明规则打不响**。打印桶分布，问"什么输入会让它红" |
| **(g) 天花板饱和** | `health_cli.js --help` ⇒ `0 个文件 → 健康分 100（A）` ⇒ 路径打错被当成通过 | 给"无输入"**独立第三态**（`grade='N/A'`），坏根**非 0 退出**。*量具必须能说"我没有可量的东西"* |
| **(h) 汇总虚高** | 报"5 题有效"而输入 4 题——同条 `rec` 在 `try` 里 push、`continue` 后 `finally` **又 push** | ① **单一计数点**；② `results.length === 输入条数` 且 id 无重复；③ 标题与 JSON 明细交叉核 |
| **(i) 散文回执当判据** | `{kind:'ref', status:'passed'}`——"指向某文档即算验过" | 只认门写的、带 `checks[]` 的回执 |
| **(j) 未实施级显示"通过"** | 没跑的级默认算过 | 显式 `unenforced` 且过门时打印 |
| **(k) 多根遮蔽** | 自定义 preset 的 `select` 返回 200、回读也显示 `minimal`，装的却是随附那份（**77** 工具 / 含 `bash` vs **78** / 无 `bash`） | 多根"先到先得"，**同名即被遮蔽**，回读只回名字 ⇒ 比**名字 + 来源/信任级别 + 内容派生量**。**"名字对上了"永远不是证据** |
| **(l) append-only 日志整篇数** | 前一天失败启动的陈旧行让阳性臂谎报"起来了" | 先切出**最后一次运行**的段，并打印**段数**（>1 就是提示） |

★ **第 ① 档统一自检句**：**"如果这件事坏了，这个读数会变成什么？"** 答不出一个**必然不同**的读数，就还在第 ① 档。

### 1.6.2 第 ② 档：无门

诚实的无知不是错误，**把无知说成有知才是**。两种部分无门：**派生物无门**（§1.5.1）、**扫描面 < 管辖面**（§1.5.2）。
★ 判据：**"我声称管的集合"与"我实际遍历到的集合"必须相同，且能打印**；打印不出就承认没管。
★ 与"诚实的 NONE"同构：盲测答 `NONE` 是诚实够不着；**硬凑**才是"面偏了"。

### 1.6.3 第 ③ 档：假红——两条出口，只有一条对

1. ✅ **修判据** → 变成一次有价值的排查，留下防复发记录。
2. ❌ **改被检对象去迎合**（改声明、放宽阈值、加豁免、删字段）→ **亲手把假红转成假绿**。

**⇒ 铁律：先证明判据错了，再动判据；绝不动被检对象。** 分不清就先当代码错查——**顺序反了就会顺手改声明。**

常见来源：**把两个不同维度当代理**（"不继承上下文 ⇒ 不该继承凭据"）· **脆弱解析**（正则匹配源码格式；
实测报过"67 个工具全未归线"，权威值 64 且全归线）· **注释污染**（负向断言因注释里写了旧 bug 的名字而假红，
正向断言被注释里的示例满足而假绿 ⇒ **先剥注释**）· **措辞不归一**（§1.7）· **读数随工作根漂移**
（`root='src'` 与 `'.'` 分类不同 ⇒ 归一化 + **根不变性写成断言**）。

★★★ **没有作用域 ⇒ 恒假红（铁律 41）**：`indexOf` 取**全局第一次**，而该串在文件里有两处（一处在别的方法）
⇒ 与另一锚点比大小**恒真** ⇒ 在**完全正确**的源码上恒红。
① 用**全文件唯一的阶段锚点**划区间；② 断言写成**要防的形状**（"从 retire 到封口之间不许有任何解锁"）；
③ 把"为什么改"钉成自证；④ 变异体必须是那个形状。

#### ★★ 规模化假红 ⇒ 已不在第 ③ 档

`gate` 说"假红优于无门"，前提是**还能定位**。`guard` 说"假红更坏"，指**另一件事**：
`.js`→`.ts` bug 让 `orphan_file` 报 **284** 条（92% 误报）——操作者只会做一件事：**不再看这个门**。
⇒ 裁决：**"相对最好"只在"它把操作者送到案发现场"时成立。一旦误报率把人赶走，它就退化成第 ① 档**——
**被绕过 = 退回没有门，而你以为有**。**判据是操作者行为，不是误报条数。**

### 1.6.4 三档能**同时**发生在一把量具上（双向失真）

实测（2026-09-28）：一个 `.js`→`.ts` 剥离缺失让整张 import 图消失 ⇒ **同一时刻**：
`orphan_file` **284**（92% 误报）= 第 ③ 档（正退化成 ①）；`layer_violation` **0**（图空了没边）= 第 ① 档；
健康分 `0 (D)` 修前修后一样 = 量程饱和，读数不能承载判决。
⇒ **"门坏了"不是一种坏。** 必须分别答：**假绿在哪？假红在哪？哪个读数是常数？**
★ 抬一层：**硬编码的 `0 findings` 本身就是一个否定判据**——分不开"干净"与"什么都看不见"。

### 1.6.5 读数四态

| 态 | 含义 | 对调用方 |
|---|---|---|
| **0 / 空** | 量到了，结果是零 | 正常通过 |
| **`N/A`** | **没有输入可量**（空目录、路径打错） | **非 0 退出**或显式 N/A，**不许当满分** |
| **`unknown`** | 有输入，但**证据不足/通道不可用** | **表现得像 fatal** |
| **`pending`** | **还不到判的时候**（`blocked_by` 有值） | **不计 failed 也不计 passed**，写清卡在哪 |

★ **"看不到" ≠ "观察到没有"**：数据源缺失时诚实结论是 **unknown ⇒ fail closed**。
把**可观测性做成独立字段**（`agentsObservable: false ⇒ quiesced forced false`），**不要用空数组冒充"没有东西在跑"**。
★ **通道不可用必须与 0 分开报**：把 `null` 当 0 数 ⇒ "进程不存在"的**假阳性**；总判定里让它**不参与**。
★ **`unknown` vs `pending`**：前者**该有证据拿不到 ⇒ 拦**；后者**证据还不该存在 ⇒ 不拦、不记失败、记账**。
把 pending 当 pass 是假绿；当 fail 是第 8 案例"4 道门被绕"的直接成因。

### 1.6.6 信任何门之前先跑三问

1. **桶分布**：一个桶装了 ~everything？（283/308 ⇒ 那个 0 是结构盲）
2. **动态量程**：喂**已知好**与**已知坏**，读数相同 ⇒ **穿着判据外衣的常数**。（两侧都要喂）
3. **夹具现实性**：夹具约定与真实语料 diff。实测夹具用无扩展名 import，真实 **961/971** 带 `.js` ⇒ 测试**永远不可能失败**。
★ **同形状的夹具缺陷会复发**：发现一处后 grep 整个测试套件（同模块夹具也只跑无扩展名，生产 99.9% 带 `.js`）。
★ **样本分布必须是真实分布**：用自己手写的"合格样本"定判据 = 用我猜的分布量真实对象；大面积报红时**先怀疑判据**。

## 1.7 契约类门（压缩保留）

从散文解析判据时，**必须校验「声明条数 = 解析条数」**：规格写「这**五**段」，只断言"解析出 > 0 段"
⇒ 改坏 4 个后解析出 1 段仍不报错 ⇒ 契约悄悄从 5 降到 1 = 假绿。声明值认不出也抛错；从唯一真相源解析。
★ 文本匹配要归一化（`推荐 + 风险` vs 「推荐与风险」），**容忍措辞、不容忍缺失**；反向查裸词（`同会话` 命中「不**同会话**」）。
★ **只验形状不验内容真假**，并写清它不防什么。
★ 「禁止编造」可落成判据：**凡说某符号在某 `文件:行` ⇒ 真去读那一行；搜不到即红**。
必须收窄到"显式引证"——第一版按"同段出现文件名 + 新符号"判红 ⇒ **6 条里 5 条误报**；收窄后误报全消。无引证的新符号只报告不判红。

## 1.8 门自己的输入会不会腐烂（`gate` §5b）

**每个门都有输入**：豁免名单、基线快照、allowlist、frozen 计数。★ 危险在于它们**腐烂时长得像正常**：
【陈旧/冗余/死代码】与【合法豁免】在门眼里**无法区分** ⇒ 门把"不知道"换成"看起来知道"。

实测：**20 条内部模块豁免，烂了三处却零信号**——
【陈旧】`derive_reasoning`（路径已不存在）；【冗余】`archive_node`（已被"被 lane import"判据接住，去掉仍绿）；
【死代码】`list_features`（测试在引，生产零引用）；其余 17 条只被兄弟模块 import，确需人判。
★ 最恶劣：**门已泛化一半，旧名单还留着** ⇒ 每次新增继续手抄；注释甚至写"以后不用手抄了"。

**修法：豁免 = 断言 + 复算。** 每条带**证据字段**（如 `importedBy: string[]`）+ `why`，门**每次跑都重算**。
三检查：① **存在性**；② **覆盖性**（能被自动判据覆盖的不许留）；③ **必要性**（"无人使用"必须由扫描给出 ⇒ 死代码，处置是**删**）。
配套：**棘轮**（只许减，基线写常量，新增 ⇒ 红）+ **出生证**。

**最常见的腐烂：门里硬编码「路径」**（2026-10-01，一次搬迁炸出 3 处）。`rename_symbol.ts` 1920 行 → 文件夹 + 9 文件：
`importedBy` 指向已删文件 ⇒ 红；`resolveToolFile()` 只认同名 `.ts` ⇒ 认不出文件夹模块 ⇒ 泛化为 `.ts` **or** `<name>/index.ts`；
`FEATURE_FILES` 抛 ENOENT ⇒ **pre-commit 挡下提交**（那格本允许目录 ⇒ 写成目录）；已知违规基线旧条目 stale、新环算新增 ⇒ **原地刷新那一条**（不是加债）。
★ 搬迁前扫 `grep -rn "<旧路径>" src/ tests/ scripts/ .githooks/ docs/`；**别只 grep `src/` 和 `tests/`**——
第 3 处在 `scripts/`，**只在提交时发作** ⇒ **提交本身也是一道判据**。
★★ 更贵版本（案例 6）：搬走 67 个工具定义后，一道门**读到 0 个工具**（绿变红），另一道比较 `prev=67` vs `cur=0`
⇒ **把 67 个工具全报成"改名未清理"**。⇒ (a) 输入位置靠**扫目录**算；(b) **"门的输入住哪"只许一份知识**。

## 1.9 先做「状态群地图」，再决定要不要加第 N+1 个（`gate` §5c）

> 用户（2026-09-30）：「这些东西**记个台账就得了**……散在乱七八糟的地方**只会误导**，因为本身是**维护地狱**。……**你自己验自己的**。」

**状态群 = 一份需要人喂、且腐了没人知道的东西**：登记表/基线/allowlist/frozen 计数。

① **按更新机制分类**：**自动重生成**（有 `UPDATE_*=1`）不是负担；**空表**不是；★ **真手维护**才是。
② **问"期望值从哪来"**：是不是**从当前实现反推**的？有**独立判据**（对外契约、行为等价且改基线要记账）⇒「变化即红」靠谱。
只有**棘轮存量** ⇒ 冻结的是**当时的读数**，而读数**可能本来就是假账**（实测：一份"21 条欠账"当场证伪 2 条——
一条说的 helper 早已存在且 10 个门在用，一条只剩 1 处注释）⇒ **假账被原样冻结成"允许的存量"**。
③ **能由判据取代的整表删掉**（唯一真正的收敛）。实测：43 条"会扫仓库的实现模块"名单
⇒ 换成「**被 lane import 或 被兄弟模块 import ⇒ 它是某工具的实现**」。收益：**手维护状态群 2 → 1，不新增任何东西**。

★★ **反面：不要为了"记住欠账"再建一个门。** 我为记欠账设计过 `debt_index.json` + 门 + 棘轮 + 出生证 + `UPDATE`
⇒ 用户一句话否掉：那是**第八个状态群**。★ **台账是给人看的，不是给门看的；给门看的那份必然要人喂。**
⇒ 记在**一个** markdown，写明「本节是唯一出处」；**只记核实过的**，没核实单列"仅是线索"。
★★ **"从旧散文里刮欠账"会把已还的债重新记上，台账本身开始说谎。**

## 1.10 先问「能不能不写门」——三层顺序

**从便宜到贵问三次，能停就停。** 不要先写门再回头想它是否多余——那时第二份副本已造出来了。

**第一层：编译器 / 类型系统**（`gate` §5g）。
> 用户：「这些东西**编译器都本身能够直接查出来的**吧，**你写这么多夹具其实就是在手工替代编译器的作用，而且还贴的很歪**。」

症状：**用文本模拟语义**。实例（647 行门 + 198 行夹具）：登记表写 `producer: 'src/.../symbols.ts#syncFile'`，
门 `splitRef()` 切成模块+符号，再 import 查导出表 ⇒ ★★ **那是在手工重新实现模块解析器。**

| 你想查 | 手写门 | ★ 换成 |
|---|---|---|
| 函数还在不在 | 反解 `'file#symbol'` | **值引用**：`import { syncFile }`，直接写 |
| 名字拼对没有 | 字面子串 | **字面量联合类型** |
| 字段填了没有 | 自定"≥10 字"阈值 | **判别联合** `{kind:'x'; why:string} \| {kind:'y'; produce:Fn}` |
| 枚举合法 | `['a','b'].includes(v)` | **联合类型** |
| 目录不许 import 某物 | 读源码找 `from 'node:fs'` | **ESLint `no-restricted-imports`** |
| 不许成环/越层 | 自己遍历 import 图 | **dependency-cruiser** |

★★ 实测消融：注入三类错 ⇒ `tsc` 全抓且**带纠正提示**（`Did you mean 'source_files'?` /
`Property 'why' is missing` / `Cannot find name '…RENAMED'`）；同一批错在旧的"字符串 + 手写门"下**一件都查不出**（改名后照绿）。
⇒ 门 **647 行 → 15 项**，剩下全是编译器真查不了的（数组 id 重复/图无环/跨字段语义/运行期行为）。
★★ **连带更狠**：文档里"手抄一份机器可读的表" = 自造必然腐烂的副本——账本里手抄的 15 行工序表**当天下午就过期**。
⇒ **能就别写门、也别手抄，写成类型让编译器管。**

**第二层：现成工具**（`gate` §5e）。
> 用户：「需要**固定的**验证工具，**而不是随项目变动的**……我们自己写门，**它是会漂移的**。」

**自写门的代价（实测）**：本仓自写门**腐了四次**——43 条手抄"谁扫仓库"、20 条手抄豁免、`INTERNAL_MODULES` 三处腐烂、
一次量具被打脸三次。共同特征：**判据是手抄清单，不是声明式模式**。
**判据只有一条：这套语义能不能干净地映射到某个现成工具的约定？** 能 ⇒ 用工具；不能 ⇒ 自写，但应该很少。
★ **"用工具" ≠ "写一堆自定义规则"**——写多了工具就重新变成自写门。**用预设，多余的不去管。**
（分层/循环 `dependency-cruiser`；未覆盖文件 `Fallow` 的 `boundary-coverage`；ESLint 用 `eslint-plugin-boundaries`；
monorepo 用 `Nx enforce-module-boundaries`；死代码/未用导出用 `knip`。）

**第三层：只好自写时，认清主场。**

| 门 | 编译器能查吗 | 结论 |
|---|---|---|
| 产者/位置存在、字段必填、枚举合法、类型相符 | ✅ | **删门**，改类型/值引用 |
| 目录 import 限制、分层、循环 | ✅ 框架能 | **删门**，改 ESLint/dep-cruiser |
| **文本重复**（同意图多份/旧品牌串） | ❌ | 保留（认清是**债务温度计**，目标清零） |
| 图的**无环** | ❌ | 保留 |
| **运行期行为**（不退化/方向/反饱和/双向自证） | ❌ | 保留（**这类才是门的主场**） |

★ 棘轮不是病，**病在"期望值来自手抄的一行行名字"**：声明式模式加文件不用改规则；手抄清单必腐。
★ **Don't make the AI remember your rules. Make your system represent them.** 目标不是约束最大化，是**把重要假设显式化**。

## 1.11 把「声明」升级成「可证伪判据」（`gate` §5f）

**场景**：要门管一件**没有可机检定义**的事（如"数据归哪个根"）。纯手写登记表 = 新状态群：
只能证明"写了的是真的"，证不了"**写的那句话本身**是真是假"。

> **一条属性的真假，往往可以改成"把某个输入变一下，输出必须跟着变"。**

```
owner='project'  ⇒ 用两个不同项目根调 resolver，两次结果【必须不同】，且各自【必须含自己那个根】
owner='dataHome' ⇒ 根来自环境量，跑不出两个根 ⇒ 退而校验逐解析器白名单，并【声明强度更弱】
```

★ 它**真抓得到 bug**：`cacheDir()` 不收 root、偷用 `process.cwd()` ⇒ 传两个根返回**同一个值**。
**门今天就能抓到昨天的 bug**——这是判断"判据够不够硬"的最好测试。

**三要点**：① 输入必须真的变，变量必须是**参数**不是环境（env/cwd/包根跑不出两个值 ⇒ 那一半只能用白名单，**且必须标弱**；不要为对称硬凑）；
② 加一条"**含自己那个根**"，否则返回 `Date.now()` 的也能过；③ 首参不是那个变量的函数不能进这类——
**抛错也算红，且报错要告诉作者"这份数据归别的根，请改 owner"**。

**粒度必须与"判据说的是什么"对齐**：说"模块不许 import X" ⇒ 到模块；说"这个解析器的根是 dataHome" ⇒ `file#symbol`；
说"行为的最小充分特征" ⇒ 行为特征，不是那次实现的字面。
★ 反例：dataHome 白名单做成模块级，而模块里同时住着两种根 ⇒ 整模块放行 ⇒ 注入照绿 = 假绿。

**模式对"行为的最小充分特征"写**：`import_cache_${feature}.db` 遇到 `import_cache_${f}.db`（换变量名）⇒ **照绿**；
改成变量无关前缀 `import_cache_${` 才拦得住。（同族：`'cache.db'` 只取**带引号的文件名叶子**，三种拼法都命中。）

**「限度」必须被实测**：写"本门查不了漏写的"是诚实，但**只做到这一步就是新的自我安慰**。
派**独立核验**：**不给它看被核验对象**（只给源头）；回来**逐条抽验，不许只信总结**
（实测：它报 5 条，抽验后 3 条坐实、1 条与已有结论一致、约 15 条未验）；
**未验的如实标注"不当事实用"**，**列清单并计数**（`notRegisteredYet` + 棘轮）。
实测：**一扇门只保护它册上的东西**——独立核验清出 ≈18 项没登记的数据 + 3 处"同一份数据两个根"，其中 1 处**真 bug**，门**一条都没报**。

**根冲突记账**：给**独立字段**（`rootConflict: string`）+ **棘轮**；**写了但没写清（<10 字）判红**——
**半吊子的 `rootConflict` 比不写更坏**（让棘轮以为记过了）。
★ `noneDebt` 6→8 **不是新增债**，是**两笔债第一次被看见**；不写清会被误读成放水。

# 第二章 · 门坏了怎么查

**适用信号**：部署说成功但服务是死的 / "检查明明存在，为什么没抓到" / 回滚机制没回滚 / **门是绿的但你觉得它没意义**。
> 这比原始事故更危险：事故会被发现，静默放行不会。它应被当成比"它没抓到的那件事"更高优先级。

## 2.0 核心洞察

> **纯否定判据（"没找到错误 ⇒ 健康"）分不开"干净"与"证据还没产生"。**
> **对异步落盘的外部产物只读一次，是必然的竞态。**

两者相加 = 静默通过。**修法不是更好的正则，是"有界等待重读 + 必须出现的正向信号"。**
★ 抬一层：**硬编码的 `0 findings` 本身就是一个否定判据**——分不开"干净"与"什么都看不见"。

## 2.1 诊断程序（八步，顺序不能反）

**① 从磁盘复现案发现场，不许先猜。** 建表：门的状态日志（何时宣布成功）· 目标生命周期/退出日志（何时真死、退出码）·
证据文件 **mtime**（何时落盘）· 进程 boot 标记。`statSync(...).mtime` 是单个最有价值的数字：
**`mtime > 门宣布成功的时刻` ⇒ 门读太早。这就是全部诊断。** 算式写进报告：

```
BOOT 08:25:31.328 / guard OK 08:25:34.072 (+2.744s) / evidence mtime 08:25:34.709 (+3.381s)
                     / process EXIT 08:25:34.737 code=1     <-- 证据比门读它晚 637ms
```

**② 数「这条判据历史上为正过几次」。** 长期 0 次不是"没出事"，是"判据是死代码"。
实测：204 次 `defer` 里 `waitedTurnEnd=true` 为 **0**；171 次 freeze 里非零 `lastSeq` 为 **0**。
两个"保险"从未启用，而文档、注释、操作者都以为它们在。**用脚本数并打印 tally，不要肉眼看。**
★ 作者侧：**门要打印"这条判据曾为真几次"**——0 本身就是警报。

**③ 先排除"模式早就覆盖了"。** 把整段产物喂给现有匹配器；若**现在**能匹配 ⇒ 问题不是判据，**是时序**。
跳过这步，就是花一天加正则什么也没修好。

**④ 枚举失败路径上所有的闸。** 泄漏常是"窗口被条件跳过"：找 `if (!fast && windowMs > 0)` 这类守卫，
问事发时 flag 是什么值。**跳过所有等待的"快路径"就是零观测窗。**
★ 还要分开**每个窗口观测什么**：liveness probe 答"进程还活着"（崩前一瞬也是 true），**不**答"日志刷完了吗"。
**两个感觉相似的窗口可能正交**，别让一个替另一个作答。

**⑤ 修：有界等待 + 正向证据 + 三态。**

```
loop until deadline:
  if process already exited (exitCode !== null) -> FATAL   # 确定性，无竞态
  seg = re-read evidence
  if fatal patterns match -> FATAL   (early-exit)
  if POSITIVE ready signal -> HEALTHY
  if deadline passed -> UNKNOWN
  sleep(interval)
```

- **三态** `healthy/fatal/unknown`；三者分开，但让 **`unknown` 对调用方表现得像 `fatal`**。
- **确定性死亡信号优先**：`proc.exitCode !== null` 无竞态；`kill(pid,0)` 有 PID 复用窗口。
- **确定即快败**（早失败 = 早回滚 = 更小爆炸半径）。
- **窗口按实测定**：观测延迟 × 1.75（3.41s → 6s）；别过度加宽，每次交接都付这个成本。
- **可注入** `{timeoutMs, intervalMs, hasExited, isAlive, now, sleep}`，否则无法用假时钟单测。

**⑥ 选正向信号，必须实证判别力。** 扫描盘上每段历史运行，统计含候选信号的段数与"崩溃且缺它"的段数：
要好运行覆盖率高、且**零个好运行缺它**。参考案例 `dsh web: http://127.0.0.1:<port>`（**最后打印**）
出现在 **9/10** 真实段，**唯一**缺它的就是崩溃段。**优先选"在最后一个可能失败的东西之后"才出现的信号。**

**⑦ 出生证 + 真产物集成测试。** 单元测试用脚本化日志快照 + 假时钟；**真产物**：拿盘上真实那份日志，
在**两种状态**下跑真实现（检查时刻原样 / 完整）——夹具证明不了"你修好了**这次**事故"。同时测反方向：健康段仍须 `healthy`。

**⑧ 更正记录。** 若文档已声称这道闸"修好了"而它是**假修复**——**不要悄悄改代码**。加一节写"假修复 vs 真修复" +
时间轴，并**标记旧结论**；否则下一个人信错那一行。

**案例 7（design-canvas，2026-10-06）同一个保险箱上开了两个洞**
- **病**：同一个下午三处独立失效——① 判据**从散文派生**；② 登记过的门**从不设 exit code**（永不可能失败）；
  ③ 判决被**通配边全称满足**（对每个输入都通过）。三种都看起来像在工作的检查。
- **药**：① 判据改读**结构化字段**；② **先让门能失败，再修它报的东西**；③ 把**全称成立**的边从判决移除，只报真正带 payload 的。
  细则见 7a–7d。
- **7a 判据从散文派生 ⇒ 假红**：用 `t.meaning.includes('已退役')` 决定退役；某词条的散文**顺手提到另一个词条**（"`read_files`（已退役）"）
  ⇒ **那个词条也被报成退役**。**谎话是可读的**，这才是危险处。⇒ **机器判据读结构化字段，散文可以解释、绝不可以判决。**
  修法：加 `retired?: 'product' | 'input' | 'both'`（**侧别拆分很重要**）。
- **7b 登记过的门永不可能失败**：`verify.mjs` 默认模式**从不设 exit code** ⇒ 无条件 0。**活证**：当时真有未定义占位符 `candidates`，它仍退出 **0**。
  ⇒ 对每道门**说出"凭什么它会变红"**；说不出就是装饰。**先让它能失败，再修它报的东西。**
- **7c 残留**：一条判据有**两个实现**（`--glossary` 与默认分支）——今天等价，但是**判据分叉的种子**；写在源码里是诚实做法。
- **7d 按构造空转**：链检查遇两条**通配边**（`ANY_TOOL → ANY_TOOL`）⇒ 每对都命中 ⇒ 每条链都"通过"。
  **抓到它靠与已知事实不一致**（机器说没问题，当天真跑已证明会断；**新判决不豁免审计**）。修法：全称成立的边**必要但不充分**，从判决移除。
- **判据（7a–7d）**：判据可以因为 (a) **从错的介质派生**、(b) **从未接上结果**、(c) **被全称情形满足**而坏掉。
  **通用探针：要那个能让它变红的输入——然后确认那个输入真的存在。**

**★ 案例之外的三个推论（原「横切」节的收口）**
- **副本**：先搜全部副本再修；副本常**一致地错**；合并时**按意图写测试**（按旧输出录基线 = 把 bug 固化成契约）；**重复的策略 ≠ 重复的实现**。
- **快照**：分 **stable**（逐字节）与 **measuring**（只做结构断言）；**"我改了" ≠ "改在门观测的范围里"**（改 description 而快照抓 output ⇒ 假证书）；
  **单独绿、全套红 ≠ 绿**。
- **文本 / 死代码 / 静默降级**：别用文本判引用（建 import 图）；死代码三问（谁 import → 谁广告 → **真做了什么**，**报成功的 stub 比缺失更坏**）；
  **若 fallback 的失败模式是"少做一点但不出声"，它就不该存在**。

## 2.3 第 8 个案例（2026-10-18，design-canvas）「4 道门被绕 7 次」

> ★ **诚实边界**：书面痕迹**只有一句**——commit `5947b6f5`：「永远红的契约 = 又一个被绕的门
> （今天"4 道门被绕 7 次"就是这么来的）」。**哪 4 道门、7 次分别何时，没有逐笔留档。下面不编造明细**。

**病**
- **现象**：门账面上有 4 道，但 **7 次**实际决策里没起到门的作用——使用者绕过去了。**门全绿或全红都不重要：没有人再看它。**
- **根因三类**：① **假绿**（判据通过，但**根本不覆盖**当时状态——"一扇门只保护它册上的东西"）；
  ② **判据不覆盖**（门测的是"已经做到的形状"，而当时是"还差 5 个前置条件"，那个状态**不在取值域里**，只有 pass/fail）；
  ③ **无人执行**（契约**永远红**；红久了人不会修，会绕 ⇒ **永远红的门 = 零信息量**，与假绿等价）。
- **本案例唯一的新知识**：**"还没做到"与"做错了"在二态门里长得一模一样。**
  于是"等 5 个工具加参数"这件**正常的进行中状态**被迫报 fail；fail 每天都有 ⇒ 降级成噪音 ⇒ 被绕。

**药**
- **让门报 `pending`，而不是红着**（第四态，§1.6.5）：`blocked_by` 有值 ⇒ `verdict=pending`，**不跑 expect**，
  `detail` 写清卡在哪，**不计入 failed**。
- 实测：`D-actor-entry` 配 `blocked_by` ⇒ `pending`，`detail='进行中 · 卡在：等 5 个写源码的工具加 agent 参数…'`，`failed` 不变。
- ★ **pending 不是放水**：**不计 passed**（否则假绿）；**必须写清阻塞点**（写不清退回 fail）；
  **进回执** ⇒ "几件事卡着、卡在谁身上"变成**可读数字**，而不是一片红里看不出来。

**判据（三条）**
1. 一道门若**长期只有红**，先问"它是不是把'尚未'和'错误'混成了一个值"，**不要**先修被它报的东西。
2. 读数的**取值域必须覆盖真实状态的种类**：`pass/fail/pending/unknown/N/A` 不是"更细"，是**原先有一个状态无处安放**。
3. **"被绕了几次"是门的健康指标**，不是使用者的纪律问题。需要人"每次都记得绕过它"的系统等于没有门。

★ 与 §1.4：分档解决"该红的红到什么程度"；pending 解决"**还不到判的时候**"。两者都不能把**该拦的东西**放过去：
pending 必须可审计（`blocked_by` 机器可读），不是一句"以后再说"。

# 第三章 · 委派怎么核

## 3.0 默认姿势：它的结论是「待验假设」

子代理会：① 把**方向对但量级错**的报成结论；② 把**预测**写成**实测**；③ 只修你点名的那条，留下**同族未修**；
④ 在**临时副本**里演示而不动真文件，却说"已修"。
⇒ **核验不是重跑它的脚本**——那只能证明"它没算错自己那套口径"，**证明不了那套口径本身对不对**。
★★ 两个方向都要防：**不轻信指控**（可能是假红，§3.3②），**也不轻信"已完成"**（可能是假绿）——
同一个毛病的两面：**把"看起来像"当成"是"**。

## 3.1 核验清单（前三条必做）

| # | 查什么 | 怎么查 |
|---|---|---|
| **1** | **关键数字**：用**另一种独立方法**重算 | 它用分段统计，你就用**行级 diff**；它用前缀/后缀，你就用 **hunk 计数**。**两种一致才算坐实。** |
| **2** | **方向 vs 量级**分开判 | "结论成立但归因错"极常见（它说"100% 来自 X"，实际 **98.7%**，且不止一处）⇒ 接受方向，**改数字**。 |
| **3** | **签名的完整性** | 证据文件**真在盘上**吗？按它给的规则**复算一遍**（文件名写 `<字符数>-<id>`，就复算字符数）。 |
| **4** | ★★★ **取代型改造 ⇒ 回归差集** | 见 §3.2。把 A 换成 B、把三份收成一份、删旧实现时**必做**。 |
| **5** | ★★ **证据只在夹具的形状上成立？** | 把**同一语义**换成**真实工程的形状**再跑（§1.6.6③）。 |
| 6 | **它没做什么** | 诚实清单里哪些是**没验证**、哪些是**验证了不通过**？后者常被写得像前者（§3.5）。 |
| 7 | **改动范围** | `git status` / `diff --stat`：顺手改了别处吗？临时脚本留在被跟踪目录了吗？ |
| 8 | **同族漏网** | 你给的是"这一类问题"，就**自己扫一遍同类**（实测：它修 2 处，还有 2 处漏网）。 |

## 3.2 ★★★ 回归差集

**触发**：把 A 换成 B / 把 N 份收成 1 份 / 删掉旧实现 / 大范围搬迁改名。

**① 免费基线**：别急着重建产物。若 `dist/`（或任何编译产物）**还是改动前的**，它就是**免费的旧基线**；
对**同一批输入**同时喂新旧两版，比出**差集**。
★ 前提：**两侧各自现算**索引/状态，不共用缓存（实测真仓直接跑会因索引陈旧漂出假读数；用临时目录 + 独立 `AGENT_IO_HOME` 重算）。

**② 判据必须是差集，不是单边**：**旧能新不能 = 回归**；**新能旧不能 = 新增能力**。
❌ 只验"指定输入现在对了"——它**不会**验"原来对的现在还对不对"。
实测（2026-09-30）：抓到 **1 处真回归**（新实现某层"未命中即早退"，吃掉旧实现会命中的回退路径）
+ **2 处真 bug**（`?? []` 把"未传"变成"空表"；`join('', '/abs')` 产出绝对路径 ⇒ 该层恒 null）+ **1 处与代码相反的注释**。

**③ 同一入口、逐条对齐、报出"只差哪一条"**：

```
before: checked 25 · passed 12 · failed 12 · unsupported 1
after : checked 25 · passed 12 · failed 12 · unsupported 1   （逐条只差第 5 条）
```

★ 关键在**"只差第 N 条"**以及**那一条是什么性质**（**设计重钉**还是**逻辑变化**）。
**只报总数相同不算证明**——总数可以两处互相抵消。★ 还要证明**其他块逐字不变**。

**④ 反例：别用错工具判"差异是否集中"**。用**最长公共前缀 + 最长公共后缀**判断差异是否集中是**错的**——
只要前 473 字符处有一处小改动，就会得出"差异分散"。正确做法：**数 diff 的 hunk**（`diff -U0` 的 `@@` 行）。
★ **"集中/分散"是关于 hunk 的问题，不是关于边界的问题。** 选错口径会得到**方向相反**的结论，而且看起来很有数据。

## 3.3 三条附加判据

**① 独立复核"你自己的判断"**：实测一天抓到 **4 处错，全是判断/口径类，0 处事实类**（`dagLayout` 其实是真操作；`editCode` 产物有类型；
目录改名会因**域表同 id 直接 throw** 而崩；`classifyTools` 第 2 个入参是 `BrickifyResult`）。
⇒ 只审"判断/口径"不查事实；**不要把结论告诉它**（只给判据，否则是请它背书）；判据给全；要 `文件:行` 并允许"找不到"。
★ 声称"另一个模型的意见"前必须拿到**路由证据**（`model` 传错名会静默回落默认）。

**② 缺陷指控先证可达**：① 门 pattern 真认不出同义写法（它对）；② 我的验具"3 个函数没原样保留"是**我的切分 bug**；
③ "`TOOL_DOMAINS` 文件夹化后失配"现象对，但 `toolDomainOf` **只在路径以 `tools/` 开头时被调用** ⇒ **不可达**。
⇒ **先读调用点** → **问这条路径在真实数据上出现过吗** → **不可达也要如实标注**。★ 排掉假指控时常暴露真问题。

**③ 计数类指控：数的是判据还是影子？** T48 指"C# 包缺冻结保护"，`grep -c protect` 得 **csharp=0**；真调一次：打标记后改名**被阻断**——
守卫在**两门语言共用的引擎**里，**恰好不在它数的文件里**。⇒ 换成**行为口径**实测，并换口径再数（看调用链）。
★★ **"哪个文件里有什么字面量"几乎从不是有效判据**——它假设"文件边界 = 能力边界"。

## 3.4 把过宽的表述改成可用的数字

- **"100%" / "全部" / "逐字相同"** → 要**分布**（几个块、各占多少字符/行）。
- **"一定 / 不可能"** → 要**因果**而不是**未观测**："没观察到" ≠ "不可能"。
- **"已修好"** → 要**可证伪的验收信号**（"下次跑批的 `diffStat` 必须非空"）。
- 修正后**写回文档**，并**保留"原表述错在哪"**——否则下一个人会重新引入它。
★ **证据分级**：**直接读过**（能指文件名与行）✅；**二手汇总** ⚠️ 只能当线索并写明；**推断** ❌ 必须标"推断"。

## 3.5 诚实清单

> ★ 本仓已有机械判据：`scripts/check-receipt.mjs` 检查回执 **C0 五栏**（做了什么 / 判据读数 / `[未核]` / 行为改变 / 滞涩报告），
> 缺栏 ⇒ `exit 1` 并点名缺哪栏。

**交活方必须写**：

| 栏 | 写什么 | 常见造假 |
|---|---|---|
| **做了什么** | 文件 + 动作，能对上 `git diff` | 把"计划"写成"已完成" |
| **判据读数** | 命令 + **原样输出**（不是"通过了"） | 只报总数不报逐条；只报"该绿的绿了"、不报"该红的还没红" |
| **`[未核]`** | ★ **显式列出没验证的**，并说清"没试"还是"试了不通" | 把"验证了但不通过"混进"没验证"（**最常被利用的一栏**） |
| **行为改变** | 对外可见的变化（契约/接口/产物） | 用"内部重构"掩盖契约变化 |
| **滞涩报告** | 卡在哪、原样报错 | 只写"遇到一些问题" |

★ 硬规则：**"试了不通"和"没试"必须分栏**。前者往往比成功更有价值（确切阻塞点：命令 + 原样报错）。

**核验方（我自己）回来必须写**：① **各读了多少**（行数/字节/**是否通读**，分块读完要说明，不许拿骨架冒充）；
② **合并了哪几处重复**（"旧 A §X 与旧 B §Y 讲同一件事" + 保留在哪节）；
③ **哪里两份说法冲突、按谁写的**（冲突 + 裁决 + 理由；**不允许"两边都留着让读者自己判"**）；
④ **删掉了什么、为什么**；⑤ **最终字数 + 三份是否已移走**（路径/可回滚）。
★ 第 ① 条是**防"看骨架提炼"的唯一办法**：**行数与"是否通读"必须自报**——
"读了 682 行"和"读了目录"在产出上**看不出区别**，只有被追问时才暴露。
