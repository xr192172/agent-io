## 八、坑清单（本会话实测踩过，勿重踩）

1. **PowerShell 吞 JSON 引号**：CLI 参数写文件用 `--input <文件>`；写 JSON 用 `[IO.File]::WriteAllText(path, text, (New-Object System.Text.UTF8Encoding($false)))`（PS5 Set-Content 带 BOM）。
2. **npm 必须用 npm.cmd**（npm.ps1 被执行策略拦）。
3. **DSH 沙箱**：node 子进程只能写 D:\dev_hzy；系统 Temp EPERM ⇒ 一切临时文件放工作区；SQLite 临时文件问题已用 temp_store=MEMORY 根治（不要回退）。
4. **AGENT_IO_HOME = 数据根**（不是 .agent-io 子目录）；设错会产生 `.agent-io\.agent-io` 重叠目录。
5. **WAL 锁**：并发开库会报 busy；检查残留 node 进程；checkpoint 用 `PRAGMA wal_checkpoint(TRUNCATE)`。
6. **registry.npmmirror 有 tree-sitter 包镜像**；GitHub release 用 gh-proxy.com 前缀。
7. **报错文案会骗人**："unable to open database file" 实为 FTS5 临时文件 CANTOPEN；"解析失败"其实可能是解析成功后写库失败——先拿堆栈再定论（本轮用 procdump/注入堆栈定位，最终靠最小复现）。
8. **跨项目数据根**：`.agentio-data`（跨项目 registry/judge-cache）在包根；`.agent-io`（项目本地）在项目根；两者别混。
9. fuintFoodSystem 根下 `.agent-io` 曾因错误索引建过一次（已删）；项目侧 cache.db 可删可重建，design/tasks 不可。
10. 侦察/重写代理只在 worktree 里干活；主工作区 D:\dev_hzy\agent-io 保持在 feat/lang-adapter-semantic。
