# 改动前必查清单（preflight checklist）

> **这份清单不是"注意事项"，是"可执行的检查"** —— 每条都带命令或读数要求。
> ★ 它的来源：**2026-10-15/16 一天里实际撞到的洞**（每条都注明了撞它的那件事）。
> ★ 用法：**动手前逐条过一遍**（该跳过的写"不适用"）；★ **每撞到一个新洞，就往这里加一条。**

---

## A. 动手之前（"数边界"）

- [ ] ★★★ **A0 · 先问「本仓有没有现成的便利工具」，再动 `grep`**
  ★★ **这个仓从最开始就是"给 agent 用的"**（仓里有 `dogfood/`）—— **`grep`/`read` 只作辅助（校验、定位），不作"理解项目"的手段。**
  | 要做什么 | 用哪个（不用 grep） |
  |---|---|
  | 看项目全貌 / 结构 / 规模 / 层次 / 决策卡 | ★ **`get_dsl query=features\|nodes\|edges\|files\|decisions\|digest\|pending\|calls\|functions`** |
  | 理解"谁调谁 / 谁依赖谁" | ★ **DB 的 `edges`**（call 7437 / type_ref 4727 / import 1202）—— ★ **比 DSL 里的 1074 条丰富得多** |
  | 定位某个符号 / 校验某处有没有某调用 | ★ 先用 DB `nodes` 查，`grep` 兜底（★ 用时要**标注"这是辅助"**） |
  | 判断"能不能改" | ★ **`write_gate`**（未登记不许落盘）· ★ **`validateDSL`**（图自洽） |
  | 收账 | ★ **`npm run verify`（4 道门）· `certs/*.mjs`（每笔一枚证）** |
  | 新旧判断 | ★ **`_sync.scanRev / age`**（★ 没有它就靠不住——见 §71 那个 14.25h 的坑） |
  ★★ **为什么这条排第 0**：用 `grep` 干活的代价是**具体的** ——
  **① 没有护栏 ② 没有校验器 ③ 没有微缩（每次靠读全貌）④ 结论没有住处 ⑤ 每次从零**。
  ★★★ **2026-10-15/16 一整天的"多轮迭代 / 边界漏了 / 报告与实际不符"，根因都在这** ——
  **在用一套"没有专用支持"的方式工作，然后手工补它本该有的护栏。**

- [ ] ★★★ **A0' · 「方案/结论」必须写成 DSL，并过 `validateDSL`**
  ★ 实测（§75）：**写方案 → 校验器报错 → 修 → green**，一轮里**逮住 4 个肉眼看不见的错**
  （字符串裸引号 · `/type` 必须 `const` · `/version` 必须是字符串不数字 · `/semantic/files` 必须是数组、`id` 必须是**节点 id**）。
  ★★ **且它可 diff**：分歧（"三态还是五态"）**写出来就是两张图，能逐条比**。
  ★★★ **语言说得出、但判不了；DSL 一写，错自己就冒出来。** —— 所以别用自然语言讨论方案。

- [ ] **A1 · 改一个函数 ⇒ `grep` 出它的「全部」调用点**
  `grep -rn "<fnName>" src/ | grep -v "function <fnName>"`
  ★ 撞它的那件事：改 `serve.ts` 时**只改了 `/api/load`，漏了同一个文件里的 `GET /api/live`（`serve.ts:390`）** ——
  它裸调 `getLiveFeature`，结果拿到的图**没有边**（`edges=ABSENT`）。
  ★ 纪律：**同一文件里也常有另一个入口**；★ 顺手把该函数的**导出**也数一遍（`export function`）。

- [ ] **A2 · 改一条通路 ⇒ 枚举它的「所有上限 / 截断 / 常量」**
  `grep -n "MAX_\|LIMIT\|Math.min\|slice(0" <那个文件>`
  ★ 撞它的那件事：`live_render.ts:56` 的 **`MAX_FILES=200`** ⇒ 真仓 479 文件里 **304 个（63%）拿不回事实**，
  而注释却声称"逐项复原" ⇒ **对拍静默少算**（`diff_views`：`design_symbols` 3530→1782）。

- [ ] **A3 · 摘/改一个字段 ⇒ 先 `grep` 全部「消费者」**
  `grep -rn "<字段名>" src/ certs/`
  ★ 撞它的那件事：摘 `symbols[]`/`lines`/`edges` 前**量过**（✅ 做了），但**漏掉"同文件内的其他入口"**（见 A1）。
  ★ 纪律：**"消费者"包括：读它的人、把它转发出去的 API、以及把它写回去的编辑路径。**

- [ ] **A4 · 谁在写 / 谁在读 ⇒ 双证**
  写：`grep -rn "save<X>\b" src/` · 读：`grep -rn "get<X>\b" src/ | wc -l`
  ★ 撞它的那件事：`edit_dsl` **读 `getDSL` 却写 `features/`**（"读A写B"）；
  以及 `derive_feature_tree.ts:276` **读 `live/` 却写进 `features/`**（注释自称"写回 live"，与实现不符）。

- [ ] **A5 · 改行为之前，先量「现状读数」**
  ★ 三次救场的同一招：**T340（险些红两证）· T353（量出 4 张证依赖旧行为）· (c2)（量出真仓漂移）**。
  ★ 纪律：**没有"改前读数"的改动，不许开工** —— 否则改完无法证明"只是我想改的那部分变了"。

- [ ] **A6 · 结论性判断 ⇒ 先问"我是在读事实，还是在推断？"**
  ★ 撞它的那件事：我说"`meta.goals` 可以放未实现条目" —— ★ **那是从 `OverlayGoal` 接口推的，不是实测**；
  实测 **DSL 里根本没有 `meta`**（全 JSON 检索 `meta`/`goals`/`storyboard` 命中 0）。
  ★ 纪律：**"某处有某字段"必须让定义与该字段在同一次读数里出现。**

- [ ] ★★ **A7 · 描述里的"键名 / 字段名 / 形状"一律以文件为准**（先打印形状，再写消费方）
  ★ 撞它的那件事（2026-10-16 滞涩小会 · 题二 runner）：派活描述写 `invariant_checks` 的键是 `cmd / pass_when / red`，
  ★ 实测是 **`invariant / check / cmd / red_when`** —— **根本没有 `pass_when`**；
  照描述写"找 `pass_when` 定通过条件"的 runner ⇒ **永远拿不到通过条件**（一种静默的假绿）。
  ★ 纪律：**形状类断言（键名 / 类型 / 层级 / 数组还是对象）必须先打印出来**再写消费方 ——
  `node -e "console.log(Object.keys(x))"` 或 `get_dsl`；★ 报告里转述形状时**标注"以文件为准"**。

## B. 做完之后（"证明它真的成了"）

- [ ] **B1 · ★★ "全绿 ≠ 被验"：有没有一条证覆盖「你新加的那个方向」？**
  ★ 撞它的那件事：(c2) 改动**有十九条证全绿**，但 **grep 全 `certs/` 只有 `t345` 提 `facts`，且它只盖读侧**
  ⇒ **写端无任何证** ⇒ ★ **"十九证全绿"与"这笔记被验"是两件事**。
  ★ 纪律：**新增一个方向（写端/新通路/新字段）⇒ 必须新增一条打它的证**，否则不许收账。

- [ ] **B2 · 有没有"半修"？**（本仓铁律：**半修比不修更坏**）
  ★ 检查：**这条改动有没有留下"看起来修好了、其实只修了一半"的中间态**？（(c2) 就是 → 已回退）
  ★ 做不完 ⇒ **回退**，把"已确证的部分 + 剩余清单"交回；★ **不许留残缺态**。

- [ ] **B3 · 真仓未被触碰**（读操作也会动 mtime）
  `ls -la --time-style=+%H:%M:%S .agent-io/features/<f>.json .agent-io/live/<f>.dsl.json`
  ★ 纪律：跑实验**一律临时目录 + 独立 `AGENT_IO_HOME`**；★ **真仓 `cache.db` 只读打开**（`readOnly:true`）。
  ★ 撞它的那件事：有人用**读写**方式开了一次真仓 `cache.db` ⇒ 其 mtime 变了（数据未改，**但要留痕**）。

- [ ] **B4 · 环境相关的确定性**（同一台机器对 ≠ 换台机器也对）
  ★ 撞它的那件事：布局排序用了 `localeCompare` ⇒ **同 locale 稳定、跨 locale 会变**
  （`zh-CN` vs `tr-TR` 动 7/14、vs `da-DK` 动 14/14）⇒ ★ **"按需渲染"的可复现性前提**。
  ★ 纪律：**排序/哈希/序列化里不许有 locale 相关的比较**；★ "可复现"要**跨环境**验，不是同机跑两遍。

- [ ] ★★ **B5 · 证的夹具必须"确定"：不许锚在"末行 / 末项 / 最大 n"上**
  ★ 撞它的那件事（2026-10-16 小会 · t347）：`t347` 里一条对照取 `docs/accounting.jsonl` 的**最后一行**当"老格式"夹具；
  ★ 而本笔自己随后往台账**追加了一条合规行** ⇒ **同一个证单独跑绿、批跑红**（`11/1`）。
  ⇒ ★★ **"最后一行是谁"会随文件增长而变** ⇒ 那不是可复现的夹具，是**时序巧合**。
  ★ 纪律：夹具锚在**append-only 的头部**、或**按内容查找**、或**内置字面量**；
  凡是"末行 / 末项 / 最大 n / 最新一条"作锚点的判据，都要问一句：**它明天还成立吗？**
  ★ 另一面：**批跑能抓到"单独跑是绿的证"** ⇒ 别只用单张证的绿去收账（本仓 B1 同源）。
