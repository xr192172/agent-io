## A. 动手之前（"数边界"）

- [ ] **A.1 · ★★★ 要改什么，就数它的「全部」消费点**
  ★ **改函数** ⇒ 数全部调用点；★ **改字段** ⇒ 数全部读写者；★ **都属于同一件事：先数，再改。**
  ★★ **必须数到的地方**（★ 实测两次漏在这）：**同一个文件里的其他入口 · 编译器断言钉死的那些断言 · 不止一处入口时被忽略的那一处**。
  ★ **判据**：数完贴一份清单（`file:line`），**并在改完后逐条回去确认没漏**。

- [ ] **A.2 · 改一条通路 ⇒ 枚举它的「所有上限 / 截断 / 常量」**
  ★ 例：分页大小、`MAX_*`、`slice(...)`、`top-N`、`LIMIT`。
  ★ **判据**：★ 报"某机制存在"时**让定义与调用同一次读数出现**（★ **不许从接口推**）；★ 说不出来 ⇒ 底数是编的。

- [ ] **A.3 · 谁在写 / 谁在读 ⇒ 双证（写端与读端各一条读数）**
  ★ **一处权威 + 一处渲染**：同一批数据不许两处都存。
  ★ **判据**：★ 写端与读端各贴一条；★ **"两处都能写" ⇒ 记下，这是"一事实两权威"**（★ 本仓头号病）。

- [ ] **A.4 · 改行为之前，先量「现状读数」**
  ★ 不许声称"没有行为改变"（★ 逐条列）；★ 不许用"看起来等价"代替"跑一遍"。
  ★ **判据**：★ 改前记读数 ⇒ 改后同跑 ⇒ 逐项比；★ **差异必须解释**（★ 包括"为什么这个差异可接受"）。

## B. 做完之后（"证明它真的成了"）

- [ ] **B.1 · ★★★ "全绿 ≠ 被验"：有没有一条证覆盖「你新加的那个方向」？**
  ★ **新增一个方向（写端 / 新通路 / 新字段 / 新 kind）⇒ 必须新增一条打它的证**；★ **没新增方向 ⇒ 不许造"打没做的功能"的假证**。
  ★★ **`unsupported > 0` 不算绿**（★ 判不了 ≠ 通过）；★ **`verify` 全绿 ≠ 本笔被验**。
  ★ **判据**：★ 每条新方向对应一张证；★ 证要**能自己坏**（★ 造一个坏样例 ⇒ 它报红）。

- [ ] **B.2 · 有没有"半修"？**（★ 本仓铁律：**半修比不修更坏**）
  ★ **判据**：★ **做不干净 ⇒ 回退**，把"已确证的部分 + 剩余清单"交回；★ **不许留"看起来修好了"的中间态**。
  ★ 实测：一笔子代理**开工前就停手**（认出"缺一维"而非"缺一条"）—— ★ **那是正确结果，不是失败**。

- [ ] **B.3 · 真仓未被触碰**（★ 读操作也会动 mtime）
  ★ 跑实验一律**临时目录 + 独立 `AGENT_IO_HOME`**；★ **真仓 `cache.db` 只读**（`readOnly:true`）。
  ★ **判据**：★ `features/…json` 与 `live/…dsl.json` 的 **mtime + md5 逐条贴**；★ 若被读开过（`-wal/-shm`）**如实报**。

- [ ] **B.4 · 环境相关的确定性**（★ 同一台机器对 ≠ 换台机器也对）
  ★ 例：**排序用 `localeCompare` ⇒ 换 locale 坐标全变**；★ 路径大小写；★ 时区；★ CRLF/LF。
  ★ **判据**：★ 找出"依赖环境的那一处"，★ **或**明确写"本处依赖环境、影响面是 X"。
