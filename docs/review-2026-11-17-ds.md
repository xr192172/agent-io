## ① 架构与判据体系：强在哪、弱在哪

**强（有锚点、可复核）**

- **一处权威被写成制度而不是愿望**：门自己不实现判定，只调现成函数（`scripts/verify.mjs:458-460` 结构意图门调 `design_line.ts#silentGapsOf`、`structure_gap.ts#structureGap`；`:520-521` 派生条目门调 `req_baseline.ts#judgeDerivedEntryChange`）。这条纪律比"多写测试"贵一个量级，因为**它让"第二把尺"成了可被判红的错误**。
- **四值语义贯穿到退出码**：`unsupported ≠ pass`，读不到册也判红（`scripts/verify.mjs:368`）；总门三态 0/1/2，缺输入用 2 而不是折成 0（GUIDE-GATE.md:30-34）。这是**假绿的免疫系统**，业界多数 CI 只有 0/1。
- **棘轮只许不增，且"清零"必须显式**：判据总数 816（`scripts/judge-baseline.json:3`）、测试 139/821（`scripts/test-baseline.json`）、工具面 40 工具 / 154 034 字节（`scripts/mcp/tool-surface-baseline.json`）、无卡写账 `max_no_card:1`、结构缺口基线**已清空**（`scripts/structure-gaps-baseline.json` 的 `files:[] / dirs:[]`）——**棘轮能被注销，说明它不是永久豁免**，这是很多仓做不到的。
- **判据强度分层写进了纪律**：`file-exists`/`symbol-exists`/`signature-matches` 明确标"发现不了逻辑错"（AGENTS.md:39）；实测分布也真的是强判据为主：run 244 / call-exists 161 / source-has 123 / behavior-cases 99 / signature-matches 60 / domain-independent 57 / symbol-exists 34 / file-exists 31 / edge 6 / runtime 1（`scripts/judge-baseline.json:4-93`，我按 kind 加总 = 816，与 `total` 闭合）。
- **"检查对象退出检查范围 ⇒ 检查自动变绿"被写成收尾第一问**（AGENTS.md:99-105）。这是我认为整套方法论里**最不该被抄漏的一条**。

**弱（同样有锚点）**

- **判据强度仍有 8% 的软底**：存在类 71 条（file-exists 31 + symbol-exists 34 + edge 6）占 816 的 8.7%。突变门前只抽 N=5 个 `behavior-cases` + 1 个 `call-exists`（`scripts/verify.mjs:406`），**软 kind 一条都抽不到** ⇒ "软判据退化"在结构上不可见。
- **门的语义边界靠注释守，不靠类型守**。「不建免疫系统门」「永远亮的告警等于被关掉的告警」都是散文（verify.mjs:314-316、GUIDE-GATE.md:38）；`为什么撤过 3 道门`（`:347-361`）也只在注释里。**一个新人删掉 `--allow-structure-gaps` 不会红**。
- **双档内环/全量的判据本身是散文**：`npm run verify:changed` 的"必须重验 / 允许继承"四条（AGENTS.md:50-55）没有对应机器判据；`verify` 13 分钟 vs 内环 20-30 秒的差（AGENTS.md:82-83）只写在文档里。

## ③ 并发多模型协作形态：可扩展性与风险

**形态**（`AGENTS.md:227-250` + `docs/todo.md:500-508, 580`）：侦察席（只读，无写盘无子代理）→ 执行席（第一轮只回报）→ 验收席（只给树 + 判据，不给过程）→ lead 合并/裁定；台账行 = 一条 PR（提案 → 反驳/反例 → lead 裁定 → 动工 → 证据回填），批注**追加不改写**；正在试"多席并发 `edit_dsl` 提案 → lead 像 merge 分支一样合并 → 领卡 → 并发 `edit_code`"。

**可扩展的正确之处**

- **把"并发"限制在只读侧，写侧单腿**（`heavy.lock` + 同一棵树，AGENTS.md:248）。这与"合分支"的直觉相反，但**是唯一在单仓上成立的**：`verify`/`mutate`/`judge-all` 互斥（AGENTS.md:127），`write_log` 是 append-only 且无 RELABEL（`write-log-baseline.json` note 记"事后补卡不可能"）。
- **反驳义务被制度化**：后续席必须先读原提案再交"支持或反驳 + 反例"（`docs/todo.md:502-504`）。这是把 code review 里最贵的部分（为什么不同意）变成**存储对象**。
- **证据链自带过期语义**：`complete` 的 `evidence` 必带 `command + observed`，代码变了证据自动过期（README.md:43-44）。

**风险（我认为是真的）**

- **R1 · "并发设计链"缺合并工具**：现在是 lead 手工合并（`docs/todo.md:580` ②）。L1 引擎只做了写端与只读查询、**不含冲突检测**（`ledger.ts` 全文无 diff/merge 概念）⇒ 三路并发提案时，**冲突裁定质量 = lead 的上下文余量**，而 lead 的上下文正是最稀缺资源（D6）。
- **R2 · 已发表的反证要正面回应**：`Informed but Still Colliding`（591 episodes，Qwen3.7-Plus / DeepSeek Flash）测的正是"工作区感知 + 显式协调规则能否减少并行 agent 的合并冲突"（[Zenodo 复现包](https://zenodo.org/records/23467694)，引 CooperBench arXiv:2601.13295）。而 `Asymmetric Repository Lineage Modeling…` 更直接：**79/167（47.3%）的冲突发生在"改的文件集合不相交"的 PR 之间**（[NeurIPS 2026 workshop](https://neurips.cc/virtual/2026/loc/atlanta/171490)）。⇒ AgentIO 现在用 **`write_gate` 的读集/文件集冲突**当并发护栏（VISION.md:23"读集冲突拒领"），**只能挡住那 52.7%**。这不是否定，是**必须承认的能力边界**，并且正好对应 §I 里 498 跨册 id 那类"结构性共享"。
- **R3 · 席位没有"谁负责收敛"**：三席里 lead 兼裁定 + 合并 + 提交 + 基线更新（AGENTS.md:95"更新基线是主控的活"）。**单点**。`T-#SELF-DOGFOOD` 的触发契机写得很诚实——"工具在设计上就在纠正我，我绕开了它"（`docs/todo.md:580`）——但**这句话说明的其实是：纪律拦不住 lead**。
- **R4 · 席位本身就是新的一层复杂度**：现在有 `seat_scout` / `seat_acceptance` / 执行席三种角色 + 五档能力分派（AGENTS.md:256-262）。**四份 append-only + 三席位 + 14 门 + 816 判据 + 1.16 MB 文档**，一个人维护。这是我最担心的一条：**不是复杂度失控，是可维护性单点**。

## ⑤ 可发表性：值得写，而且是**方法论文**不是工具论文

**值得写的三件东西（按独特性排序）**

1. **判据突变门（criterion mutation）**：`scripts/mutate.mjs` 对 `src/` 做一处语义突变 → 跑该条判据 → 逐字节还原；`survived>0 / unsupported>0 / killed===0` 都判红（`scripts/verify.mjs:398-411`）。**这是"判据是不是装饰"的可执行回答**。我在检索里只找到相邻物——"generator + evaluator 循环 + machine-checkable evaluator（deterministic oracle the LLM cannot fake）"与 reward hacking 的讨论（[aiefs vol5 agents](https://release-assets.githubusercontent.com/github-production-release-asset/1185590488/fb5c2119-7fe9-4995-bb1d-a1ebb5fcec44)），以及 [MADS-CPS 的 machine-checkable run-level evaluation contract](https://kdd-eval-workshop.github.io/agenticai-evaluation-kdd2026/assets/papers/6_A_Machine_Checkable_Run_Leve.pdf)——**都没有把"变异测试"用在"判据自身"上**。这一条单独就够一篇短文/一个开源亮点。
2. **假绿税收（false-green ledger）**：每个门的 `why` 都是一次真实事故的尸检，且四值语义 + 三态退出码把"判不了"从绿里分出来（`GUIDE-GATE.md:28-40`）。业界对照里最近的是 NeurIPS 那篇的"cheap signals vs executable checker"（[链接](https://neurips.cc/virtual/2026/loc/atlanta/171490)）——**它讲"用可执行裁判代替廉价信号"，AgentIO 讲"可执行裁判自己也会假绿"**，这是递进关系，不是重复。
3. **PR 链台账 + 三席（侦察/执行/验收）**：与 ICML 2026 的 [Adversarial Review: Cooperative Code Review through Structured Disagreement](https://icml.cc/virtual/2026/76905) 撞面。那篇的结论对 AgentIO 有利也有害：**"scaling agent count yields diminishing returns，main-agent + reviewer + critic 是甜点"**。AgentIO 恰好是 main + scout + acceptance，**独立收敛到同一形态**——这是好事（说明形态对），但也意味着**这一条不是新颖性，是验证**。

**业界最接近的三类，与我的评审论点对照**

| 业界工作 | 与 AgentIO 的关系 | 支持 / 反驳我的哪条论点 |
|---|---|---|
| [NeurIPS'26 并发 agent 的 verifier-guided coordination](https://neurips.cc/virtual/2026/loc/atlanta/171490) | 同题：并发 agent + 可执行裁判 + 冲突预测 benchmark（MERGEGYM） | **支持**"判据 > 读数"（§①）；**反驳**"重度增量继承"：它的实测是 "median git merge-tree replay 0.02 s ⇒ **when exact replay is cheap, verify everything**"。AgentIO 的全量 13 分钟主要在测试门（8.8 min），**不是重放贵，是测试贵** ⇒ `T-#INC-VERIFY`（门级继承，L 规模）的收益被高估，`T-#INC-JOBS`（已实测 2.04x，commit `41b6029b`）才是对的方向。 |
| [Passes Alone, Fails Together（stale benchmark）](https://dl.acm.org/doi/10.1145/3842650.3843171) | 并行 patch 各自过、合起来挂；834 runs / 417 Django 对 | **反驳** §③ 的"文件集不相交 = 安全"：AgentIO 的 `write_gate` 文件级冲突护栏**测不到**接口语义冲突。 |
| [Informed but Still Colliding（Zenodo 复现包）](https://zenodo.org/records/23467694) + ICML'26 Adversarial Review | 591 episodes；workspace awareness 的限界；main+reviewer+critic 甜点 | **支持**三席形态（独立收敛）；**反驳**"多席并发越多越好"——该文献的取向是**减少** agent 数、提高单个协作密度。 |

**可发表性缺口（诚实版）**：AgentIO 现在**没有任何对照读数**——没有 baseline、没有真实项目上的 A/B、没有"这套流程 vs 直接让 Agent 写"的度量。而上面三类工作全是 benchmark / randomized experiment。⇒ 要发表，**必须先补 §④ 缺的 ①**（一条真实项目端到端 + 一个可比基线）。这也是一件好事：**它同时是产品价值的唯一证明**。

## ⑥ 可优化点 Top5（影响 × 成本，含最小改法）

**1. 让 L1 引擎有第一个消费者（影响 ★★★★★ / 成本 S）**

**2. patrol 加 S4：台账/册/代码三方对账（影响 ★★★★★ / 成本 S）**

最小改法：`scripts/patrol.mjs:170-194` 的 `ledgerCheck` 里增一档，输入全部现成（`judge-baseline.json` by_kind · 册 `.agent-io/design/*.dsl.json` · `tasks.db` 计数）。**只报不改**（与 S1/S2/S3 同口径），读数带分母。这条修的是**元问题**，且不新增门（入口数不增，符合 AGENTS.md:155）。

**3. 给"软判据"上方向棘轮 + 强制抽样（影响 ★★★★ / 成本 S）**
现象：存在类 71 条（8.7%），突变门只抽 `behavior-cases`+`call-exists`（`verify.mjs:406`）⇒ 软判据退化不可见。

**4. 把 `docs/todo.md` 降级为派生视图（影响 ★★★★ / 成本 M）**

**5. CLI 逃生舱 `key=@file` / `key=@-`（影响 ★★★ / 成本 S）**
现象：PowerShell 吃引号**已两次实测**（`docs/todo.md:559`；AGENTS.md:131-133 也记了 PS 坑）。当前唯一绕法是"写 JSON 到临时文件再 `--input`"——**每多一步就是一次人肉失误面**。
