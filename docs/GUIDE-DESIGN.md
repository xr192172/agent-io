# 设计指南：写一道不会撒谎的判据

> 2026-10-18，从 17 份 skill 里**只提取设计侧**内容，按主题重组，**逐条注明出处**（`skill` §节）。
> 本文件不引入任何 skill 里没有的判断；凡是合并/排序，都只是编排，不是新增主张。
> 适用边界见 §0；操作侧（加/删工具、跑链、验收命令）见 `GUIDE-USAGE.md`。

---

## 0. 先划边界：门纪律只管门，不管散文

| 断言住在哪 | 要不要较真 | 出处 |
|---|---|---|
| **门 / 量具 / 测试**里的断言 | ★★ 必须较真：撤掉修复 ⇒ 必须变红（消融自证） | `gate-authoring` §0b |
| **注释 / 文档 / 散文**里的描述 | **便宜且真**，发现即改，**不做出生证** | `gate-authoring` §0b |

- 判对错就两条：**测试通过 + 与契约相符**；把"注释里一句话写错"升级成"纪律/新门"是**过度工程化**，副作用是写东西时缩手缩脚。（`gate-authoring` §0b）
- 别把"改了对外契约/语法"写进"代价"清单：若项目没有外部消费者，那只是自家一次同步。（`gate-authoring` §0b）
- ★ **顺序纪律**：先问"编译器/框架能不能查" → 能就改设计 → 改完门会自己变小。不要先把门写出来再回头想它是否多余，那时第二份副本已经造出来了。（`gate-authoring` §5g）

## 1. 判据怎么写才不撒谎

### 1.1 证据来源：只跑真的，不读文本

1. **只跑真证据，不读源码。** 正则解析源码文本 = 在猜"它大概是什么样"；要 import 编译产物、真调函数、内省运行时对象。（`gate-authoring` §0 纪律 1）
2. **判"有没有某能力"不能数字面量。** "哪个文件里有什么字面量"几乎从不是有效判据 —— 它假设"文件边界 = 能力边界"，在有共享/继承/引擎化的代码里这个假设经常是假的。（`verify-delegated-work` §6）
   - 实例：C# 语言包 `protect` 命中 0，但保护其实生效 —— 守卫在两门语言共用的引擎（`java.ts`）里，C# 走的正是那个引擎。（`verify-delegated-work` §6）
   - 正确问法：**"该行为在产物里留下了什么痕迹"**，而不是"某个标识符在不在"。（`dsh-delegate-loop` §5）
3. **按名字 grep 会骗你。** 删工具前要 grep 真 import 语句（含 `.js` 后缀），不是按名字 grep —— 命中的大多是注释、字符串、术语表、历史快照。（`dc-remove-tool` §一）
4. **文本匹配型判据不懂语义。** 必须问："我匹配的是**路径参数**还是**文件内容**？""是**读**还是**写**？" 修法是给规则加语义 scope，不是继续调正则。（`gate-authoring` §3）
5. **别用文本判断"是否被引用"。** 建真 import 图；文本只可用于没有边的唯一一类：**字符串路径**（构建脚本按名字读源文件），且必须单独成桶。（`guard-blindspot-diagnosis` Pitfalls）

### 1.2 自证：两个方向 + 消融 + 出生证

6. **两个方向都要自证**：① 坏输入被挡在**正确的级与检查项**上；② **好输入必须被放行**。只证 ① 的门可能是个"一律 blocked"的废门。（`gate-authoring` §0 纪律 3）
7. **未实施的级必须显式标 `unenforced`**，绝不计作通过；过门时**必须**把未实施的级打印出来。（`gate-authoring` §0 纪律 2、§1.5）
8. **消融自证**：逐个撤掉修复 ⇒ 对应的断言**必须变红**。两个方向只能证明"门能区分好坏"，消融才能证明"门测的就是那个修复"。（`gate-authoring` §2）
   - 消融要**逐个**，不能一次全撤；断言名要写清意图，输出才能告诉你哪条被判据覆盖了。（`gate-authoring` §2）
9. **出生证**：回归测试若从未失败过，它没有价值。把**旧逻辑跑新夹具**、看它给出坏结果，并把这条断言写进测试文件、注释说明"这就是旧代码会挂的那条"。（`guard-blindspot-diagnosis` §6）
10. **门的出生证也要被检查**：自证里的变异体必须**就是那个要防的形状**；旧自证"能报红"却没在测要防的东西，不算自证。（`gate-authoring` §3 铁律 41 ④）
11. **门必须是唯一能改状态的路径**；`acceptance.kind` 只认门写的回执，**散文引用（指向某文档"已验证"）不算判据**。（`gate-authoring` §1.3）
12. **回执要可审计**：`{kind, ref, status, ranAt, proofLevel, unenforced, checks[], evidence}`，`checks[]` 逐项带 `{level, name, ok, detail}`，失败能指名原因。（`gate-authoring` §1.4）

### 1.3 契约与计数：别让"部分损坏"变成通过

13. **契约类门要校"声明条数 = 解析条数"**：只断言"解析出 > 0 段"，会在 5 段被改坏 4 段时解析出 1 段而不报错 ⇒ 契约被悄悄从 5 降到 1 = 假绿。声明值认不出来也要抛错。（`gate-authoring` §3）
14. **契约从唯一真相源解析**，不许手抄第二份；解析锚点要放宽到措辞（同一文件里可能有"你的回答必须…"与"产出必须…"两种写法）。（`gate-authoring` §3）
15. **文本/名称匹配要归一化**：`推荐 + 风险` vs 「推荐与风险」在合格产出上会长期假红 ⇒ 门被当噪音 ⇒ 整体被绕过。**容忍措辞，不容忍缺失**；反向也要查（裸词 `同会话` 会命中「不**同会话**」= 假绿）。（`gate-authoring` §3）
16. **汇总必须与明细对账**：报"N 题有效"时同时断言 `results.length === 输入条数` 且 id 无重复；一条记录只允许一个 `push` 位置（`continue/break/return` 都会跑 `finally`）。（`gate-authoring` §3）
17. **文本判据一律先标定作用域**：全局 `indexOf`/正则取"第一次出现"会跨作用域命中 ⇒ 在完全正确的源码上恒报红。（`gate-authoring` §3 铁律 41）
    - 断言要写成**真正要防的形状**（"从 retire 到封口之间不许有任何解锁"），不是"两个全局下标谁大"。（同上）
18. **判据/规格/答案清单不能放在被测对象的读写范围内**：否则第一条动作就是 `read` 题面与判据脚本，陷阱全部降级成"照抄规格"，且会让上面所有纪律一起失效。（`gate-authoring` §3）
19. **判据的样本分布必须是真实分布**：用自己手写的"合格样本"定判据 = 用我猜的分布去量真实对象；上线前至少拿一次真实产出校准。（`gate-authoring` §3）

### 1.4 覆盖面：扫描面必须等于管辖面

20. **门要覆盖"用户真正碰的那个对象"，不只是源**：源 `scripts/dsh-up.cmd` 修好了，派生物桌面快捷方式没重生成 ⇒ 用户双击满屏报错。凡"生成/拷贝出来的东西"都要问"它的门在哪"。（`gate-authoring` §5）
21. **扫描面 = 管辖面**：门声称管什么，就必须真的遍历到什么。症状：读数**恒为 0 或恒为某个整数**。实例：一个"未登记目录"门只遍历 1 个容器却声称管整仓 ⇒ `unlisted: 0`，真实有 17 个目录。（`gate-authoring` §6）
    - 「容器」节点必须**既算自己的、又递归进去**；只做一边就漏一半。（同上）
22. **别快照"会测量仓库本身"的工具**：`index_integrity`/`harvest_decisions` 的输出会随被删文件、新增文档而变。把快照分成 **stable（逐字节）** 与 **measuring（只断言结构：能跑、非空、不抛、报告形状在）**。（`guard-blindspot-diagnosis` Pitfalls）
23. **单独绿但全套红 ≠ 绿**：顺序/状态依赖与跨测试干扰只在全套里可见。（`guard-blindspot-diagnosis` Pitfalls）
24. **门不能把自己数进去**：残留/模式门的源码里必然出现它要查的模式；用**单独常量**排除自己，不要塞进"历史/豁免"名单（两种豁免意思完全不同）。（`guard-blindspot-diagnosis` Pitfalls）

### 1.5 门自己的输入：名单会腐烂

25. **每个门都有输入**（豁免名单 / 基线快照 / allowlist / frozen 计数）；它们腐烂时长得像正常：「陈旧 / 冗余 / 死代码」与「合法豁免」在门眼里无法区分。（`gate-authoring` §5b）
26. **豁免 = 断言 + 复算**，不是"一行豁免"：每条携带证据字段（如 `importedBy`）+ `why`，门每次跑都重算，断言不成立 ⇒ 红。（`gate-authoring` §5b）
27. **三条可复用检查**：① 存在性（路径必须存在）；② 覆盖性（能被自动判据覆盖的条目不许留在名单里）；③ 必要性（"无人使用"必须由扫描给出，无人使用 ⇒ 删，不是豁免）。（`gate-authoring` §5b）
28. **配套棘轮**：条目数只许减不许增，基线写成常量；新增 ⇒ 红，逼你在同一次提交里写下"为什么判据盖不住它"。（`gate-authoring` §5b）
29. **别在门里硬编码"实现住在哪个路径"**：文件一移动/拆分，门当场失效；按**目录扫描**算输入位置，且"输入在哪"本身是知识，只留一份。（`gate-authoring` §5b；`guard-blindspot-diagnosis` Pitfalls）
30. **加门前先算状态群账**：按更新机制分三类 —— 自动重生成（不是负担）/ 空表（不是）/ **真手维护**（是负担）。（`gate-authoring` §5c）
31. **问"期望值从哪来"**：有独立判据（对外契约、行为等价且改基线要记账）⇒「变化即红」靠谱；只有棘轮存量 ⇒ 冻结的是**当时的读数**，而读数可能本来就是假账。（`gate-authoring` §5c）
32. **能由判据取代的，就整表删掉** —— 这是唯一真正的收敛。反面：**不要为了"记住欠账"再建一个门**；台账写在**一个** markdown 里，并写明"本节是唯一出处"，且只记核实过的。（`gate-authoring` §5c）
33. **自写门 vs 现成工具**：判据只有一条 —— 你这套语义能不能干净地映射到某个现成工具的约定？能 ⇒ 用工具（规则集由社区维护，不随你的口味漂移）；不能（领域特有语义）⇒ 自写，但应该很少。（`gate-authoring` §5e）
    - "用工具"不等于"写一堆自定义规则"；自定义规则写多了，工具就重新变成自写门。（同上）
34. **限度的诚实 ≠ 限度的量化**：门里写"本门查不了漏写的"只是自我安慰；要**派独立核验**（不给它看被核验对象，只给源头）、回来**逐条抽验**、未验的**如实标注并计数**（`notRegisteredYet` + 棘轮）。（`gate-authoring` §5f）
    - 实测结论：**一扇门只保护它册上的东西** —— 独立核验清出 ≈18 项没登记的数据 + 3 处"同一份数据两个根"，门一条都没报。（`gate-authoring` §5f）

### 1.6 严重度与失败方式

35. **分档**：`ERROR` ⇒ 非 0；`WARN` ⇒ 退出 0 但大声打印 + 计数。一律判红的后果是使用者绕过门或盲目加豁免 —— **门被绕过 = 退回没有门**。再给 `--strict` 把"严"做成可选旋钮。（`gate-authoring` §4）
36. **读数"不可用"必须与读数"为 0"分开报**：通道自身不可用时显式输出"本通道无结论"，并在总判定里让它**不参与**（不是当 0 参与）。（`gate-authoring` §3）
37. **留红的意思是"没证据"还是"真坏了"要分清**：后者要修，前者要如实报告并留红 —— **不许为了让门变绿而制造证据**；fail-closed 的门禁止"就地自证通过"。（`gate-authoring` §6）
38. **收尾动作不要只依赖"删除"**：宿主可能给 `fs` 加批量删除护栏（50/turn）；收尾写成"先删，删不动就置空"，断言放宽为"不存在或已置空"。（`gate-authoring` §5d）
39. **更正记录**：如果文档已声称某闸"修好了"，后来发现是假修复，**不要悄悄改代码** —— 加一节写清"假修复 vs 真修复" + 时间轴 + 标记旧结论。（`guard-blindspot-diagnosis` §8）

## 2. 假信号分档

### 2.1 三档：按"有没有坐标"排序

| 档 | 症状 | 有没有坐标 | 为什么坏 | 出处 |
|---|---|---|---|---|
| **假绿 / 空过**（最坏） | 没跑或退化成空转的检查显示成通过；遍历空集也算过；只断言"没抛错"不查值 | **没有** | 输出是绿的，你连该去哪看都不知道，而且你以为查过了 | `gate-authoring` §3 |
| **无门**（次坏） | 压根没有这个检查 | 没有 | 诚实的无知：至少你知道自己没查 | `gate-authoring` §3 |
| **假红**（相对最好） | 判据写错，拦住合法输入 | **有** | 把"未知的未知"变成"已知的未知" | `gate-authoring` §3 |

- **⇒ 假红优于无门。**（`gate-authoring` §3）
- 但假红有**两条出口，只有一条对**：① ✅ 修判据；② ❌ 改被检对象去迎合（改声明、放宽阈值、加豁免）—— 后者把假红**转化成假绿**，从"有线索"掉进最坏档。（`gate-authoring` §3）
- **铁律：看到假红，先证明判据错了，再动判据；绝不动被检对象。** 分不清就先当代码错查（默认信任判据）。（`gate-authoring` §3）
- 第二重风险：反复误报 ⇒ 门被绕过/没人看 ⇒ 退化成"名义上有门" = 假绿。（`gate-authoring` §3）

### 2.2 更坏的一种：量具双向失真

- **同一把量具可以同时假绿 + 假红 + 读数饱和**：实测一个 `.js`→`.ts` 后缀 bug 让整张 import 图消失 ⇒ `orphan_file` 284（92% 误报）**同时** `layer_violation` 0（空转），健康分修前修后都读 0。（`guard-blindspot-diagnosis` §1d）
- 这**比静默放行更坏**：假红会摧毁操作者看门的意愿。（`guard-blindspot-diagnosis` §1d）
- **三条体检**（信任何门之前先跑）：
  1. **桶分布**：一个桶装了 ~everything（实测 283/308）⇒ 报出的 `0` **不是通过，是证明规则打不响**。问："什么输入会让它红？那种输入在语料里存在吗？"（`guard-blindspot-diagnosis` §1d.1）
  2. **动态量程**：喂一个已知好、一个已知坏，读数相同 ⇒ 指标是**穿着判据外衣的常数**。（`guard-blindspot-diagnosis` §1d.2）
  3. **夹具现实性**：夹具用无扩展名 import，真实语料 961/971 带 `.js` ⇒ 测试**永远不可能失败**。（`guard-blindspot-diagnosis` §1d.3）

### 2.3 假绿 / 空过的常见来源

- 把 `{kind:'ref', status:'passed'}` 这类**散文回执**当判据。（`gate-authoring` §3）
- 未实施的级默认显示"通过"而不是 `unenforced`。（`gate-authoring` §3）
- 检查退化成空过：`for` 遍历空集也算通过；只看"有没有抛错"不看值。（`gate-authoring` §3）
- **依赖一个不存在的 API ⇒ 判据恒空过**：`listSessions()` 方法名不存在 ⇒ 取空列表 ⇒ 循环零次 ⇒ 171 条记录读数全 0，门槛从未量过任何东西。（`gate-authoring` §3）
- **append-only 日志只读末段**：整篇数标记时，前一天失败启动的陈旧行会让阳性臂被谎报成"起来了"。（`gate-authoring` §3）
- **多根配置静默遮蔽**：`select` 返回 200、回读也显示同名，装的却是随附那份 ⇒ "名字对上了"永远不是证据，要比**名字 + 来源/信任级别 + 内容派生量**。（`gate-authoring` §3）
- **汇总计数虚高**：同一记录 `try` 里 push、`finally` 又 push。（`gate-authoring` §3）
- **注册了但永不变红的门**：`verify.mjs` 的默认模式从不设 exit code ⇒ 无条件返回 0，而当时真的存在未定义占位符。**问"凭什么它会变红"**；答不出就是**装饰**。（`guard-blindspot-diagnosis` §7b）
- **对所有输入都成立**：通配边 `ANY_TOOL → ANY_TOOL` 让任意两条链都"通过" ⇒ 判据无法失败。（`guard-blindspot-diagnosis` §7d）
- **天花板饱和**：喂不存在的路径，读数 `100（A）` ⇒ 路径打错被当成通过检查。必须给"无输入"独立的第三态，并对坏根非 0 退出。（`guard-blindspot-diagnosis` §1d.4）

### 2.4 假红的常见来源

- **把两个不同维度当代理关系**（"不继承上下文 ⇒ 不该继承凭据"）。（`gate-authoring` §3）
- **依赖脆弱解析**（正则匹配源码格式 ⇒ 上游一重构就假漂移）。（`gate-authoring` §3）
- **注释污染文本判据**：负向断言被注释里的旧 bug 名字触发；正向断言被注释里的示例满足（假绿）。凡对源码做文本断言，**先剥注释**。（`gate-authoring` §3）
- **文本判据没有作用域**（见 §1.3 第 17 条）。（`gate-authoring` §3）
- **措辞不归一**（见 §1.3 第 15 条）。（`gate-authoring` §3）
- **读数随工作根漂移**：同一个文件在 `root='src'` 与 `root='.'` 下分类不同 ⇒ 两次"同一个量具"的读数差一两个。要归一化并把**根不变性写成断言**。（`guard-blindspot-diagnosis` §1d.5）

### 2.5 一种不是错的读数：诚实的 NONE

- 盲测里被试答 `NONE`（"清单里没有能干这个的"）是**诚实的够不着，不是错**；代价是"多走入口"（1–3 步）。**硬凑**才是"面偏了"的信号。（`dc-face-bench` §四）
- 与三档同构：**诚实无知（NONE / 无门）优于假的好看（硬凑 / 假绿）**。（`dc-face-bench` §四 + `gate-authoring` §3）

## 3. 闸会失效

### 3.1 两个根因

> **纯否定判据（"没找到错误 ⇒ 健康"）分不开"干净"与"证据还没产生"。**
> **对异步落盘的外部产物只读一次，是必然的竞态。**
> 两者相加 = 静默通过。修法不是更好的正则，是**有界等待重读 + 必须出现的正向信号**。（`guard-blindspot-diagnosis` 核心洞察）

### 3.2 失效后的取证

- **先复现案发现场，不许先猜**：从磁盘已有产物建时间表 —— 门自己的 status log（何时报成功）、目标的生命周期/退出 log（何时死、退出码）、门读的证据文件 **mtime**（证据何时才落盘）、进程的 boot marker（何时开始）。（`guard-blindspot-diagnosis` §1）
- **`mtime > 门报成功的时刻` ⇒ 门读太早**，这就是全部诊断。（`guard-blindspot-diagnosis` §1）
- **数"这条判据历史上为正过几次"**：0 次不是"没出事"，是**判据是死代码**。实测：204 次 defer 里 `waitedTurnEnd=true` 为 0；171 条 freeze 里 `lastSeq` 非 0 为 0 —— 两个"保险"从未启用，而文档/注释/操作者都以为它们在。（`guard-blindspot-diagnosis` §1b）
  - 作者侧推论：**门要打印"这条判据曾为真几次"**，0 本身就是警报。（同上）
- **"看不到" ≠ "观察到没有"**：数据源缺失时诚实结论是 **unknown ⇒ fail closed**，且要把可观测性做成独立字段（`agentsObservable: false ⇒ quiesced forced false`），不能用一个空数组冒充"没有东西在跑"。（`guard-blindspot-diagnosis` §1c）
- **先排除"模式早就覆盖了"**：把整段产物喂给现有匹配器，若现在能匹配 ⇒ 问题从来不是判据，是**时序**。（`guard-blindspot-diagnosis` §2）
- **枚举失败路径上的所有闸**：找被 flag 条件跳过的窗口（`if (!fast && windowMs > 0)`）；"fast path"等于零观测窗。（`guard-blindspot-diagnosis` §3）
- **两个看起来像的窗口可能是正交的**：liveness probe 答"进程还活着"（崩溃前一刻也是 true），不答"日志刷完了吗"。（`guard-blindspot-diagnosis` §3）

### 3.3 修法：有界等待 + 正向证据 + 三态

```
loop until deadline:
  if process already exited (exitCode !== null) -> FATAL   # 确定性，无竞态
  seg = re-read evidence
  if fatal patterns match -> FATAL   (early-exit)
  if POSITIVE ready signal -> HEALTHY
  if deadline passed -> UNKNOWN      (证据不足)
  sleep(interval)
```

（`guard-blindspot-diagnosis` §4）

- **三态而不是 bool**：`healthy` / `fatal` / `unknown`；`unknown` 对调用方**表现得像 fatal**（"不知道它是好的"和"它是坏的"同样不能进生产）。（`guard-blindspot-diagnosis` §4）
- **确定性死亡信号优先**：`child_process.proc.exitCode !== null` 由内核填，没有竞态；`process.kill(pid,0)` 有 PID 复用窗口。（`guard-blindspot-diagnosis` §4）
- **窗口按实测定**（观测到的证据延迟 × 1.75，3.41s → 6s），不按口味；别过度加宽，每次换代都要付这个成本。（`guard-blindspot-diagnosis` §4）
- **可注入**（`timeoutMs/intervalMs/hasExited/isAlive/now/sleep`），否则逻辑无法用假时钟单测。（`guard-blindspot-diagnosis` §4）
- **正向信号要实证判别力**：扫描历史上每一段运行，统计它覆盖了多少好运行、有没有好运行缺它；参考案例里 `dsh web: http://…` 出现在 9/10 真实段，唯一缺失的就是崩溃段。优先选**在所有可能失败的东西之后**才出现的信号。（`guard-blindspot-diagnosis` §5）

### 3.4 失效的其他形态（都实测过）

- **重复副本**：同一解析器存在 3 份，只有一份被修；正确的实现带着解释注释躺在兄弟文件里，教训从未传播。⇒ 诊断"忘了处理 X"时，**先搜这段代码的所有副本**；修法是一份共享实现，不是 N 份同时打补丁。（`guard-blindspot-diagnosis` §1d）
- **副本"一致地错"**：两份逐字相同的 `extractImportMap` 都把 `a as c` 的本地名取错；合并时按**意图**写测试，测试立刻变红 —— bug 一直在，只是没人恰好在那处用别名。（`guard-blindspot-diagnosis` §1e-bis）
- **快路径藏坏回退**：闭包构建有 `cache.db` 快路径（正确）+ 即时回退（坏的）；缺陷只在无索引/跨根/新监听到的文件上发作 ⇒ 多年测试从未碰到。量化影响范围前**先问生产走哪条路径**。（`guard-blindspot-diagnosis` §1f.2）
- **静默降级会繁殖**：五个机制（权威答的是另一个问题 / 失败是静默的 / 局部最优 / 没有变更通知 / 不同问题看起来像一个）。⇒ **若一个 fallback 的失败模式是"少做一点但不出声"，它就不该存在**：要么响亮失败，要么把"少了多少"变成可读数字。（`guard-blindspot-diagnosis` §1g）
- **闸的输入路径被搬走**：门不报错，它**读到空**，于是要么空过、要么把整个世界报成变更（67 个工具全被报成"改名未清理"）。（`guard-blindspot-diagnosis` Pitfalls）
- **"我改了" ≠ "改在被门观测的范围里"**：篡改的字符串住在工具 **description** 里，而快照抓的是工具 **output** ⇒ 门照绿，出生证是假的。要靠"观察门因为正确的原因变红"来验证。（`guard-blindspot-diagnosis` Pitfalls）

### 3.5 索引层的同构：没发现 ≠ 是对的

- **绕过写闸直接改盘时 `stale_resolved` 仍是 0**（索引还没重同步、旧节点还在、旧引用"连得上"）；此时真正的谎言是 `not_fresh`：`find_references` 会把 LLM 指向**已不存在的旧名**。别把"没发现陈旧断言"读成"索引是对的"。（`dc-index-triage` 一致性）
- **召回边界也是"不撒谎"的一部分**：候选集被截断/收窄时必须如实上报（`candidateScan = {closureFiles, textAdded, textScanned, textBounded}`），否则"候选集不全"会被当成"没有别的引用"。（`dc-index-triage` 一致性）
- **自检类工具必须纯只读**：`index_integrity({refresh:false})` 若顺手刷新，它报告的是"修完之后"而非"调用前"的现状 —— 另一种撒谎。（`dc-index-triage` 写闸节）

## 4. 编译器能查就别写门

### 4.1 症状：用文本模拟语义

- 把代码里的东西**抄成字符串**再反解：登记表写 `producer: 'src/infrastructure/index/symbols.ts#syncFile'`，门再 `splitRef()` 切模块+符号、import 模块查导出表 ⇒ **这是在手工重新实现模块解析器**。（`gate-authoring` §5g）

### 4.2 替换表

| 你想查 | 手写门（文本） | 换成什么 | 出处 |
|---|---|---|---|
| 那个函数还在不在 | 反解 `'file#symbol'` 查导出表 | **值引用**：`import { syncFile }` 直接用 | `gate-authoring` §5g |
| 名字拼对没有 | 字面子串匹配 | **字面量联合类型** | 同上 |
| 该填的字段填了没 | 自己定"≥10 字"阈值 | **判别联合** `{kind:'x'; why:string} \| {kind:'y'; produce:Fn}` | 同上 |
| 枚举值合法 | `['a','b'].includes(v)` | **联合类型** | 同上 |
| 目录不许 import 某东西 | 读源码找 `from 'node:fs'` | **ESLint `no-restricted-imports`** | 同上 |
| 模块不许成环/越层 | 自己遍历 import 图 | **dependency-cruiser**（声明式） | 同上 |

- **实测（消融）**：把三类错注入 typed 表 ⇒ `tsc` 全抓且**带纠正提示**（`Did you mean 'source_files'?` / `Property 'why' is missing` / `Cannot find name '…RENAMED'`）；同一批错在旧"字符串 + 手写门"写法下一件都查不出。（`gate-authoring` §5g）
- 结果：那扇门 **647 行 → 15 项**，剩下的全是编译器真查不了的（数组 id 重复 / 图无环 / 跨字段语义一致性 / 运行期行为）。（`gate-authoring` §5g）

### 4.3 编译器列漏改清单，比 grep 准

- 删/改兜底后直接 `tsc --noEmit`：漏改的 import、类型不匹配会**一次报全**；实测 11 处改动 ⇒ 编译器精确报出 **11 处缺 import**，一处不多一处不少。（`remove-silent-fallbacks` §2⑤）
- **grep 列不出"我漏了什么"，编译器能。**（`remove-silent-fallbacks` §2⑤）

### 4.4 哪些真的查不了（别把有用的门一起删）

| 门 | 编译器能查吗 | 结论 | 出处 |
|---|---|---|---|
| 产者/位置存在、字段必填、枚举合法、类型相符 | ✅ | 删门，改类型/值引用 | `gate-authoring` §5g |
| 目录 import 限制、分层、循环 | ✅ 现成框架 | 删门，改 ESLint / dep-cruiser | 同上 |
| 文本重复（同一意图多份实现 / 旧品牌串残留） | ❌ | 保留（认清它是**债务温度计**，目标是清零） | 同上 |
| 图的无环 | ❌ | 保留 | 同上 |
| 运行期行为（不退化 / 方向 / 反饱和 / 双向自证） | ❌ | 保留（**这类才是门的主场**） | 同上 |

- ★ **文档里"手抄一份机器可读的表"= 自造一个必然腐烂的副本**：账本里手抄的 15 行工序表当天下午就过期（两行的"根"当天上午就修了）。（`gate-authoring` §5g）
- ★ 注意本仓现状：2026-10-05 起测试框架与全部门已整体移除（`dc-add-tool` §一/§五）。**"用哪个框架"要按当前裁定**，但"能由编译器/框架表达的，不要用手写门模拟"这条判据不变。

## 5. 声明要可证伪

### 5.1 把声明改写成 variation test

> **一条属性的真假，往往可以改成"把某个输入变一下，输出必须跟着变"。**（`gate-authoring` §5f）

- 实例：`owner ∈ {project, dataHome}` 听起来是声明，可改写成：
  - `owner='project'` ⇒ 用两个不同项目根调 resolver，两次结果**必须不同**，且各自**必须包含自己那个根**；
  - `owner='dataHome'` ⇒ 根来自环境量，跑不出两个根 ⇒ 退而校验**逐解析器白名单**，并**如实声明强度更弱**。（`gate-authoring` §5f）
- **这条判据真能抓 bug**：`cacheDir()` 不收 root、偷用 `process.cwd()` ⇒ 传两个不同根返回同一个值 ⇒ **门今天就能抓到昨天的 bug**。这是判断"判据够不够硬"的最好测试。（`gate-authoring` §5f）
- **三个要点**：
  1. 输入必须真的变，且变量必须是**参数**不是环境（env/cwd/包根跑不出两个值 ⇒ 那一半只能用白名单，**且必须标注它更弱**；不要为对称硬凑 = 假强度）。
  2. 加一条"**含自己那个根**"的断言，否则一个返回 `Date.now()` 的 resolver 也能通过。
  3. 首参不是那个变量的函数不能进这一类；抛错也算红，且报错要告诉作者"这份数据其实归别的根"。（`gate-authoring` §5f）
- **粒度必须与判据说的是什么对齐**：判据说"这个模块不许 import X" ⇒ 名单到模块；说"这个解析器的根是 dataHome" ⇒ 名单到 `file#symbol`；说"这个行为的最小充分特征" ⇒ 模式写到行为，不是那次实现的字面。（`gate-authoring` §5f）
  - 反例：dataHome 白名单做成模块级，而模块里同时住着两种根 ⇒ 整模块放行 ⇒ 注入照绿 = 假绿。（同上）
- **模式要对"行为的最小充分特征"写**：`import_cache_${feature}.db` 遇到 `import_cache_${f}.db`（换变量名）照绿；改成变量无关的前缀 `import_cache_${` 才拦得住。（`gate-authoring` §5f）

### 5.2 兜底声明：是默认值，还是换了题

- **三分类，不照"有没有 `??`"分**：
  - `baseDir ?? getDataHome()` = **默认值**（右边是同一件事的合法归属）⇒ 留，并在注释写明；
  - `input.source_root ?? input.project_dir` = **两来源一语义** ⇒ 留；
  - `dsl.source_root ?? process.cwd()` = **换题**（cwd 与被分析对象毫无关系）⇒ 删。（`remove-silent-fallbacks` §1）
- **`?? process.cwd()` 不是"退而求其次"，是"答错了还装作答对了"**：一个没有自己数据的对象会静默读到 cwd 那个对象的数据，不报错、结果看起来完全正常 ⇒ **静默的错误答案比报错坏一百倍**。（`remove-silent-fallbacks` §1）
- **换题类再分一次：抛 / skip / 4xx**：
  - 必须有该输入才能做 ⇒ **抛**（报错里写"这里故意不兜底到 X"）；
  - 可选工序 ⇒ **skip**（不做那件本来就可选的事）；
  - HTTP/工具入口 ⇒ **4xx + 说清缺什么**（不要 500 栈，也不要静默用错值）。（`remove-silent-fallbacks` §2③）
- **skip ≠ 兜底**：兜底=拿错的输入继续做本该做对的事；skip=不做本来就可选的事。自检：**这个 skip 会不会让主结果变错？** 会 ⇒ 必答项，必须抛。（`remove-silent-fallbacks` §2③）
- **用真注入验证声明**：往名单里塞一条坏条目 ⇒ 跑门 ⇒ 断言红 ⇒ 还原；**注入后回读文件确认落盘**（实测 `node -e` 正则被 CRLF 吃掉 ⇒ 注入没生效却不报错 ⇒ 看起来像判据失效，其实是证据先坏）。（`gate-authoring` §5b）

### 5.3 表述：把过宽的话改成可用的数字

- **"100%" / "全部" / "逐字相同"** → 一律要求给出**分布**（几个块、各占多少字符/行）。（`verify-delegated-work` §2）
- **"一定 / 不可能"** → 要求给出**因果**而不是**未观测**："没观察到" ≠ "不可能"。（`verify-delegated-work` §2）
- **"已修好"** → 要求给出**可证伪的验收信号**（例："下次跑批的 `diffStat` 必须非空"）。（`verify-delegated-work` §2）
- **修正后必须写回文档，并保留"原表述错在哪"** —— 否则下一个人会重新引入它。（`verify-delegated-work` §2）
- **证据分级**（引用时必须标）：
  - **直接读过**（能指出文件名与行）⇒ ✅ 可当结论；
  - **二手汇总** ⇒ ⚠️ 只能当线索，写明"二手"；
  - **推断** ⇒ ❌ 必须标"未验证"，并给出验证方法。（`oss-prior-art-first` §4）
  - 通用禁令：凡"它一定能/一定不能"，后面补一句"**我没核实的是 X，验证方法是 Y**"。（同上）
- **不许把预测/推断写成实测**。（`dc-drive-chain` §六）
- **不能从"面大全对"推断"列多了没事"** —— 样本小、题是我出的；必须写"未核实清单"（样本量 / 题面设计者 / 被试是子代理 / 置信度是否可信）。（`dc-face-bench` §四、§六）
- **共线时交叉表只能生成假设，不能当因果**；要定论必须做受控 A/B（同父、同题、只改一个变量）。（`prompt-cache-reuse-diagnosis` §5.3）
- **没有探针证据就不要说"推送成功"**；说"本地已就绪、差凭据推送"比说"已推送"诚实且更有用。（`git-repo-hygiene` §七）
- **"换代报 success ≠ 新代可用"**；`check:profile` 绿 ≠ 插件配置没问题（它只组装不实例化）。（`dsh-profile-integrity` §6）
- **写禁令时"否定 + 禁止"优于"说明 + 让它判断"**：硬规则式"那些不是可以直接调用的 tool…不要试"实测 0 次被拒；说明式 1 次；无约定 1–2 次。要写明失败后果（"会立刻失败并浪费一整轮"）。（`dsh-agent-preset-authoring` §四）

### 5.4 判据要有执行者，且执行者不能是自己人

- **"判据没有执行者 = 等于没有"**（`docs/DESIGN.md` P4 的提法）在本组 skill 里的对应物：门必须有退出码、必须被套件跑到、必须能变红（`gate-authoring` §1.7、`guard` §7b）。
- **独立核验要"不给结论"**：只给判据、不给答案，它才会主动反驳；先给结论就变成"请它背书"。（`verify-delegated-work` §0.5）
- **审"判断/口径"，不要拿它查事实**："它是纯计算""这两个是同一类"这类断言比"文件在哪"难反驳得多，也最容易错。（`verify-delegated-work` §0.5）
- **缺陷指控先证可达**：现象对但代码路径根本走不到 ⇒ 不值得修；报告里要写"现象属实，但也无人可达"，否则下一个人会去修不存在的问题（假红的生产方式）。（`verify-delegated-work` §5）

## 6. 一页速查（交付前问自己）

1. 我这条判据，**跑的是真证据还是源码文本**？（`gate-authoring` §0.1）
2. 坏输入被挡时，**挡在正确的级与检查项**上了吗？（§0.3）
3. **好输入会被放行**吗？（§0.3）
4. 我**撤掉修复**，这条断言会红吗？（§2）
5. 这条判据**历史上为正过几次**？0 次是不是说明它是死的？（`guard` §1b）
6. 我**只读了一次**异步落盘的证据吗？（`guard` 核心洞察）
7. 我的分类器是不是**一个桶装了 95%**？（`guard` §1d.1）
8. 我给**空输入/坏路径**喂过吗？它读出 100 分了吗？（`guard` §1d.4）
9. 夹具的写法和**生产语料**一致吗（扩展名、模块制式、路径风格）？（`guard` §1d.3）
10. 这份豁免/基线**谁在喂**？期望值是从哪来的？（`gate-authoring` §5b/§5c）
11. 这件事**编译器/框架**能不能查？能的话我为什么还在写门？（§5g）
12. 我写的这句话，**能被什么输入证伪**？答不出就是散文，别把它装成判据。（§5f + §0b）
