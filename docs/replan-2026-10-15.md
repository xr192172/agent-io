## 3. 三件主线（有顺序，各有判据）

### 主线 A · 单一入口（**先做**）
- **做什么**：就是本文档 —— 它 ≤ 20K 字符，且**必须宣布**其余文档的角色（见 §4 表）。
- **判据**：一个新会话**只读本文档 + 跑一条命令** ⇒ 能说出"下一步做什么、判据是什么"。
  ★ 这条判据**可当场测**（让一个子代理只读本文档，问它"下一步做什么"，对不上就是没写清）。
  ★★ **2026-10-15 用户修正（采纳）：卡片方案【作废】** —— 用户原话：*"我其实觉得这样可以好像更容易腐，
  因为这样的话其实是无端的增多了这个相同信息的文档，要不然你还是直接写一份规划文档，
  我们直接按照那份规划文档当 ToDo 用吧。这些文档直接将其归档，就是你把这些文档里面还没做的全都列出来，
  然后判断是否要那个，然后已经做的过期的就给它那个归档掉"*。
    · **我原方案错在哪**：**卡片 = "同一信息又住一份"** —— 原文改一个字，卡片就开始腐（本仓头号病根）。
      ★ 卡片**只在"它取代原文"时才成立**；我做的是"再加一层" ⇒ 必然双份记账 ⇒ 更容易腐。**用户判断正确。**
    · **改为**：**一份规划文档（本文档）= 唯一 TODO**；其余文档**归档**（不删，标"历史/证据"）；
      做法 = ① 把各文档里**还没做的全列出来** → ② 逐条**判定要不要做** → ③ **已做的/过期的直接归档**。
    · **抽取的产物落点**：`docs/_extract/*.extract.md`（**中间产物**，合成完即可删——它不是"又一份真相"）。
    · **判定规则**（合成时我逐条判，规则先定，别临场发挥）：
      已做（有读数）⇒ 归档 · 过期（说法与现状不符）⇒ 归档并注明"当时为何立" ·
      未做且有判据 ⇒ **进 TODO** · 未做但判据不明 ⇒ 标"**待补判据**"（**不许**直接当"要做"）。

### 主线 B · 判据收口（**索引一族**）
- **做什么**：观测 3 里那五条**是同一个病**（"索引是否可用 / 项目根在哪 / 路径怎么写"住多处）。
  收成一处权威，其余降级为**引用**（不是复制）。
- **判据**：同一问句的判据**副本数 0**；且各处读数**互相一致**（写成**一张证**：同一夹具上三处读同一个值）。
  ★ 这一族先做，因为**它是"掌握力"的物理基础** —— 索引不可信 ⇒ 所有上层判据都不可信。

### 主线 C · 账的复核机制（**防过期**）
- **做什么**：每条"现状 / 剩余"**必须带一条可复跑的复核命令**（如 `grep -c` / `node -e` / 一条证名）；
  没有复核命令的，标 `[未复核]`；复跑对不上的，标 `[stale]` 并当场改。
- **判据**：抽 10 条，**过期 ≤ 1**。★ 这条直接治观测 4 那类"差点重复实现 / 差点再犯一次"。

## 8. 2026-10-15 用户修正三：「一条条怼进 DSL」+ 我的核验与规程

用户原话：*"你就直接把这些文档全都往设计 DSL 里面怼，一条条怼过去，然后**有重复的就验证哪一个是对的**。
这样的话，因为**每一个节点它应该是有相关决策的唯一性的**吧。也可以把这些**过期的决策直接由后面仍存活的决策覆盖**掉。"*

### 8.1 ★ 核验结论：**你要的三件事，DSL 的语义里已经全有了**（有 `file:line`，不是听说）
| 你要的 | DSL 里已有的 |
|---|---|

| **过期由后来的覆盖** | `status?: 'active' \| 'superseded' \| 'draft'`（`geometry.ts:192-193`），逐字注释："**superseded=已被新版取代（历史版不删，进 `decision_history`）**" |

⇒ ★ **不需要新设计**，只需要**用它**。而"不是删、是标 superseded + 留史"这一条，正好也满足"原文是证据"。

### 8.2 规程（怼进 DSL 必须照这四条）
1. **唯一键 = 节点**：每条待办必须先**归到一个节点**（feature / 文件 / 域）；**归不上的不许怼**。
2. **去重分两类**（照 T109 已拍的口径）：**措辞抖动** ⇒ 合并成一条；**真分歧** ⇒ 留 `dissent`/`alternatives`，**不许取"最新"就完事**。
3. **标过期必须有读数**：`superseded` / `deprecated` 一律附一条**可复跑的复核命令**（今天已逮到 3 例"账比现实旧"⇒ 不许凭感觉标）。

## 9. 2026-10-15 用户修正四：「在 DSL 里加一块内置 todo」—— 我的判断（**方向对，但"加一块"要改成"加一格"**）

用户原话：*"那就在设计 DSL 里面再设计一块，或者说加一块它内置的 todo，这样的话我们目前的 todo 就是一个历史 todo，
那里面的 todo 就只留存活 todo。或者是说刚好相反，你觉得怎么样？"*

### 9.1 方向：**A（todo 的家搬到 DSL）成立；B（反过来）不成立**
**判据 = 家应该在有"判据能力"的那一侧**：
- md todo **没有任何判据能力**：今天量出 77 条里 **24 条给不出判据**；`[x]` 已勾 26 条与"真做完"之间**无判据**；
  且 **T236 的判据被它自己污染**（`grep -c 关键词 == 0`，而它把关键词写进了 todo.md）。
- DSL 侧有 `expectations`（**机器可判**，`geometry.ts` 的 `NodeDecision` 字段）+ `consistency_check` 对拍
  ⇒ **只有 DSL 侧能自动判"完成"**。
⇒ 所以 md todo 该降为**历史归档**（不删：它是证据），活 todo 住 DSL。

### 9.2 ★★ 但**"加一块"要改成"加一格"**
- **理由**：todo 与决策**不是两件事**，是同一件事的**两个状态轴** ——
  决策问"**是否仍生效**"（`status: active/superseded/draft`），任务问"**是否已做完**"。
- **加"一块"新的数据结构** = 又造一个与决策平行的体系 ⇒ **同一信息住两份**（正是用户否掉卡片方案的那条理由）。
- **改为**：在**既有决策卡上加一格"兑现状态"**（候选名 `delivery: 'pending' | 'done'`，或复用
  `expectations` 的判定结果）；★ 而 **todo 是一份投影**（`query decisions where delivery=pending`）——
  **视图不是住处**（与 §7"md 只是投影"完全一致，逻辑自洽）。

### 9.3 ★ 硬前提：**"完成"这一格现在不存在，且必须可判定**
- `status` 的枚举是 `active | superseded | draft` —— **里面没有"已完成"** ⇒ 这一格是**新增语义**。
- 而"完成"**不许靠人勾**：md 侧已经证明会腐（26 勾 vs 77 未勾，且"勾了"≠"做了"）。
- ⇒ 完成的判据**只许三档**：① `expectations` 全绿（**自动**）· ② 附一条**可复跑的读数**（半自动）·
  ③ 明确标 **"人工确认"**（诚实）。★ **不许第四种：默默勾上。**

### 9.4 我上一轮的卡口要**放宽**（但有未验完的一格）

## 10. 2026-10-15 三路独立评审（任务系统形状）—— **结论：不该新建，该复用；且我上一轮的两处错**

三份评审产物：`docs/_extract/quest-A-structure.md`（数据面）· `quest-B-done.md`（完成判定）· `quest-C-view.md`（视图/前置链）。

### 10.1 ★★ 我认的两处错
1. **`delivery: 'pending' | 'done'` 是自相矛盾的**（B 抓到）：只要是**可被 `edit_dsl` 赋值的字段**，
   就**可以被直接置成 done** ⇒ 与我自己写的"**不许默默勾上**"冲突。

   的形状、其余字段照写（`node_ops.ts:100,223`）。
2. **我提的"任务 = 独立对象"已经存在**（A/C 抓到）：`OverlayGoal{ id, title, status: 'active'|'done'|'parked'|'dropped' }`
   已经是"独立对象 + 含 done 的状态机"，**且已住在 `overlay.global` 且已可投影**。
   ⇒ 再新建 = **同一件事住两处 + 一个名字两个意思**（正是本项目头号病根）。

### 10.2 ★★★ 真正的病根被指出来了：**"这项活到哪了"有 ≥6 套表达**（A 的原话：再加就成第 6 条状态轴）

### 10.3 三条硬结论（可直接当施工依据）
1. **复用，不新建**：任务对象 = `OverlayGoal`；节点/文件级三态 = 既有 `Node.status` / `SemanticFile.status`

   ⇒ **"完成"里必有一块永不可判，全绿 ≠ 完成**。
