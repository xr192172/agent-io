## 一、四份稿子**独立收敛**到的四件事（★ 我只列四份都撞到的）

1. **不许新建面板 / 不许新增存储** —— A、C、D 各自独立得出同一结论：
   玩家眼前要的一切**都能从现有字段投影出来**（方向读 `meta.goals`、动作读 `query=pending`（直读 overlay）、对拍用 `diff_views`）。
   ★ 任何"看板/任务表/进度百分比"都是**第二住处** ⇒ 与"同一件事只住一处"直接冲突。
2. ★★ **最大风险不是"不做事"，是"自证"** —— B 的 C2/C8 与 D 的 attestation 滥用是同一条：
   `evidence` 的第三档（**显式人工确认**）允许 `by:'llm'` ⇒ **玩家可以自己给自己签"我完成了"**；
   而第二档（可复跑读数）**只存不跑** ⇒ 也可以造假。
3. ★★★ **内容生产的真瓶颈已被实测坐实（只有 C 去跑了数据）**：
   `expectations` **只有 6 种 kind**（`file-exists` / `symbol-exists` / `signature-matches` / `edge-exists` /
   `edge-absent` / `call-exists`）⇒ **没有一条能表达"这段该重写"** ⇒ ★ **关卡有名字、没内容**。
   实测旁证：`expected_apis` 在 `self`（479 文件）/`run82`（200 文件）上**总条数 = 0**；`run82` 的 72 张卡只有
   **1 条 `expectations`、0 条 `lifecycle`**。
4. **闸的"完备性"没有证盯着** —— B 最不放心的 R3（闸靠**逐工具手挂**，`edit_code` 是事后补的）与 D 的绕过清单一致：
   `rename_files` / `symbol_move` 走自己的快照路径、**未接闸** ⇒ **拦的是礼貌玩家，不是所有写入**。

## 二、我的裁决（合成，不是拼贴）

### 2.1 规则清单（采纳 B 的 R1–R6，逐条配判据）
| # | 规则 | 判据 |
|---|---|---|
| R1 | **真相单源** | 每类事实的**写入点 = 1**（人工口径清单，非单条 grep） |
| R2 | **单向投影** | 权威**不读**投影（依赖方向单向） |
| R3 | **谁能写** | 每个写工具**都过闸**（现状：**缺证**，见 2.4） |
| R4 | **怎么算完成** | `progress='done'` ⇒ **必须带 `evidence`**（三档）；**无 evidence ⇒ 拒** |
| R5 | **前置解锁** | `requires` 未满足 ⇒ **拒落盘**；★ **没标 `requires` 的边一律不拦**（防误伤） |
| R6 | **判据唯一** | 同一问句的**判据副本数 = 0**；且**判据不许查含它自身的文件**（防自污染） |

### 2.2 冲突裁决顺序（采纳 B，一句话）
> **`overlay.progress` 赢一切** —— base 的 `Node.status` 是**脏投影**（只用来报偏差、等对账）；`dsl.status` 是不落库的派生值。

### 2.3 形状（采纳 A + C 的一致结论）
- **任务的排布 = "可做集合"**（`pending` 候选 ∩ 前置放行），**不按节点**（import 依赖 ≠ 任务前置）、**不按 feature**（200 文件一屏）。
- ★ **任务的载体挂 `scope`（块名）一处**（C 的主张）：它是 `buildDiffBlocks` 的**纯函数视图**、**不落新存储**；
  块名必含 `:`、节点 id 实测不含 `:` ⇒ **天然不撞**，重跑逐字相同 ⇒ **不会造重复**。
- **三态够用**：解锁 = `requires` + 拒绝回执 · 奖励 = `progress_evidence` 三档 · 成就 = `goal.status=done`。
  ★ **不发明第四态**（`blocked` 已由 `requires` 表达）。

### 2.4 ★★ 我排的优先级（按"四份稿子共同指出的最大风险"排，不按工作量）
| 序 | 做什么 | 为什么排这里 | 判据 |
|---|---|---|---|
| **1** | ★★★ **给 `expectations` 补"该重写"这一类 kind** | 它是**内容生产的总闸**：不补，所有关卡**有名字没内容**（C 实测三条生成路径产量全 0） | 构造一个"该重写"的期望 ⇒ 能红能绿 |
| **2** | **`attestation` 加固**（D 的四条：**强制带 `source_node_id`** + 每 feature 每会话 ≤3 条 + 与 `expectations` **互斥** + `at` 由系统时钟填且相邻 ≥30s） | 它是**自证漏洞**的正面（B 的 C2 + D 的同一条） | 构造 `by:'llm'` 自签 ⇒ **受限/被拒** |
| **3** | **"每个写工具都过闸"补一条证** | B 最不放心的 R3 + D 的绕过清单（`rename_files`/`symbol_move` 未接） | 一条证：**列出所有写工具，逐个断言过闸**（漏一个就红） |
| **4** | 把上面三条的结论**搬进 DSL**（`edit_dsl` 写决策卡） | 按本项目规矩：**设计的正式住处是 DSL**，本文件只是草稿 | `get_dsl` 能读出这些决策 |

### 2.5 四份稿子**共同主张砍掉**的（一致度最高的一栏）
看板/Kanban（第二住处）· 第四进度态（`requires` 已表达）· 完成度百分比与积分/streak（无判据 + 要新存储）·
机器自动排程（**优先级函数写不出来 ⇒ 判不了 ⇒ 不做**）· 从 import 边自动推 `requires`（会把全仓锁死）·
按 `arch_layer` 分关卡（实测 `core` 占 381/479 = 79.5%，分了等于没分）。
