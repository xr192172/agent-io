# DSL 该留什么（"优化 DSL"的可执行清单）· 2026-10-16

> 依据：用户的三层结构 —— **DSL（微缩/重要）→ DB（理解关系）→ 源码（定位）**；
> 以及实测（见 `docs/replan-log-2026-10-15.md` §63）：**事实类 DB 全有且更新鲜；意图类 + 规则派生类 DB 一列都没有。**

## 一、三层分工（一句话）

| 层 | 装什么 | 谁产生 | 新鲜度要求 |
|---|---|---|---|
| ★ **DSL** | **微缩的、重要的、DB 没有的** | 意图 = 人/LLM；层次/布局 = 规则算 | **不装事实 ⇒ 永不陈旧** |
| **DB** | **事实**（files 531 / nodes 8446 / edges 13283 / imports / unresolved_refs） | 扫描器（有保鲜：逐文件 mtime+size） | **每次调用前自证** |
| **源码** | 真相本身 | 人 / agent | — |

## 二、★ DSL 该**留**的字段（DB 里没有）

| 字段 | 为什么留 |
|---|---|
| `nodes[].decision`（`summary`/`expectations`/`progress`） | ★ **意图**，DB 无此类列；**不可重算** |
| `nodes[].status`（done / in_progress / …） | ★ 意图（进度） |
| `semantic.files[].responsibility` | ★ 一句话职责（派生句，**目前"现渲染·不落盘"，可保留该口径**） |
| `nodes[].arch_layer` + `layers[]` | ★ **规则派生**（`layer_detect.ts` 路径匹配）—— ★ 见 §四的警告 |
| `geometry.nodes[].x/y/w/h` + `geometry.width/height` | ★ **布局**（给人/LLM 看形状）—— ★ 见 §五的硬风险 |
| `annotations[]` | ★ 人写的标注 |
| 顶层 `id/type/feature/version/title/source_root/status` | 身份 |
| `_dsl_rev`（乐观锁）+ `_sync`（**★ 必须加"来源与代"**） | 权威 + **新鲜度自证**（§六） |

## 三、★ DSL 该**去掉**的（DB 能现算 ⇒ 复制必然陈旧）

| 字段 | 替代 |
|---|---|
| `semantic.files[].symbols[]`（583 个） | ★ **查 DB `nodes`（8446，且更新鲜）** |
| `semantic.files[].lines` / `node_count` | 查 DB `files` |
| `geometry.edges[]`（imports/contains 1074 条） | ★ **查 DB `edges`（import 1193 / call 7390 / type_ref 4700）** |
| 任何"扫描事实的逐条副本" | 一律改为**按需查询** |

⇒ ★ **判据（能判真假）**：**DSL 文件里凡是"删了能靠 DB 重建"的字段，都是复制**；
操作化：**把 DSL 里每个字段问一句"DB 能不能现算"** —— 能 ⇒ 删；不能 ⇒ 留。

## 三'、★★ 更正（2026-10-16 实测后，覆盖原 §三 的粗判）
★ 原 §三 把 `geometry.edges[]` / `symbols[]` 一律当"事实副本" ⇒ **实测发现三处错**：
1. ★★ **`geometry.edges` 与 `symbols[].decision` 不只是事实，还是「意图载体」**（手绘边住 `geometry.edges`：`derive_chain.ts:755`/`edge_ops.ts:54`；
   `Symbol.decision` 在 `diff_views.ts:933` 被读）⇒ **不能按"事实副本"摘**；
2. ★ **`node_count` 是空目标**（类型与数据里都不存在）⇒ **从清单移除**；
3. ★★ **`contains` 边在 DB 里没有对应**（DB 只有 call/import/type_ref）⇒ "查 DB edges 替代"对**部分边**不成立（`contains` 要**由路径重导**）。
★ **正确的做法顺序**（实测得出）：
**(a)** 先补 `_sync.scanRev/age`（**已完成**，见流水账 §66.3）→ **(b)** 让**读取侧**改走 DB（建 live 视图的"DB 现渲染"通路）
→ **(c)** 才摘字段（★ 且**先修 `t341`**：它的悬空边探针直写 `geometry.edges`，摘边后会**失效**）。
★ **判据**：**(c) 之前，"删掉 `live` 文件仍能给出同一份实际图"（判据①）无法成立** —— 实测：删 live ⇒ `getDSLByView(vm=live)` = `null`。
## 四、★ 一个必须一起处理的发现：`arch_layer` 是"路径字符串匹配"

`layer_detect.ts:128-141`：相对路径按 `/` 切段、去扩展名转小写、与 patterns **精确串等**，
**全不命中 → `'core'`** ⇒ ★★ **`core 381` 这个数字是"没匹配上任何层"的结果，不是"核心模块多"**。
⇒ ★ **留 `arch_layer` 可以，但必须知道它是什么**；★ **提升它的唯一方式是换判据**（用 DB 的 `type_ref`/`call` 边做真架构分析）—— **那是另一件事，别混进"优化 DSL"**。

## 五、★ 硬风险：布局能不能"字节稳定"（**决定这条路走不走得通**）

"事实改成按需渲染"要求**渲染结果可复现**。布局的风险点：
- `layoutGroup` 排序键含 **`a.id.localeCompare(b.id)`（locale 相关）**；
- 布局是**"输入文件集"的整体函数** ⇒ 文件增删会**整体重排**。

⇒ **判据（先验这条，成本最低、决定成败）**：
同一输入、同一源，跑**两次** `import_project`，比较
`sha256(JSON.stringify(nodes.map(n => [n.id, n.x, n.y, n.width, n.height])))` 是否**相等**。
- **相等** ⇒ 可以走"按需渲染"；
- **不等** ⇒ 先修布局（把 `localeCompare` 换成语义无关的稳定键）**再谈**，否则每次渲染坐标都变 ⇒ **diff 变噪声**。

## 六、★ `_sync` 必须补"代"（否则"用 DSL 无法自证新旧"）

现状：`_sync` 只有 `saved_at` ⇒ ★ **实测"用 DSL 时无法自证新旧"**（本日靠人工对比两份文件才发现 `live` 落后 14.25h）。
⇒ 补：**`scanRev`（DB 的 `max(files.indexed_at)` 或等价版本号）+ `age`** ⇒
★ **让任何读 DSL 的人/工具能一眼判断"我看到的是哪一代"**；★ 并规定：**age 超阈值 ⇒ 拒绝下结论**（不是"提示"）。

## 七、★★ 接下来三步（回答"我现在要怎么做"）

| 步 | 做什么 | 判据 |
|---|---|---|
| **第 1 步** | ★ **验"布局字节稳定"**（§五） | 两跑 hash **相等** ⇒ 放行；不等 ⇒ 先修布局 |
| **第 2 步** | ★ **按 §三 把 DSL 里"事实副本"字段摘掉**（改成按需查 DB），并给 `_sync` 补 `scanRev`/`age`（§六） | ① DSL 文件**显著变小**；② **删掉 `live` 文件后，`get_dsl(vm=live)` 仍能给出同一份"实际图"**（= 它不再依赖冻结副本）；③ 既有证不红 |
| **第 3 步** | ★★ **回到"对拍"**：`设计（人写的图）` vs `实际（从 DB 现渲染的图）` | 四类判定语义不变（同 id / 要实现 / 未纳入设计 / 认亲）；★ **且 age 是新的**（不再对"14 小时前的实际"） |

★ **为什么第 1 步必须先做**：第 2 步的成败**完全押在"渲染可复现"**上；布局抖一格，第 2 步就是"把确定性换成噪声"。
★ **第 3 步之后**，`live/` 这份**冻结文件**才可以谈"退役"（它退成"一次渲染的缓存"，而不是"权威的一方"）。
