## 1. 这个项目在做什么（最小必要）

一个**代码库的设计册 ↔ 实际册**双册系统。仓库：`D:/agentio/dev/agent-io`（TypeScript）。

| 册 | 住在哪 | 是什么 |
|---|---|---|
| **设计册**（design DSL） | `.agent-io/design/*.dsl.json`（3 个 feature） | 描述代码**应该**是什么：文件、符号、API 契约、依赖、判据、决策卡、目标 |
| **实际册**（live） | `.agent-io/cache.db`（25 张表） | 描述代码**现在**是什么：9186 个符号、16866 条边、import、签名 |

**目标闭环**（用户设想，已立为规则 0.29）：

```
实际册 →①派生→ 设计册 →②人编辑→ ③展开成画布 →④坍缩集
      →⑤按设计册改源码→ ⑥重算实际册 A′ →⑦对拍 A′ == D？
           一致 ⇒ 消解设计 + 把 A′ 的细节灌进空槽位
```

**核心用途**：让"改代码"变成"改设计册，再由设计册驱动源码" —— 这样 LLM 的改动可被机械校验，不依赖 LLM 可靠。

## 3. 已裁定的语义（**不要重新论证，直接当前提**）

这 8 条是用户已经拍过板的，你在此基础上往前推，不要回头质疑：

| # | 已裁定 | 为什么（一句话，供你理解，不必复述） |
|---|---|---|
| 1 | **派生只填空值，绝不覆盖非空值** | 否则"期望侧=实现侧"⇒ 对拍恒真（oracle problem）。`existing.length > 0` ⇒ 整字段跳过 |
| 2 | **派生条目必须带 provenance**（`notes: from:cache.db@<scanRev>`） | 让"派生基线"与"人写契约"可 grep 区分 |
| 3 | **`drift` 的 `clean` 是 baseline-freeze 语义，不是正确性证明** | 冻结时刻两侧同源，clean 是构造出来的；价值在"此后代码一改就显形" |
| 4 | **对拍 = round-trip 验证 `A′ == D`，结论是布尔值**，不是"差异条数" | 没有中间态：不通过就不许消解 |
| 5 | **空槽位是兜底不是设计**：只有"实况里没有、也无从派生"的字段才留空，**且必须声明** | 结构层字段空 ⇒ 缺陷；未声明而空 ⇒ 缺陷 |
| 6 | **消解 ≠ 删除** | 消解是"标记 + 灌入细节"，删除是抹掉 |
| 7 | **核销 = `plan_exit_check` + `judge` + `complete(evidence)` + 画布消解**（四件套已存在，但**没串成一条链**：消解无自动触发、`plan_exit_check` 只覆盖画布内符号） | |
| 8 | **设计册能重算的是：文件结构 + 签名骨架 + import 关系；不能重算函数体逻辑** | 设计册从不存 body |

**另一条重要的边界（今天刚踩）**：`expected_apis` 只收 `function`/`method`/`const 函数形态`；
`type`/`interface`/`class`/`const 数据常量` 共 4913 个符号**被排除**，因为 `cache.db` 里它们的签名是退化的（`typeD() `）。
