## 0. 目标口径与前置依赖

### 0.1 目标口径（终局目标已于 2026-11-23 冻结，见 §0.4）



* **终局目标**：不追求「证明永不漏选」（任意代码不可判定）；追求 \*\*「开发关键路径上不再出现全量 + 没有静默的漏网之鱼」\*\*。全量退场 = 退出本地收口门，转为 CI / 云端 / 空闲期抽样校准，**不是物理消失**。

* **建成后状态**：本地日常收口从「全量必跑」退到「增量静态证明实时 + 周期 reference run 异步校准」；消除用户感知的全量阻塞。

* **保留的全量面**：CI/PR 全量观察期保留；发布前、公共底座变更、兜底回落、周期全量仍跑全量；重量级对照在 CI / 云端，不占开发机（§0.3）。

* **对外口径**：覆盖证明建成后**不宣称「已不会漂移 / 永不漏选」**；未判定 / 未覆盖 / 盲区读数始终带分母显形。

* **保守下界不让步**：选材目标是「宁多不漏的下界」，不做激进剪枝；确定性规则 + fail-closed，最接近 Develocity Conservative 档（简报 §1.7）。

> 项；调度形态（分层 / 事件触发 + 空闲窗 / 隔离强制 / 资源分层 / 实时演算边界）不再留白。阈值类起步值已于 2026-11-24 冻结，见 §5。



1. **分层**：静态覆盖证明（选材 /holes/ 边计算）是廉价图计算，随 `verify:changed` 实时演算、实时把关；经验校准（reference run / 消融对照）是昂贵实跑，异步执行，不与开发回路同步。

2. **不做常驻后台服务持续跑全量**。事件触发 + 空闲窗口：触发条件 = WIDEN / 选材器 /mapper/ 边 schema 变更、holes>0、unknown 边新增、每 N 次收口提交、夜间空闲窗。无触发不跑。

3. **隔离强制**：reference run 必须在干净快照 / 独立 worktree 上跑，不得在活工作树跑（tasks.db/cache.db 本地态 + 刚修好的跨文件污染会互扰）；结果作为证据入 ledger，发现漏选 → 选材 fail-closed 扩宽直至修复。

4. **资源权衡**：本机只跑轻量抽样消融，jobs 上限 + 低优先级 + 可被前台开发验证抢占 / 取消；重量级全量对照放 CI / 云端观察期，不占开发机。前台开发回路永远优先。

5. **实时演算边界**：实时的是「证明没漏选」的图计算与 holes 闸，不是「实时重跑全量验证」（后者重新制造用户正要消灭的阻塞）。

### 0.4 覆盖证明终局边界（2026-11-23 Main 补充裁决，逐字纳入，已冻结）



1. **目标表述修正**：不追求「证明永不漏选」（任意代码不可判定），追求「开发关键路径上不再出现全量 + 没有静默的漏网之鱼」。全量退场 = 退出本地收口门，转为 CI / 云端 / 空闲期抽样校准，不是物理消失。

2. **核心不变量**：可判定依赖缺口清零；不可判定部分诚实标 unknown，走登记制或 fail-closed 扩宽，绝不允许静默漏。漏选必须暴露为登记债务 / 扩宽事件。

3. **四条解法路线纳入分批**：封闭化 / 声明输入（远期协议税）、unknown 登记制（动态导入 / 反射显式登记边）、测试独立化（密封状态消污染边，延续每文件数据根）、运行时覆盖反馈补经验边（没跑过的新路径仍 unknown 仍保守）。

4. **精度 - 可靠权衡明示**：对 unknown 保守扩宽会趋近全集，这是特性不是缺陷；企划必须写清「扩宽触发条件与收敛路径（登记 / 封闭化）」，避免用户再感知增量被拉成全量。

5. **组织顺序**：M1–M10 裁决表与 G1–G10 闭合企划按此边界组织 —— 先消可判定缺口（G 系），再建登记制与隔离，经验校准异步化，最后裁全量退场。

### 0.5 核心不变量（已冻结，施工与验收不得突破）



* **可判定缺口清零**：G1–G10 静态可判定缺口逐条闭合（边型接入、id 统一、键面扩面、清单对账、since 腿、新鲜度可信、归因修复、台账就位）。

* **不可判定诚实 unknown**：不可静态判定的部分（动态导入 / 反射 / 生成物 / 未跑过路径）标 unknown，走登记制或 fail-closed 扩宽；**判不了 ≠ 通过**（共识 §1.8）。

* **漏选必暴露**：任何漏选必须显形为登记债务条目或扩宽事件，进台账 /ledger；**绝不允许静默漏**—— 不得出现「图上判了无影响、实际漏选且无记录」的状态。

### 0.7 扩宽触发条件与收敛路径（已冻结，防增量被拉成全量）

**触发条件（任一命中即 fail-closed 扩宽，不静默收窄）**：



* unknown 边新增（新出现不可静态判定的动态 / 反射 / 生成节点）；

* holes > 0（周期对照发现增量漏选）；

* 漏选事件（全量抓到而增量未选到的真实红）；

* 登记债务到期（已登记未闭合的 unknown 条目超期未处置）。

**收敛路径（把扩宽拉回增量）**：



1. 登记制显式边：不可判定点先登记入册、纳入选材，消除「无记录漏网」；

2. 封闭化声明输入：远期将登记点转为显式协议 / 声明，静态可判定后退出保守扩宽；

3. 经验边补充：运行期覆盖反馈（M5 缓议）补到实测触达边，降低 unknown 面。

**权衡明示**：对 unknown 保守扩宽会趋近全集，**这是特性不是缺陷**（防静默漏优先于裁剪率）；收敛路径（登记 → 封闭化 → 经验边）负责把增量逐步拉回，避免用户在关键路径上再感知增量被拉成全量。扩宽事件与收敛进度均进台账，带分母显形。

## 1. 三路共识基础（交叉反驳后一致成立，无需裁决，直接吸收）



1. **CI 全量观察期不可退**：退场前提未满足前，push/PR 全量 `verify` + `judge-all` + 测试门全量保留；本地 `--changed` 只作内环反馈通道，读数必带分母与未覆盖数，不读作全绿。

2. **现有 fail-closed 牙齿真实有效，但只闭合「不可用 / 崩溃」类**：DB 打不开、impact 失败、缓存坏缺、git 读不到、上次非 pass、推不出观察面 ⇒ 全量 / 不继承；「边存在但部分 / 错误」（动态导入 / 反射缺边）**不触发**兜底。

3. **holes=0 是退场必要非充分条件**：消融对照基准 `fullVerdicts` 只看见全量触达的红（`incsel_ablation.ts:55-59`）；盲区类全量也未触达 ⇒ holes 恒 0 证明不了盲区闭合。须并列：unknown 守卫锚点登记 + unknown 占比达标 + undetermined 占比不超阈 + 边型完备性对账。

4. **缓存类比限单树 fail-closed 跳过，撤回跨机复用**：`.agent-io/*` gitignored 单机派生态，Bazel/Nx 团队共享缓存语义无载体。

5. **突变旁证不得背书测试套件充分性 / 自证包面完整性**：本仓 `mutate` 是判据 - 突变对粒度（非 PIT 套件分数）；D7 病史证突变错对象假绿；包面完整性以行为级 E2E 夹具为准。

6. **flaky 不设隔离队列**：flaky = 隔离 / 干扰缺陷须修；并行红串行绿保留红、不洗绿。

7. **保守下界取向不让步**：无历史观测库、无概率模型，Fast / 激进剪枝不适用。

8. **证据纪律：判不了 ≠ 通过**：unsupported/error/skip 不冒充 pass/killed；外部「跳过 / 未覆盖 / 等价突变」读数不得映射成仓内绿 verdict。

## 7. 硬约束（三路共识，施工不得突破）



1. **保守下界不让步**：不确定即保守纳入 / 回落全量，不做激进剪枝。

2. **判不了 ≠ 通过**：unjudgeable → unsupported，非 pass；unsupported/error/skip 不冒充 pass/killed；读不到 ≠ 没改动、找不到 ≠ 没影响。

3. **缓存限单树 fail-closed**：不跨会话 / 跨机复用；键任一读不到 ⇒ 不跳；坏缓存自愈为空属保守方向。

4. **突变不背书包面**：mutate 读数仅判据强度样本，不背书测试套件充分性或自证包面完整性。

5. **flaky 修不隔离**：干扰类判缺陷必修，不设隔离队列洗绿。

6. **证据留痕带分母**：内环读数必带验了 N / 未覆盖 U / 继承 / 未判定；未覆盖 ≠ 没影响。

### 10.2 隔离清单契约（新增）

**目的**：把「半径外全局红」从批收口门里显式剥出来，既不混成本批失败，也不允许静默豁免；清单是漏点显形与归因留痕的唯一住处。

**条目契约**：



| 字段                | 语义                                                                  |
| ----------------- | ------------------------------------------------------------------- |
| `gate`            | 全局门标识（门 7/8/10/11-global/12/15-global / 跨册计数钉）                      |
| `status`          | 不绿状态读数（红 /unsupported/ 缺失；读数带分母，§7-6）                               |

**生命周期**：



1. 批收口时枚举全局门；半径外不绿 ⇒ 落清单；半径内不绿 ⇒ 回批内门必修。

3. 异步全量 / 周期门复跑后回填条目状态；转绿关闭，仍红延续并更新 `next_full_run`。

4. 条目 `in_blast_radius` 判定翻转（新改动波及该门）⇒ 立即转批内门。

**边界**：隔离清单不是豁免凭证 —— 它只把既有红与本批改动解耦；兜底复跑义务与漏选暴露义务不变（§0.5、§0.7）。清单缺失，或条目无主 / 无下次复跑时点 ⇒ fail-closed，按半径内处理。

### 10.3 M3′・选点终局原则（目标节；Main 2026-11-24）

> **时效标注**
>
> ：本节为终局目标原则。
>
> **过渡期 M2′ 收口分层不变；当前 G-1 按 M2′ 收口不受本节影响。**
>
>  合龙条件（见下）满足前，现行 blast-radius 选点与兜底全量继续有效。

**① 原理：assume-guarantee / 模块化验证**

模块契约满足 ⇒ 不影响外部，**当且仅当**：



1. 契约完整覆盖所有对外可观测面：返回值 + 共享权威副作用 + 性能 / 资源 + 错误模式 + 并发 / 顺序；

2. 契约 / 依赖图无洞。

O1 为前提①的反例：返回值契约绿，但共享注册表副作用坏 —— 契约面未覆盖权威副作用，模块化保证不成立。

**② 终局选点口径**

爆炸半径 = **契约边界**（非传递闭包）。模块契约完整且被检查 ⇒ 改内部只跑其契约测试；下游传递测试冗余可丢。

**③ 分级放松规则**



| 模块契约状态        | 选点口径                           |
| ------------- | ------------------------------ |
| 契约完整          | 契约边界选点（终局口径）                   |
| 契约不完整         | blast-radius 过近似（现行口径）         |
| unknown / 不可判 | widen / fail-closed（§0.7、§7-2） |

新增 `contract_coverage` 维度（与 L8 unknown 占比护栏对偶）：逐模块补全契约面，逐模块收缩选点半径。

**④ 合龙条件**

覆盖证明 G-1/G-2 补边（消 16.7% test→src 直连盲区，§6）+ P1 效果边界 / RESP-CONTRACT / 意图编译器补全契约。两线合龙后，「只测契约」取代 blast-radius / 全量选点。
