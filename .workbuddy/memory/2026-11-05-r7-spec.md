## 二、4 条 lint 守卫的定稿数组（可直接粘）

  },
  { // #3
    file: 'AGENTS.md',

  },
  { // #5
    file: 'docs/RETIRED.md',
    mustHave: ['| 日期 | 退役对象 | 性质 |', '## 回炉登记'],
    columns: { headerStartsWith: '| 日期 |', expect: 6 },

★ **需要两个兄弟字段**（主控已批，各 1 行声明、非新机制）：
`minCount: [{pattern, atLeast}]` 与 `columns: {headerStartsWith, expect}`。
**理由**：只用纯 `mustHave: string[]` ⇒ #2 的「≥20 节」装不下（删到 19 节仍绿 ⇒ 按 0.25② **不算检测点**）、
#5 的「每行 6 列」装不下（必须挂账）。

★ **#5 的列数要用 md 表格解析** ⇒ 0.18④：必须是**一个**专用模块（认转义 `(?<!\\)\|`、按行自身闭合判边界、拒多行内容），
**不许临时 split/正则**。今天仓里**没有**渲染/解析器（`lint-prose-as-structure` 只读）⇒ 并入 `gen_dsl_schema.mjs` 那趟一并造，
并在注释里声明"唯一实现"。

## 三、写入时拒绝（上闸）的规格

- **落点**：`src/domain/expectation_kinds.ts#validateExpectation`，插在 `:388`（fields 循环 + `requiresWhyToMention` 之后）与 `atLeastOneOf` 之前。
- **主体 path 用现成的 `pathsOf`**（`:286`），**不新增 `declaredPathsOf`** —— 它的语义就是"这条判据牵动到的全部路径"。
  - 扩法：`KindSpec` 加**声明位** `declaredPathFields?: readonly string[]`（点号路径）；`run` 声明 `['input.file']`。
  - ★ **`run.fields += {name:'input.file'}` 是假声明**（校验循环取 `o['input.file']` ⇒ 永远 undefined ⇒ continue
    ⇒ 登记了却不校验 = 0.9.4 假绿）⇒ **不许**。
  - ★ **`subjectPathOf` 一律不动**（`run` 返回 `''` 是诚实的：run 能读任意文件，没有唯一主体）。
    实测：3 条 run 判据的 `subjectPathOf===''` 但 `input.file` 是 md ⇒ **闸只有走 `pathsOf` 才看得见这 3 条（3/8）**。
  - `edge-exists`/`edge-absent` 的 `from`/`to` 是**节点 id 不是路径** ⇒ 闸不参与，判据用 `KIND_SPECS[kind].axis === 'edge'`，**不用 kind 字面量**。
- **边界**：只按 `extname().toLowerCase()==='.md'` **精确**判，不扩 `.mdx` / `.markdown`（零例 ⇒ 不提前长成规则）。
- **验收**：`awk '/function validateExpectation/,/^}/' src/domain/expectation_kinds.ts | grep -c "kind ==="` **必须 = 0**。
- **双向用例**（载体 = `behavior-cases` on `validateExpectation`，该文件零 import ⇒ E-CRIT-006 不拒）：
  - **异义必不命中（拒）**：`source-has path=AGENTS.md` · `run input.file=docs/x.md` · `symbol-exists path=docs/A.MD` · `path=docs\\x.md`
  - **同义必命中（不拒，防误伤）**：`path=src/x.ts` · `path=scripts/probe-gate-cov.mjs` · `edge-exists from=n1 to=n2` · `runtime events=…jsonl` · `path=docs/x.json`
- **迁移实测**：615/615 rejected=0，Δ=0（现存 45 条 run 判据零影响）。

## 五、docs 4 节点：**节点留、判据移走**（不是幽灵）

`semantic.files` = **机器可派生**的清单（`import_project` 扫盘；`include_docs` 默认 false）；
`geometry.nodes` = **设计侧声明**。只在 geometry、无 semantic.files ⇒ 派生不到 ⇒ 4 个文件 **Test-Path 全 True**

检测点：**「`path` 以 `.md` 结尾的节点，其 `decision.expectations` 必须为空」**（= 闸的存量侧读数，同源）。

## 六、"docs 不归册管"今天**哪里都没表达 = 沉默，不是声明**

三处都不算：① `agent-io` / `agent-io-toolface` **无 `excluded` 字段**；② `include_docs=false` 只影响**采集**；
③ `watch_project.ts#shouldSyncRel` 对 `.md` 返 false 是**索引侧**口径。

⇒ 补册级 `excluded`（形态照 task-system-plan）：
`{path:'docs/', reason:'文档不在册管辖内：不可机器派生（include_docs=false）、无符号/无 import；文档守卫走 lint 的 DOC_STRUCTURE_GUARDS，不占判据位'}`

★ **顺序**：先处置 8 条 → 再上闸 → **最后**声明 excluded。
理由：`isExcludedPath` 会让这 8 条从"未覆盖"读数里**消失**，先声明就再也看不见它们曾存在（0.12）；
且闸治**入口**、excluded 治**分母**，excluded 不会阻止明天有人再写一条 md 判据。

## 七、三种"主体/宿主错位"形态（一起治，已写进 AGENTS 0.2）

1. **宿主是幽灵节点** · 2. **id 与 path 不同源** · 3. **红了两侧都不认领（orphan）**
共同根因：**「主体」与「宿主」是两个自由字段，没有任何一致性检查**
⇒ 治本：把 `task_machine#classifyRed` 的分类器**升格为门读数**（唯一实现已在，不重写）
