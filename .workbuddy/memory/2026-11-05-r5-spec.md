## 二、★ 总准入表 A–E 的实测事实（判据求值器自己的代码，换前必读）

```
A 表达力
  · `symbol-exists` = `expectations.ts:284 #judgeSymbolOrSignature`：**现读现解析**
    （`fs.readFileSync` + `parseFileSymbols`，**不读 cache.db**）；命中 `s.name===symbol || s.qualified_name===symbol`；
    **不按 kind 过滤、不要求 export**（L318 注释 T258 起）⇒ 局部变量 / 对象字段 / 接口字段**表达不了**；const/interface/method 都行
  · `signature-matches` = 同函数尾段，比 `hit.signature`，`normSignature` 压空白
    ★ **const 的 signature 是首行原文** ⇒ 对数组类 const **不稳**（实测 `LANE_META` 被截）⇒ 别用
B 载体边界
  · `behavior-cases`：E-CRIT-006 ⇒ 目标文件有**裸三方值 import** 时**写判据那一刻就拒**（`node:` 内置放行）；
    只能比**返回值**（`sameBehaviorRet`），**观测不到入参被不被改**
  · `run`：求值域仅 `input/root/validateDSL/fs/path`；写入时拒 `Date|Math.random|performance|readdir|process|require|import(`；
    表达式**抛错 ⇒ unsupported（不是 fail）**
  · ★★ `call-exists`：`expectations.ts:541` —— **只读 cache.db 调用边**；caller id = `path#symbol`；
    **只比 `shortName(callee)===target`** ⇒ **方法/成员调用会退化成短名**（`declaredNew.has(` → `has`）**太泛不可用**；
    且 `const DESIGN_TOOLS = {…}` 这类大对象里的箭头函数 **caller 归属不可靠**
    ⇒ **`design/index.ts` 与 `meta/index.ts` 的判据一律不换 call-exists**
  · `edge-*`：`expectations.ts:249 #depFactsIncomplete` —— 只记 relative 边；陈旧 ⇒ unsupported
C 强弱：新 kind 的取值域必须覆盖原串的**全部**意图，且反例域更宽；只覆盖一半 ⇒ **拆**，一律不换
D 前置（★必须点名的缺陷）
  · `isSupported = 扩展名 ∧ 语言包已装`（`kernel.ts:4142 isExtSupported(ext)!==null`）；
    `tree-sitter-java` / `-python` 在 **optionalDependencies** ⇒ 换过去**继承"机器没装包 ⇒ unsupported ⇒ 双向拦 claim/complete"**
  · `symbol-exists` 的"现解析"路径**不走 `ensureIndexFreshForJudge`**（那条只服务 call/edge）
    ⇒ 新鲜度风险反而不存在，代价是"tree-sitter 解析失败 ⇒ 静默少符号"
  · `call-exists` / `edge-*` 依赖索引新鲜度
E 目标真的存在吗：用**判据自己的实现**（`dist/.../ast_parser.js#parseFileSymbols`）逐条跑过
```

## 三、★ 四条被推翻的说法（其中两条是主控的错 = 0.24 违例）

```
① #92：主控派卡的 `start_index, end_index` **这个串在文件里不存在**
   实际 `remove_dead_imports.ts:319` 是 `start_index si, end_index ei`；另 L304 是 `COUNT(start_index)`
   ⇒ 照派卡写会**假红**。改 `start_index si, end_index ei`
② #116：主控给的 `public static void setGlobalSink(Sink s)` **不是文件原文**
   `Camprobe.java:74` 的解析签名是 `setGlobalSink(Sink s): void`
   ⇒ 整条**该换 `symbol-exists`**（`Camprobe.setGlobalSink` / `Camprobe.capture` 都能现解析命中）
③ #117/#118 的 why 说「py 符号级判据天花板 heuristic ⇒ 文本判据更诚实」**已过期**
   实测 `parseFileSymbols` 把 `camprobe.py` 的 **11 个顶层函数全解出来**
   （`set_global_probe_sink@26` / `capture_probe@39` / `cam_lambda@50` / `_scrub@80`）⇒ 四条都能换
④ #65 的 why 自述「roots.ts 不是设计节点 ⇒ symbol-exists 会报"不对应任何节点"」
   在 `judgeSymbolOrSignature` 里**找不到该检查**（只有 `existsSync` + `isSupportedFile` + 现解析）
   ⇒ 要么指别处、要么已过期 ⇒ **换前请实测一次**；若限制为真 ⇒ **#65 必须留 source-has**
★ ①② 是**主控把没 grep 过的"技术建议"写进派卡** = 0.24 违例；已把"匹配串也算技术建议"补进 0.24
```
