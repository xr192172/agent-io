## 三、八条主线（病 → 改法 → 证据）

### 1. 367 / 435 会逐轮交替（翻译基线不可信）
- **病**：`tsc_fix` 从 outDir 上溯找 `tsconfig.json`，**找不到就 `return null`**（静默 no-op）；且它编译的是**上一版产物**（陈旧输入自反馈）。
- **改**：在被改写目录里生成只覆盖自身的 tsconfig；`return null` 全改 `skip(reason)` 诊断；读数落 `regen-report.json`。
- **证**：连跑两次 **367/367**，83 文件 sha256 全同；TEMP 对照 `--no-fix` 435/435、fix ON 367/367 ⇒ 两条路径都确定。
- ★ 我在这条上**判断错了一次**：以为 `--no-fix` 没生效，实际它只置 `AGENT_IO_TSC_FIX=0`，而门是 `==='1'`。

### 2. 退役 574 条「编译器重复」判据
- **病**：`file-exists` / `symbol-exists` / `signature-matches` 三类本质是重复 `tsc`/`go build`/`git`；且**对变异尺免疫**（`mutate.mjs` 改的是判据不是代码）。
- **改**：删 `file-exists`(50) + `symbol-exists`(524)；**保留 `signature-matches`(53)**。
- ★ **保留的理由是活反例**：`assertValidExpectations` 的期望签名少了我当天新加的 `ctx?`，`tsc` 不会报（可选参数不破坏调用点），**只有 `signature-matches` 抓到了**。它管的是「设计声明的签名 vs 实现」——tsc 不知道设计说过什么。
- **读数**：tsp judge 700/1 → 702/0；三册 919 → 339。

### 3. D2 是**真空绿**
- **病**：D2 用 `n.description` 筛范围，而**全部 1257 个节点 description 为空** ⇒ `inScope=0` ⇒ `bad` 恒空 ⇒ 恒 pass。
- **改**：改读 `n.path`，并把"有 path"变成真判据（对全部 516 个 `type=file` 节点判，缺 0）；豁免（`module`/`doc`）**写进 rule**，不靠表达式静默过滤。
- ★ 独立复核说"`p &&` 过滤了 107 个无 path 节点"，代理实测**它是空操作**（`''` 本就过不了 `startsWith`），205 个无 path 全是 `module`(204)+`doc`(1)。**但 rule 与判据不一致是真的，已修。**

### 4. 三处「失败看起来像空」的门
- `verify-changed.mjs`：git 失败 ⇒ `changed=[]` ⇒ **exit 0**（增量门"什么都没验"却通过）。
- `contract_gate/core.ts`：读不动的文件当"零未定义引用"，**且仍计入已扫** ⇒ 覆盖率虚高。
- `write_gate#symbolsInFileOf`：索引读不到 ⇒ 符号清单空 ⇒ **A7「每个符号都要表态」整格静默失效**。
- **改**：三处都改成"失败必须产诊断 + 带分母（验了 N / 跳过 M）"；A7 在 `planGate` 出声（warning，不拦 —— 拦死会让没索引的新项目写不了源码）、冻结档 throw、claim 读全门 blocking。
- **证**：`tests/p0_silent_failure_guards.test.ts` 3 例先红后绿。
