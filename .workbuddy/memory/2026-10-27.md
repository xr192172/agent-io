## 6. 用户追问「给指针是什么意思」 ⇒ **抓到一个真 bug**（同日晚）

- 我上一版把截断提示写成 `next_hop_args(tool='find_references')` —— **该工具必填是 `touched`**，
  跟着这行跑会报「缺必填：touched」⇒ **比不给指针更糟**（让人以为"全貌拿不到"）。
- 改成指得通的调用：`next_hop_args(touched=<本回执 ---DATA--- 里的 touched>)`（实测退出 0，
  回执是"备好 5 个下一棒的入参 + 逐格来源 + 意图位"，**这才是真正的使用指南**）。
- 用户提的另一个点也对：那段散文在他眼里是**指南**（不是噪音）⇒ 改成**渐进披露**：
  **首次给全貌**（这时它当指南），之后才收敛到 3 条 + 指针；`AGENT_IO_HANDOFF=full|brief` 可显式覆盖。
  进程内 `Set` 记"已给过全貌"，长驻 MCP 天然生效；`npm run tool` 每次新进程 ⇒ 每次都全给。
- 证：`certs/t377-handoff-pointer-cert.mjs` **7/0**（首次全貌 · brief 只 3 条 · **照着指针真跑一次退出 0** · 页脚指到指南）。
## 7. "首次给全貌"的隐藏状态被推翻（2026-10-28 00:10 · 用户追问）

- 问：「压缩上下文或交给子代理会不会影响」⇒ **会**。原判据是"本进程第一次出现接续段就给全貌"，
  但**读的人会换**：上下文压缩后我不记得看过、子代理更是从没看过，而服务端仍记着"已给过"
  ⇒ 新读者永远只见 3 条、还以为是全貌。**隐藏状态与读者不匹配** ⇒ 删掉那个 `Set`。
- 现在**无状态**：默认 3 条 + 一行跑得通的"看全貌"指针（全貌永远一次调用可达）；
  `AGENT_IO_HANDOFF=full` 才摊全（人读 CLI / 第一次摸某个工具时用）。
- 判据（可复用）：**给"读者"的记忆不能存在"服务端"里** —— 读者会换（压缩、子代理、换会话），
  能存住的是**回执本身**：所以答案要写在每次回执里（指针 + 一句"第一次接这个工具就先跑它"）。
