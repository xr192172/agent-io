## 四、`scanValueImports` 裁决（本卡核心）

- **它确实是**一处剥注释实现（不是"另一件事的顺带需要"）：实测注释里的 `import` 会让它误判
  （`// import ts from 'typescript'` ⇒ count=1/bareCount=1）⇒ 今天能得 0 **完全是靠剥**（`maskStringBodies` 只掩字符串、掩不了注释）。
- **但有一半很值钱**：它需要的是「**注释区间变成空白**」不是"删掉注释字符"
  ⇒ `statementAt`/`raw.slice` 同坐标自洽 ⇒ **换成 `stripCommentsSync` 下游一行都不用改**。
- **(B) 跳过剥注释 ⇒ 不可行**（上条实测）。(C) 让 `domain` 引 `infrastructure` ⇒ **不可**（`tests/p0_domain_purity.test.ts:96` 是活的机器门，全仓唯一层方向约束）。
- ★ **(A) 但不要整体搬** ⇒ **端口注入** `ctx.scanValueImports`（与既有 `ctx.readSource` 同惯例）。
  整体搬会把 blast radius 从 1 个 ctx 键变成 4 个写点 + `gate_error.ts:610` 的 `where.symbol`。
- ★ **主控裁定（叉路口）**：`assertValidExpectations` 是 **sync**、`stripCommentsSync` 未预热返 `null`
  ⇒ **不让它二选一**，走第三条：**注入 + 调用方先 prewarm**（4 个写点都是 async，`await prewarmKernel()` 不是负担）；
  **仍 null ⇒ 拒**，报文点名「parser 未就绪」（0.9.4 第 1 行 + 与 `judgeSourceHas:378-385` 同口径）。
  判据：构造"parser 未预热" ⇒ **必须被拒且报文明说原因**，不许静默通过/失败。

### ★ 卡自己推翻了它段 1 的豁免理由（这是四问在起作用的证据）
