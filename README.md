# AgentIO

**让 AI 干的活变得可托付。**

AI 模型已经足够聪明。缺的不是智力，是可托付性——它说"做完了"，你只能选择相信，或者亲自逐行检查。AgentIO 解决的就是这个问题：**把"做完了"从一句口头承诺，变成一条机器可验证的 claim。**

## 它怎么工作

三步，每步都有一台机器在盯着：

```
① 声明     你（或提案席）在设计册里写清楚：要做什么、什么算做完（判据）
② 领卡     模型领到一张卡，这张卡就是它的许可证——没有卡，写闸不放它碰源码
③ 交割     干完了回来销卡。每个"做完了"必须附证据，
           机器当场验证：证据不够？打回。判据变了？旧的通过作废。
```

全部过程记在一条**只准追加、不准篡改**的账本上。谁领的、何时领的、证据原文、谁销的账——想改历史，数据库直接拒绝。

## 为什么是多模型

一个模型自己检查自己，等于没检查。AgentIO 从第一天就是多模型协作的：

- **不同模型不同性格**：有的擅长出方案、有的擅长挑刺、有的擅长闷头实现——让它们互相校对，反对是流程的必填项而不是礼貌选项
- **领卡制**：任务挂在板上，谁有资格谁领，领了就留痕——像游戏里的任务板，但每张任务都带验收标准
- **跨机器**：每台机器跑自己独立的完整实例（自己的账本、自己的缓存、自己的模型席位），通过 git 交换任务与成果——没有中心服务器，任何一台挂了其余照跑

## 里面有什么

不长篇列举，只说四个"别的工具没有"的：

| | 是什么 | 为什么要在意 |
|---|---|---|
| **判据** | 每条"做完了"的判定标准，写成机器可执行的形态——通过/失败/不支持/待判四态，缺证据时**判不了≠通过** | AI 最擅长的一件事就是把测试改到通过。判据是元层的：变异性测试会攻击判据本身，恒真判据活不过一个回合 |
| **写闸** | 源码写入的唯一通道。没卡拒、计划外改动拒、打开后被人动过拒、判据说"这文件写不了"也拒 | 不是权限系统，是**分权**：干活的人和判定的人不是同一个意志 |
| **账本** | append-only 事件流。挂账、批注、销账、裁定全部留痕，三层矛盾检测盯着我自己说过的话 | AI 协作的坑不是没能力，是没人记得昨天承诺过什么 |
| **设计册** | 意图的声明式载体——要做什么、做到什么程度、为什么长这样。源码是它的投影，文档是它的派生 | 手写文档会腐烂。声明式的意图不会：它变了意味着你真的改了主意 |

## 诚实的现状

**能用的**：判据体系（12 种判定类型 + 证据分级 + 变异性自检）、多模型席位协作、账本引擎、写闸、增量验证（全量 24 秒、按改动选量 4 秒）、每项目数据完全隔离。

**毛坯的**：新手上手要读的东西还太多（正在压）；报错文案 10 个里只有 1 个带结构化码；IDE 集成没有；diff 审阅靠命令行。

**没验证的**：真实项目端到端。所有测试在夹具上全绿——这恰恰说明需要一次真实项目来证明这套制度在野外也成立。

## 一句话

AgentIO 不生产代码——代码由模型生产。**AgentIO 生产的是敢把活交给模型的底气。**
