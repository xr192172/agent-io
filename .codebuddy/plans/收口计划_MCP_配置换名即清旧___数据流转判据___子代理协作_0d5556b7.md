## 需求概述

把一句「完善提示词」的要求，收成一份**可直接执行**的计划。原始意图有四个问句，必须逐条回答到可执行：

1. **围绕「收口」**：明确需要完成的事项（给清单与优先级，不是泛泛而谈）。
2. **MCP**：讨论并确定**是否**为当前项目配置 MCP，说明**配置范围**与**预期用途**。
3. **工具数据流转**：明确「**可直接取用 AST 的场景，工具仅转发原始 AST、不保留额外副本；经过加工/解析的数据则保留，并复用项目中已有的相似结构**」——要解释**如何落地**，以及「**项目中已有相似结构**」的**具体含义与对应关系**（要命名到文件/符号）。
4. **子代理**：建议后续经常派子代理分担任务，说明**适用环节**、**职责划分**与**协作方式**。

## 已确认的边界（本轮澄清）

- 交付物 = **可执行计划**（不再单独产出提示词文本）。
- MCP = **要真改配置**：① 补 `scripts/install_mcp.mjs` 的「换名即清旧键」能力；② 覆盖面铺到其他 client（走现成脚本）。
- 数据流转的落地边界 = 由实现方按「**能表示成数据就不解析 / 能引用就不复制**」划定，并把划法写进约定。
- 子代理的落地程度 = 由实现方按「本仓已吃过哪些亏」决定。

## 预期效果

- MCP 不再有「旧品牌键 + 入口路径不存在」的静默失效配置；一处配置、多处可信，且可重复一键校正。
- 「副本 vs 引用」从口头原则变成**可判定的三问判据** + **到具体载体的对应表**，并有两个真实收口点作示范。

**结论：配。** 但只配「正确的那一个名字与入口」，且范围按「**已安装才写**」判定。实测现状：

| 位置 | 现状 | 判定 |
| --- | --- | --- |
| `C:\Users\Admin\.workbuddy\mcp.json` | `agent-io` → `dist\src\presentation\mcp\server.js` | ✅ 正确，**不动** |
| `<repo>\.trae\mcp.json` | `design-canvas` → `${workspaceFolder}/dist/src/server.js` | ❌ **两处都错**：旧品牌键 + **路径不存在**（实测 `dist/src/` 下只有 `presentation/mcp/server.js`、`presentation/daemon/server.js`）⇒ **必修** |
| 其他 client（claude / cursor / vscode / codex / copilot / gemini / windsurf / cline） | 未知 | 按「已安装才写」逐台判定 |


**预期用途**：让本仓 56 个工具在客户端里可直接调用（改名 / 引用 / 漂移 / 对账走工具而非 grep），并让**入口不再静默失效**（这正是 T23「仓外引用没有判据」那一族的又一实例）。

### 落地：`scripts/install_mcp.mjs` 三处增强

1. **换名即清旧键**：平台定义加 `legacyKeys: ['design-canvas']`（旧品牌串见 AGENTS）；写入前从**同一** `keyPath` 删除这些键（TOML 走删同名 `[[mcp_servers]]` 块）。`--list` / `--check` 要能报「有旧键」。
2. **只为已安装 client 写入**：平台定义加 `probe`（探测点）。`probe` 不存在 ⇒ 判 `not-installed` **并跳过**。★ 现状 `writeConfig()` 无条件 `mkdirSync` ⇒ 会给**没装**的 client 在用户主目录**造目录**；项目级 `trae` / `vscode` 标记为恒可写。
3. **陈旧条目检测**：现状 `already ⇒ skip` ⇒ 一个**写错入口**的 `agent-io` **永远不会被修**。改为逐字段比对期望值（`trae` 的 `${workspaceFolder}` 字面量归一后比），不同 ⇒ 判 `stale` 并重写（写前已自动备份 `<file>.agent-io.bak`，保留）。

CLI 口径：默认 = 「补正确键 + 清旧键 + 修陈旧」；`--check` / `--list` 只报六态（`missing|present|configured|stale|not-installed|corrupt`）不写盘；`--dry-run` 打印将写内容；保留 `--target` / `--server`。

## 二、数据流转：方案如何落地 + 「已有相似结构」对应（回答问句 3）

### 判据（三问，可判定）

1. **能现取吗？**（AST / 运行时数据 / 结构化 API）⇒ 能 ⇒ **只转发，不落第二份**。
2. **必须留吗？**⇒ 必须留 ⇒ **必须挂进 `stage_registry.STAGES`**（有 `owner` / `inputs` / `fresh` / `produce`），**且只留一处**。
3. **已有结构能承载吗？**⇒ 有 ⇒ 用已有的，**不新造字段 / 表**。

一句话：**能表示成数据就不解析；能引用就不复制；只有「加工贵且下游重算贵」的才落盘。**
（与仓内既有三条同族：AGENTS「先 AST」的判定顺序、「名字像 ≠ 同义」、「同一份知识只许一处落点」。）

### 「项目中已有相似结构」= 这四个载体（用户点名要的对应表）

| 用户说法 | 仓内已有载体（路径 / 符号） | 对应关系 |
| --- | --- | --- |
| 可直接取用 AST ⇒ 只转发**原始** AST | tree-sitter 内核 `parseFileFull` / `analyzeModuleSource`；`AGENTS.md`「先 AST」判据 | 要事实就**现取**；**不许**再镜像一份 |
| 加工 / 解析后 ⇒ **予以保留** | `cache.db`（`files` / `edges` / `imports` / `symbol_index`）+ `src/application/stage_registry.ts` 的 `STAGES` + `ensureStage()`（缺了往上溯源） | 留**且唯一**，带 `owner` 与 `fresh()` |
| 复用**已有相似结构** | ① `src/application/stage_registry.ts` 的 `STAGES`（唯一数据源 + `renderStageTable()` 自投影）② `src/infrastructure/index/file_facts.ts` 的 `fileFacts()`（唯一 accessor）③ `src/domain/b_terms.ts` 的 `B_TERMS` + `Touched`（受控词表 / 跨 [B] 收据，现 6 字段）④ `src/domain/chain_wiring.ts`（接法表） | 新数据**先问能否挂上去**；能挂就不新造 |


### 落地（两条腿）

- **判据进约定**：写进 `scripts/gen_agents.mjs` 模板（源），`npm run build` 重建 AGENTS.md —— agent 一进来就读到。**不新建门 / 棘轮 / 基线**（仓规：不养门；发现问题靠"修形状"，不靠"加检测"）。
- **按判据收口两个现成点**（示范，证明判据可执行）：
- **T20 剩余**：给 `edit_dsl` 补「**先读后改**」入口 —— 既然**不存镜像副本**，就必须**在编辑时强制读权威**（用户 2026-10-01 原话）。★ **复用已有机制**（`explore_code action=read` 是 `edit_code` 的前置、`evidence` / L4 那条链），**不另发明**。
- **T54 同义异名收口**：`get_dsl(query='files')` 的产物用 `path`，而下游入参要 `file` ⇒ 按「**出口字段名必须能逐字在入口字段名里找到**」收口。★ 先核实产出点与消费点；若属**对外契约变更**则先回报再动。

### 明确不做（避免半修）

- **T56「剪贴板 / 变量」那一格**：形状未定（`chain_wiring.ts` 的 `AnchorKey = keyof Touched` 是否松弛成 `{from:'touched',key} | {from:'product',path}` 判别联合，会牺牲一个编译期保证）⇒ 先拍板。
- **T19 剩余**：读者自动 `ensureStage` —— ★ **受阻**（`dsl_live` 仍是 `pending`，接之前必须先定"写读两侧同一个根"）。

## 三、子代理协作：环节、分工、验收（回答问句 4）

**落地程度（判断）= 落成仓内载体**（`AGENTS.md`，源 = `gen_agents.mjs`），**不新建 skill** —— 用户级已有 `verify-delegated-work` / `dsh-delegate-loop` 等，再建一份就是**第二个副本**（本仓明令禁止）。依据是本仓为此吃过的亏：

- **该派的环节**：① 大范围侦察 / 定位（多目录、多命名）；② **独立核验**（不给它看结论，让它从源码自清点）；③ 迁移 / 改名前的波及面量化；④ 长尾静默失效排查（散文里的旧路径、仓外引用）。
- **不该派的**：单文件小改；需要连续上下文的设计决策；**任何会写共享产物的动作**。
- **分工原则**：读 / 写分离（侦察者只读）；★ **同一工作树不许并行 `npm run build`**（会重写共享 `dist/`，实测一个执行者的中间态让另一个人的 build 报 8 条 `no exported member`）；**但"不许写共享产物"≠"不许跑验证"** —— 可真跑（库外 loader 直跑 `src/`、改前改后对拍 sha256 / 逐条比对），**用完必须清掉探针产物**。
- **派活格式（硬性）**：**先写判据 + 要求"先回报再动手"**（实测：当天子代理**三次推翻**派活方假设 ⇒ 不许只信任务单）；回报须含「我核了什么、读数是什么」。
- **验收**：① `tsc` / `build` 分别跑通；② 关键结论**换一种口径再数一遍**（防「量具量到影子」，实例：`read_files` 报 10/31、实为 5）；③ 展示层**不许 filter 关键字段再下判断**；④ 结论回原始数据（`--json`）复核一次。

## 七、关键代码结构（`install_mcp.mjs` 的平台定义与状态机）

```ts
/** 平台定义：新增 legacyKeys 与 probe 两个字段 */
interface Platform {
  name: string;
  label: string;
  configPath: string;
  kind: 'json' | 'toml';
  keyPath: string;                 // 'mcpServers' | 'servers' | ''
  serverKey: 'agent-io';
  legacyKeys?: string[];           // ★ 新增：['design-canvas'] —— 写入时从同一 keyPath 删除
  probe?: string | null;           // ★ 新增：null ⇒ 项目级(恒可写)；否则 = 该 client 已安装的探测点
  command?: string;
  args?: string[];
}

type State = 'missing' | 'present' | 'configured' | 'stale' | 'not-installed' | 'corrupt';

// 新增纯函数（无副作用，便于 --dry-run / --check 复用）
declare function stripLegacyKeys(parsed: unknown, keyPath: string, legacyKeys: string[]): string[];
declare function isStale(current: unknown, expected: unknown): boolean; // 归一 ${workspaceFolder} 后逐字段比
```

## Agent Extensions

### SubAgent

- **code-explorer**
- Purpose: 承担代价高、面铺得开的**侦察与独立核验**——尤其是 T54 的「`path` 是谁产的、谁在消费」这类跨多文件跨命名的事实清点，以及迁移前的波及面量化。
- Expected outcome: 产出「产出点 / 消费点 / 类型 / 行号 + 是否对外契约」的结构化清单；关键结论必须**换一种口径再数一遍**并回原始数据（`--json`）复核，供计划里的收口步骤直接用。

### Skill

- **design-canvas-mind**
- Purpose: 在按判据收口 T54 / T20 时，用本仓自身的工具链（`capability_map` 先行 → `find_references` 查波及面 → `rename_symbols` 改名 → `detect_drift` 对账 → 真调验收）而不是 grep 手改，保持"工具被想起"。
- Expected outcome: T54 的字段名收口与 T20 的 `edit_dsl` 入口改动**全部经工具执行并可复算**（改前/改后读数留证），且不产生绕过工具的手工替换。
