# `certs/` —— 出生证（开发侧验收证）

> ★ **这不是门，也不该进 CI。** 它是**开发侧**的验收证：每修一个真缺陷，就写一张证
> 证明"修了，且**改回去会变红**"。总门只有 `npm run verify` 一个（见仓根 `README.md`）。

## 为什么它进了版本控制（2026-10-13，T223/T224）

此前这些证住在 `.inspect/` —— 而 `.inspect/` 在 `.gitignore` 里（那是个 **3.2 GB 的垃圾场**）。

后果是**实测出来的**，不是推想的：

| | 读数（一次完整全量） |
|---|---|
| 搬家前 | `37 张：崩 4 · 有红 0 · 无汇总 8 · 真证书全绿 22` |
| 搬家后 | `37 张：崩 0 · 有红 0 · 无汇总 8 · 真证书全绿 29`（★ **exit 0**）✅ |

★ `22 → 29` 是因为：① 那 4 张崩的证现在真的跑起来了（其中 2 张原本就是红的，被"崩"盖住）；
② **3 张有汇总的证此前根本没被 runner 发现**（名字不合规则，见下）。

★ 那 4 张"崩"里，**3 张死在 reset 那一行**（宿主的删除护栏按**条目数**计数、阈值 50，
一次 `rmSync(dir,{recursive:true})` 照样超）⇒ ★ **它们一条断言都没跑** ⇒
其中 **2 张本来就是红的**（夹具模板是脏的），★ **而"崩"把红盖住了** ✓

⇒ ★★★ **关键**：这一切**在 git 里完全看不见** —— `.inspect/` 被忽略 ⇒
**没有 diff、没有评审、没有人会注意到"验收依据已经死了"**。
我因此把它误判成"环境噪声"，并背着那个错判断走了整整一天（详见 `docs/todo.md` 的 T223）。

**判据**：★ **验收依据必须在评审里可见**。
★ `certs/` **不在** `package.json` 的 `files` 里 ⇒ **不随 npm 发布**（它是开发侧资产，不是产品）。

## 怎么跑

```bash
node certs/run-all-certs.mjs                       # 跑全部（★ 实测 19.4 分钟）
node certs/run-all-certs.mjs t205 t212             # 只跑名字里含这几个串的
node certs/run-all-certs.mjs --exclude t189-sweep  # ★ 排掉某张（见下）
```

★ **为什么会有 19.4 分钟**（★ 这是**量出来的**，不是猜的 —— runner 每张证都记耗时）：
**`t189-sweep` 一张就占 52%**（602s / 1164s）。它**不是出生证**，是"每个工具真跑一遍看它交了什么
`touched`"的**量具**（`for (const def of TOOL_DEFS)`，69 个工具各起一次 MCP server），
被 runner 的**名字规则**收进来陪跑。⇒ 只想看"证书绿不绿"就把它排掉：
★ **实测 `--exclude t189-sweep` ⇒ 19.4 → 9.3 分钟**（36 张，崩 0 · 有红 0 · 真证书全绿 29 ✓）。

★ 第二项固定成本：**每次断言都要起一个完整的 MCP server 进程** —— 实测单次
`node scripts/mcp/mcp_call.mjs` = **1.04~1.13 秒**（spawn `server.js` + `initialize` 握手 +
一次 `tools/call`，含 51 个解析器预热）。★ 这笔开销**与调用干多少活无关** ⇒
**断言数 × 1.1s 就是地板**。★ 而这**是刻意的**：证必须走**真实接线路径**（否则测不到
"zod schema 有没有接上"）⇒ **别为提速牺牲它**（把调用改成"常驻服务"会让内存态跨调用泄漏，
对量具是更坏的错 —— 会给出"看起来通过"的假绿）。

读数同时写一份到 `certs/.work/cert-report.md`（★ 别用 `| head` 截输出 —— 管道会缓冲，
命令不跑完一个字都看不到；这个坑踩过两次，各白等 17 分钟）。

### 三档判读（**别把它们混起来**）

| 档 | 含义 | 处置 |
|---|---|---|
| **崩**（exit≠0） | ★ **待定性状态，不是"环境噪声"** | ★ **必须逐张查明它死在哪一行**。死在 reset 行的证 = **坏证**（连"没通过"都没资格说） |
| **有红**（有汇总且 FAIL≠0） | 真失败 | 看 runner 打出来的**失败那几行 ± 上下文** |
| **○ 无汇总** | 不是证（是量具/探针），或它还没成形 | 别当成红 —— ★ 但也**别当成绿** |

★ 每张证跑前先跑 `certs/t185-reset.mjs`（**从已知 good 状态**整份还原，不是从活态还）。

## 名字即发现规则（★ 3 张证曾因此**整整不被跑**）

runner 用这个正则发现证书：

```
/^(t\d+.*-cert\.(sh|mjs)|t\d+-.*\.mjs)$/
```

★ 2026-10-13 实测：`t197c-approvals` / `t197sub-flow` / `t198sub-approval` 三张**有汇总、
单独跑全绿**（5/0、27/0、15/0），但名字不匹配 ⇒ ★ **runner 从来没跑过它们** ⇒
它们**永远不会红、也永远不会绿** —— 是"坏证"的一种。已改名为 `*-cert.mjs`。
⇒ ★ **新证请用 `t<N>-<topic>-cert.mjs` 或 `t<N>-<topic>.mjs`**。

## 目录约定

| 路径 | 性质 | 进版本控制？ |
|---|---|---|
| `certs/*.{mjs,sh}` | 证 + 量具 + runner | ★ **是** |
| `certs/t185-base/` | ★ **基线**：`t185-reset` 从它整份还原活态/存档/overlay | ★ **是**（它是"已知 good 状态"的唯一副本） |
| `certs/t205-fixture/`、`certs/t213-fixture/` | 夹具**模板**（只读；证运行时往 `os.tmpdir()` 拷一份干活） | ★ **是** |
| `certs/.work/` | **只有**运行期日志与产物：`cert-report.md`、`t187-out.txt`、`t189-sweep.json` | ✗ 被 gitignore |
| `os.tmpdir()/agent-io-*` | ★ **所有租户 / 夹具 / 消融副本**（用完即弃，OS 自己清） | ✗ 仓外 |

★★ **为什么草稿必须放 `os.tmpdir()`（T224 实测，两条硬理由）**：

1. ★★★ **宿主的删除护栏按"删掉的条目数"计数**（阈值 50，**按 `tool_call_id` 累积**）。
   ★ 而整套证是**在一个 Bash 调用里**跑完的 ⇒ ★ **37 张证共用同一个 50 条预算** ✗
   ⇒ 只要累计超过 50，**后面的证会在 reset/收尾那一行崩掉、一条断言都不跑**。
   ★ 而 `os.tmpdir()` 下的路径被 shim **整体绕过**（`shouldBypassSafeDelete`）⇒ 计 0 ✓
   （★ 这条我第一版做错了：把草稿放进 `certs/.work/` —— 那**仍在仓内** ⇒ 照样计数 ⇒ 全量仍崩 ✓）
2. ★★ **`.work/` 在 `.gitignore` 里** ⇒ `import_project`（尊重 `.gitignore`）会**把这些文件过滤掉**
   ⇒ 凡是把该目录当 `project_dir` 的证都会拿到空结果。temp 在**仓外** ⇒ 不受影响 ✓

★★ 两条已确立的夹具纪律（都是实测栽出来的）：

1. **夹具工作副本放 `os.tmpdir()`** —— 见上；
   ★ 附带好处：temp 在**仓外** ⇒ 项目扫描器不会像跳过 `.inspect/` 那样把它整片跳过。
2. **模板里不放派生状态** —— `t205-fixture/src/` 曾因为留着上一次跑拆完的结果而"变脏"，
   我据此以为"新副本就是干净的" ⇒ 直接红。★ **真原样只有 `*.orig`**（模板里的 `src/` 已整个删掉）。
   ★ **`certs/t205-fixture/src` 与 `certs/t213-fixture/src` 故意不存在** —— 由证从 `*.orig` 重建。

## ★ 诚实的边界（**别把它读强了**）

★ **这不是一套可移植的第三方验收套件。** 它**绑在这台开发机的数据状态上**：

- 多数证要真调工具、并读写本机 `dataHome` 下的 `.agent-io/`（活态 DSL、feature 存档、overlay、归档库）；
- 主夹具是 feature **`run82`**（本仓自身代码的 DSL 快照），基线 `.json` 是从**某一次合法设计变更之后**
  重抓的（★ 基线过期会**抹掉**新的设计意图 —— 这个爆炸半径事故真实发生过，见 `t185-reset.mjs` 注释）；
- 换一台机器、或删掉 `.agent-io/`，**部分证会红** —— 那**不是**产品缺陷，是夹具前提不成立。

★ 所以：**CI 不跑它**（CI 只跑 `npm run verify`）。它的用途是"我改了这个，把同类回归当场证一遍"。
